# Agent 组织与开发方案

Status: active（组织基线）
Scope: 定义组织 agent 与领域 agent 的分工、结果包责任、任务规划和最终验收方式；不定义具体功能。

## 1. 共享上下文的维护

共享上下文由**领域 agent** 维护，组织 agent 只观察、评价、提要求。

- 文档所有权归对应领域。
- 组织 agent 不直接修改领域文档。
- 组织 agent 负责发现不一致、缺口和过时内容，并要求对应领域更新。

## 2. 领域识别与结果包设计

组织 agent 识别并定义项目要求的全部领域；领域 agent 设计各自的结果包。

每个结果包必须说明：

- 输入
- 产物
- 验收
- 依赖
- 上下文需求

组织 agent 按以下标准评估结果包，不替领域做设计：

- 能否得到预期结果
- 是否有缺漏
- 是否可验收

## 3. 任务规划与指导

按支撑关系、实现关系和架构关系做任务规划与指导。

1. 先确定结果包之间的依赖与接口。
2. 再排执行顺序、并行关系和集成点。
3. 规划随验收结果动态更新。

## 4. 最终目标与验收责任

组织 agent 始终对最终项目目标和验收方式负责。

- 每个任务都能追溯到核心目标。
- 组织 agent 明确自己最终要验什么、怎么验。
- 用最终验收检查计划是否偏离。

## 一句话

> 领域 agent 拥有上下文和结果包；组织 agent 拥有领域完整性、依赖规划、动态调整和最终验收。
