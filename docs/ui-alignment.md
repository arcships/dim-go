# 界面设计对齐：参数与原则（草案）

用途：把用户的设计判断转成可推导的依据，供 B 阶段概念设计与后续规格引用。本文件由组织侧维护，用户修订后生效。

## 1 原则（可判定）

| # | 原则 | 判定方式 |
|---|---|---|
| P1 | 状态永远可见 | 任一时刻能在一个固定位置答出“在跑什么、等谁、失败没有” |
| P2 | 打断只在必要时 | 流程中必须回答的事占输入位；模态只用于破坏性确认与全局动作 |
| P3 | 一屏一主任务 | 每屏只有一个主操作目标，次要信息可按需展开 |
| P4 | 键盘可完成一切 | 每个任务都有键位路径；鼠标是加速，不是前提 |
| P5 | 出错必须可行动 | 错误给原因与下一步；不给“未知错误” |
| P6 | 不假装 | 结果未知、断线、不支持，都如实呈现，不静默、不乐观更新 |

## 2 参数（先定值，再推导）

| 参数 | 建议值 | 其他选项 | 决定什么 |
|---|---|---|---|
| 密度 | 紧凑偏中 | 紧凑 / 中 / 宽松 | 行高、常驻信息量、次要信息折叠 |
| 气质 | 文档感为骨、终端感为用 | 终端感 / 文档感 / 混合 | 字体、留白、装饰、等宽使用范围 |
| 主输入 | 键盘优先 | 键盘优先 / 鼠标优先 | 命令面板、快捷键覆盖、悬停揭示的替代 |
| 打扰容忍 | 低 | 低 / 中 / 高 | 审批内联、通知主通道、错误呈现 |
| 信息暴露 | 渐进 | 渐进 / 全量 | 状态条、设置组织、右栏默认收起 |
| 会话形态 | 单窗多会话 | 单窗单会话 / 单窗多会话 / 多窗口 | 主区布局、切换方式、窗口模型 |
| 主题 | 跟随系统 | 跟随系统 / 固定明 / 固定暗 | 视觉基线、截图验收口径 |
| 动效 | 轻 | 无 / 轻 / 明显 | 状态转场、流式节奏、减少动效的默认 |

## 3 参数如何回答 Q 台账

推得的（参数定完即定）：

| Q | 由哪个参数决定 | 推导结果（按建议值） |
|---|---|---|
| Q-1 多会话注意力 | 会话形态 + 信息暴露 | 单窗多会话：主区一次一个会话，侧栏承载其余并显示状态；不引入独立“任务中心”页 |
| Q-13 悬停揭示替代 | 主输入 | 键盘优先：行内动作改为选中态可见 + 快捷键；悬停只作补充 |
| Q-16 提醒通道 | 打扰容忍 | 低：应用内为主，系统通知只用于后台任务完成与需你决定 |
| Q-9 状态条承载 | 信息暴露 | 渐进：状态条只放四项摘要，明细进浮层 |
| Q-10 设置组织 | 信息暴露 | 渐进：分组导航 + 页内下钻，不做全量搜索式设置 |
| Q-14 多窗口 | 会话形态 | 单窗：不做 popout，改为会话切换；窗口只保留主窗 |
| Q-3 右栏等价物 | 气质 + 密度 | 偏向文档感：右栏改为可收起的侧板，不做多标签堆叠 |
| Q-17 可见但禁用 | 信息暴露 + 打扰容忍 | 渐进：未接能力默认隐藏，设置里留清单与原因 |

推不得的（需要给选项后由用户选）：

| Q | 为什么推不出 |
|---|---|
| Q-2 任务与对话的层级 | 取决于用户如何理解“任务”这一层，属心智模型选择 |
| Q-7 运行中再提交的默认语义 | 取决于用户对“打断/排队”的习惯，非参数可推 |
| Q-4 审批键位覆盖面 | 取决于对教学成本的态度 |
| Q-5 输入下限 | 取决于对富文本的期待 |
| Q-6 虚拟化与选择 | 取决于长会话使用强度 |
