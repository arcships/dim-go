# 界面设计对齐：参数与原则

用途：把用户的设计判断转成可推导的依据，供 B 阶段概念设计与后续规格引用。本文件由组织侧维护，用户修订后生效。当前版本已按用户反馈改写两次。

## 1 原则（可判定）

| # | 原则 | 判定方式 |
|---|---|---|
| P1 | 状态是元素自身的变化 | 状态附着在已有 UI 元素上：行内标记、灰度、形态、位移、让位。不新增状态容器（状态条、状态指示器、徽标栏），也不靠说明文字 |
| P2 | 打断只在必要时 | 必须回答的事占输入位；模态只用于二次确认、破坏性操作与全局动作 |
| P3 | 分层的信息区域 | 每屏分主操作区、附属信息区、子操作区三层；层级不清即视为设计未定 |
| P4 | 键盘与鼠标并重 | 常用任务有键位路径；同时不牺牲鼠标的效率与精度 |
| P5 | 错误要能被理解和处理 | 给可行动的原因与下一步；错误信息要包装、分层、给建议，不把原始错误码丢给用户 |
| P6 | 状态不说谎，过程要平滑 | 事实必须真实；呈现可以平滑——自动重试、短暂抖动不必以紧张的方式呈现 |
| P7 | 可见性克制 | 有功能不等于要出现在界面上；即使出现，也不一次全摆出来。每个元素都要回答“用户此刻是否需要它”，否则隐藏或按需展开 |
| P8 | 不虚构 | 不存在的能力不画入口，不画假状态，不做“顺手加一个”；也不以“别人都这么做”作为设计依据。每个元素必须能指到一条需求或一个真实能力 |

## 2 参数

| 参数 | 取值 | 决定什么 |
|---|---|---|
| 密度 | 中 | 行高、常驻信息量、次要信息折叠 |
| 气质 | 桌面应用标准 | 按成熟桌面应用的惯例；不用终端/文档二分 |
| 输入方式 | 键盘与鼠标并重 | 命令面板与快捷键覆盖常用任务；悬停与右键同时可用 |
| 打扰容忍 | 低 | 审批内联；系统通知只用于后台完成与需你决定 |
| 信息暴露 | 渐进 | 默认不常驻业务信息；不设状态条；需要时一步可达 |
| 会话形态 | 单窗多会话（预留独立窗口） | 主区一次一个会话；后续可将会话拖出或右键在新窗口打开 |
| 主题 | 跟随系统 | 明暗跟随系统，截图基线按系统设置 |
| 动效 | 明显 | 状态转场、面板开合、流式节奏可感知；支持减少动效开关 |
| 运行中提交 | 默认排队，设置可改 | 默认排队；偏好里可切换为插话 |

## 3 输入能力

- 输入框至少支持**结构化块**：技能、文件、图片等以块的形式出现在输入区内，块本身可交互（查看、移除、替换）。
- 后续考虑支持 Markdown 语法输入；首版以块 + 纯文本为下限。

## 4 状态表达规则（P1 的落地办法）

状态不单独占位，附着在既有元素上。设计步骤固定三步：

1. **先问在哪感知**：用户在这个状态下，眼睛应该落在哪个已有元素上。
2. **再问改哪个属性**：标记（打叉、小点）、灰度、描边、形态（图标换成进行中）、位移（让位、上移）、可操作性变化。
3. **最后问一致性**：同类状态在不同元素上是否用同一种表达，避免同一含义出现多种画法。

示例：工具调用出错 → 该工具调用行内的状态标记变为叉，整行降为次要灰度；不新增提示条，不弹窗，不出现重试入口。

约束：

- 一个状态可以影响多个既有元素，但不得为此新增容器；同一含义只允许一种主表达。
- 状态表达只反映事实，不得凭空造出可执行动作。只有协议里真实存在的能力（例如重新发送消息）才允许出现入口，且必须对应一条写意图；不可重试的失败只呈现状态与原因。

## 5 可见性判定（P7 与 P8 的落地办法）

每个候选元素先过三道闸，任何一道不过就不进界面：

1. **有任务吗**：它是否服务于用户此刻要完成的事。答不出任务，隐藏。
2. **有决策或状态需要感知吗**：是否要求用户做决定，或必须让用户察觉某个变化。答不出，隐藏或合并进已有元素。
3. **有真实能力吗**：是否对应协议里存在的方法与一条写意图。答不出，删掉，不画占位。

通过三闸的元素还要过两个追问：

- **为什么是现在**：为什么必须在首屏/默认展开，而不是按需出现。
- **为什么是这样**：为什么用这个形态，而不是更省的做法。答案里不允许出现“常见做法如此”“别家都这样”。

记录方式：每个界面元素在设计稿旁标一条来源（需求条目、能力方法或状态规则）。没有来源的元素一律视为虚构，评审直接退回。

## 6 参数如何回答 Q 台账

推得的：

| Q | 推导结果 |
|---|---|
| Q-1 多会话注意力 | 单窗多会话：主区一次一个会话，侧栏承载其余；不设任务中心，界面里不出现“任务”这一层概念 |
| Q-2 任务与对话的层级 | 已消解：不设任务层，后台任务只在所属会话内呈现 |
| Q-3 右栏 | 默认折叠；展开后是带标签的容器，标签用于切换内容页 |
| Q-4 审批键位 | 常用键位要有并在面板上写出；具体键位归 C3 |
| Q-9 状态条 | 不存在这一层：所有状态附着在元素上，见 §4 |
| Q-10 设置组织 | 分组导航 + 页内下钻，渐进暴露 |
| Q-13 悬停揭示替代 | 悬停保留；常用行内动作在选中态可见并给快捷键 |
| Q-14 多窗口 | 首版单窗；预留把会话拉出为独立窗口，排后续批次 |
| Q-16 提醒通道 | 应用内为主；系统通知仅用于后台完成与需你决定 |
| Q-17 可见但禁用 | 未接能力默认隐藏，设置内保留清单与原因 |
| Q-6 虚拟化与选择 | 必须做：100–1000 个事件为基线，配分页加载与内存控制；文本选择与虚拟化冲突在 C 阶段解决 |

已由用户定：

| Q | 结论 |
|---|---|
| Q-7 运行中再提交 | 默认排队；设置页可改为插话 |
| Q-5 输入下限 | 结构化块（技能/文件/图片可交互），后续再考虑 Markdown 语法 |

## 7 决策记录格式

每条结论写四行：问题 / 选择 / 依据（引用 P# 或参数值）/ 影响面。无依据不许定稿。

## 8 对齐检验

门禁前必须提交：复述（原词）、三个应用例子、一个反例。三项不过即退回。
