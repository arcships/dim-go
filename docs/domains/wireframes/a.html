方案 A：轮次组头

依据 UI-11 / UI-15 / UI-16 / UI-17 / UI-18 / UI-19（并 §9.0 A1–A4、D1–D6） · 文档 U1-concepts §1、U1-ia §1/§7、U2 §4.4/§4.5、U3 §1.1 · 日期 2026-11-13 · 版本 第 4 版（UI-20…UI-23：图标与文字最后手段） · 状态 现行
图例 线框里的框线、间距与圆角是画法，不构成 UI-18 的判据；规格以 U2 的 token 与框架默认值为准。窗口控件（红绿灯）由系统绘制，线框只画它占的那条空带。标题行左端写一次会话名（红绿灯让位之后），系统 Title 不算重复。虚线方块是图标占位：图标由设计决定（U2-forms §3），线框只约束内容、位置与可点区。

基线：左栏放会话（256）→ 标题行 48 是窗口标题栏（红绿灯在左栏上方），只放右栏入口与偏离默认时的最小提示 → 时间线左缘对齐、行宽随内容，用户消息右对齐、助手铺开、操作收成一行 → 输入区贴底（60–300），有排队项时上方出现队列条 → 右栏可选（280–容器−400），只放当前会话的附属内容。按 §9.9：审批出现时占据输入位，替换输入区；界面不用内部术语；流式保序、动效可关。 本方案偏离 2 处：①一轮里的全部操作收成一行内容总览（这一组做了什么：动作与对象），可展开成逐条；②这一行自己承担进行中 / 等待同意 / 失败三种形态，不另起提示区。代价：不展开时看不到每一步。

UI-4 保序组头展开后的条目按发生顺序编号（1/2/3），运行中新增条目只追加在尾部；折叠只改变可见性，不改变顺序；从不整段重排
