# U2 C2：视觉规范（v3：默认优先 + 组件不改）

Status: draft（C2 结果包修订版，待组织评审）
Owner: U2 界面视觉
依据: `docs/domains/U0-framework-baseline.md` §2.4–§2.6（框架 token、主题度量、状态能力）、`docs/domains/U0-design-archaeology.md` §12.4–§12.6（现役客户端实测）、`docs/ui-alignment.md` §1–§2 与 §5（状态表达规则）、`docs/project-organization.md` §9.5–§9.9（状态标准、UI-1…UI-12）与 §9.7（可访问性评审维度）、`docs/domains/U1-ia.md` §5（每个状态落在哪个元素）、`docs/project-organization.md` §9.9 UI-13（用框架组件就不改它的样式）
范围: 首片元素——标题行、时间线的四类行（用户消息、助手回复、过程摘要行、工具行）、输入区四件（编辑器、附件块、队列条、发送/停止）、审批卡、空态、错误与未知状态——的字阶、间距、颜色语义、状态样式、动效、密度与图标、可访问性、token 表。
不做: 区域划分与控件位置（U1）、触发/前置/完成/失败/断线五段与键位（U3）、view 映射与性能预算（U4）、界面代码。本文只给"看得见的值"。

组件边界: 本文只设两样东西——**主题级 token**（颜色、字号锚点、行高倍数、主题度量）与**自绘组件的规格**（用 `*Base` / `Box` 自己搭的元素）。框架组件的尺寸、内边距、描边、填充、字体一律沿用框架（UI-13），见 §0.5、§0.6。
预览: `docs/domains/U2-visual-preview.html`（静态、无外部依赖，明/暗与减少动效可切）；由 `scripts/u2-preview.py` 按本文 token 值生成，改 token 后重跑即可保持一致。

## 0 口径

### 0.1 单位

全部为 DIP（等同 CSS px）：字号、行高、间距、描边、圆角、图标边长、动效时长。不写设备像素；涉及清晰度的判定一律注明倍率（§7.4 的 200% 走查）。

### 0.2 立场：默认优先

本文的第一条规则不是"对齐现役客户端"，而是**沿用 mygo 默认值**。框架已经定下的字号比例、行高、间距基准、圆角、动效时长、高对比度行为，一律照用；只有当下面三种依据之一存在时，才允许给出不同的值：

| 依据类型 | 判定 | 允许改什么 |
|---|---|---|
| **门槛** | 已定的可访问性阈值（WCAG 2.1 AA：正文 ≥4.5、非文本图形与状态 ≥3.0）算出的比值不达标 | 只改该颜色，改后必须给出重算前后的比值 |
| **证据** | 现役客户端的实测值、框架源码里的实际默认值 | 只在"对齐对象被点名"的地方改，并写明来源小节 |
| **需求** | `docs/project-organization.md` §9.9 的 UI-1…UI-12，或 `docs/ui-alignment.md` §1–§2 的 P/参数 | 只改需求点名的那一项 |

三条之外的改动（"更好看""和线框对得上""别家如此"）不写入本文；框架有默认就用默认。每一项偏离在 §9 台账里单列，带依据类型与可重算数值。

UI-13 是这三条之上的硬边界：它们只作用于**主题级 token 与自绘组件**；框架组件上不写数值，也不需要依据（§0.5）。

### 0.3 框架默认清单（可复核）

本文所说的"框架默认"指下列值，均来自 `github.com/egoist/mygo`（v0.8.3），可逐条对照源码：

| 项 | 默认值 | 位置 |
|---|---|---|
| 主题度量 | `Spacing` 4、`Radius` 6、`ScrollbarWidth` 6、`FocusRingWidth` 2、`FocusRingOffset` 1 | `ui/theme.go` 的 `LightTheme` / `DarkTheme` |
| 根字号 | `FontSize`：macOS 13、其他 14 | `ui/theme.go` 的 `defaultFontSize` |
| 主题色 | 背景 / 面 / 悬停 / 按下 / 边框 / 文字 / 次要文字 / 强调 / 成功 / 警告 / 危险 / 选区 / 焦点，明暗各一套 | 同上 |

### 0.4 判定方法

每条规范只接受四种判定，写在所在小节末尾：

| 代号 | 方法 | 做法 |
|---|---|---|
| A | 数值比对 | 读 §8 的 token 表，元素用的值必须逐字相同；不得出现表外数值 |
| B | 对比度计算 | WCAG 2.1 相对亮度公式：`(L1+0.05)/(L2+0.05)`，阈值见 §7；本文表内的比值即该公式结果，重算差 ≤0.01 视为通过 |
| C | 逐项走查 | 打开 `docs/domains/U2-visual-preview.html` 的对应区块，按该区块标注的属性逐条对 |
| D | 组件边界 | 该条规则是否落在框架组件上：落上即为违规（UI-13），须改为"沿用框架"或改用 `*Base` 自绘（§0.5） |

"看起来合适""和别家一致"不作为判定依据。

### 0.5 组件边界（UI-13）

`docs/project-organization.md` §9.9 的 UI-13 把本文的写法切成三层，只有前两层可以写数值：

| 层 | 本文写不写 | 例 |
|---|---|---|
| 主题级 token | **写**（只经 `Theme` 字段生效） | 颜色 18 组、`Theme.FontSize`、`Theme.Radius`、`Theme.Spacing`、`FocusRingWidth` / `FocusRingOffset`、动作时长 |
| 自绘组件 | **写**（用 `*Base` 或 `Box` 自己搭，外观由本文定） | 输入卡外壳、审批卡、状态标记、摘要行、工具行、时间线行、轮次序号、附件块、队列条、空态说明块 |
| 框架组件 | **不写**（尺寸、内边距、描边、填充、字号、禁用态都不得覆盖） | `Button` / `PrimaryButton`、`TextInput` / `TextArea`、`Tabs`、`Sidebar` / `SidebarItem`、`List`、`Scroll`、`Segmented`、`Select`、`Divider`、`Collapsible`、`Popover` |

## 1 字阶

### 1.1 来源：框架的 Markdown 标尺

各级字号、字重、标题上下间距**全部取框架 Markdown 默认值**（§0.3），本文只提供一个锚点 `Theme.FontSize`。框架没有的那个锚点本文定 14（§1.2，唯一偏离）。其余级差按框架比例换算，界面里出现的任何文本必须落到其中一行。

| 语义级 | token | 来源 | 字号 | 行高 | 字重 |
|---|---|---|---:|---:|---:|
| 正文 | `type-body` | 锚点 × 1 | 14 | ×1.5 = 21 | 400 |
| 正文强调 | `type-body-strong` | 框架 `StrongWeight` | 14 | ×1.5 = 21 | 600 |
| 次要 | `type-secondary` | 框架缩比 0.875 | 12.25 | 不设（框架字体度量） | 400 |
| 次要强调 | `type-secondary-strong` | 同上 + `StrongWeight` | 12.25 | 不设 | 600 |
| 极小 | `type-micro` | 框架缩比 0.75 | 10.5 | 不设 | 400 |
| 代码 | `type-code` | 框架 `CodeSize` 0.875 | 12.25 | ×1.4 = 17.15 | 400 |
| 标题行会话名 | `type-title-row` | 锚点 × 1 + `StrongWeight` | 14 | 不设 | 600 |
| h1 | `type-h1` | 框架 1.6em / 700 | 22.4 | ×1.5 = 33.6 | 700 |
| h2 | `type-h2` | 框架 1.35em / 650 | 18.9 | ×1.5 = 28.35 | 650 |
| h3 | `type-h3` | 框架 1.15em / 600 | 16.1 | ×1.5 = 24.15 | 600 |
| h4 | `type-h4` | 框架 1em / 600 | 14 | ×1.5 = 21 | 600 |
| h5 | `type-h5` | 框架 0.95em / 600 | 13.3 | ×1.5 = 19.95 | 600 |
| h6 | `type-h6` | 框架 0.9em / 600 | 12.6 | ×1.5 = 18.9 | 600 |

"不设"表示不调用 `LineHeight` / `FixedLineHeight`，由框架按字体度量排版（单行行盒即字体升降部之和）。判定时量到的是框架算出的行盒高度，不要求等于某个固定数。

"框架缩比 0.875 / 0.75"是两个框架自己就在用的比例（`0.875` 见 `ui/markdown/theme.go` 的 `CodeSize`，`0.75` 见 `ui/table.go` 的页码标签），本文把它们分别用作"次要"与"极小"的字号比例，而不是另定 12.25 / 10.5 两个数。级差、字重、标题比例全部来自框架，只有 §1.2 的锚点是本文定的。

框架按钮的标签字号由主题给（`Theme.FontSize`），本文不给按钮设字号、字重或内边距（UI-13）；主按钮与次按钮的层级由框架的填充与描边承担。空态、错误说明等"一行话"只用 `type-secondary` 或 `type-body`，不引入大字号（P7/P8：空态不靠夸张字号充场面）。

### 1.2 锚点：`Theme.FontSize = 14`

框架在 macOS 上默认 13。本文取 14 的依据是**证据**，不是审美：

- 现役客户端根字号实测 14px（`docs/domains/U0-design-archaeology.md` §12.6，`styles/global.css`）。并行对照期，两个客户端同一段中文的换行位置可以直接比较；取 13 时同一段落的换行位置不同，对照记录失去可比性。
- 14 是框架在非 macOS 平台上的默认值（§0.3），不是本文自造的数。

**回退代价（供评审二选一）**：若判定"对齐现役"不构成依据，则整张字阶按 13/14 = 0.929 同比缩小为 13 / 11.375 / 9.75 / 11.375、h1 20.8、h2 17.55、h3 14.95、h4 13，行高与标题间距由倍数自动跟随，**不需要改其他任何一条**——级差比例全部来自框架，锚点只有一个变量。

### 1.3 字重与字体

- 字重只用框架给出的那几个值：正文 400、强调 600、标题 700/650/600（§1.1）。不再自定"只用 400/500/600、不用 700"这类限制——框架的标题默认就是 700/650，覆盖它需要依据，本文没有。
- 字体走系统 UI 字体栈（`Theme.Font = ""`）；代码用系统等宽（`Font("SF Mono, Menlo, monospace")`）；中文由 `Lang` 决定字形变体。不内嵌字体（体积与许可都不划算，且系统字体即平台一致性的来源）。
- 文本缩放到 100–200% 由框架 `Preferences.TextScale` 乘 `FontSize` 完成（§0.3），本文不另设字号档。

**判定**：任一文本元素可量到（字号, 行高, 字重）三元组且等于 §1.1 某行；行高的量法是行盒高度（单行）或首行基线到次行基线的距离（多行）。走查 §1 区块（C）。

## 2 间距节奏

### 2.1 基础单位：框架的 4

**基础单位取框架默认 4，不做覆盖。** mygo 的内建控件内边距与间隙都是 `Spacing` 的倍数（§0.3），改成别的数就要逐个控件重调内边距，而没有需求要求更紧的排布（`docs/ui-alignment.md` §2 密度 = 中）。

### 2.2 标尺

只用框架函数 `t.Space(n)` 的七档：`space-1` 4、`space-2` 8、`space-3` 12、`space-4` 16、`space-6` 24、`space-8` 32、`space-12` 48。档位序号即框架的 n，代码里写 `t.Space(n)` 而不是字面量。间距一栏不得出现非 4 倍数的值（框架 Markdown 的 em 值另算，见 §2.4）。

### 2.3 用法（首片元素）

档位序号取自现役客户端的实测节奏（`docs/domains/U0-design-archaeology.md` §12.4、§12.5 的 1/2/3/4/6/8 单位），只是把单位换算到框架的 4：

| 位置 | 值 | 依据 |
|---|---:|---|
| 图标与文字（自绘容器内） | 8（`space-2`） | 现役 2 单位；框架按钮内图标与标签的间隙由框架给，不在本表 |
| 标记点与相邻文字 | 4（`space-1`） | 现役 1 单位；标记属于该行文字，不单独成组 |
| 同一容器内相邻元素之间（徽标、附件块） | 4–8 | 同上；框架控件自身的内边距不在此表 |
| 同一轮内消息/块之间 | 12（`space-3`） | 现役 3 单位 |
| 轮次之间 | 24（`space-6`） | 现役 6 单位，是组内的 2 倍 |
| 卡片内边距（审批卡、空态说明块、错误块） | 16（`space-4`） | 现役 4 单位 |
| 输入卡内边距 | 12（`space-3`） | 现役 3 单位 |
| 队列条与输入卡之间 | 8（`space-2`） | UI-10：队列贴输入区 |
| 区域内容左右边距 | 16（`space-4`） | 现役 4 单位 |

### 2.4 Markdown 内部间距不归本节

段落之间、列表项之间、标题上下、缩进与代码块内边距，全部是框架 Markdown 的 em 值（§0.3），在 FontSize 14 下为：

| 项 | 框架值 | 14px 下 |
|---|---:|---:|
| 段落 / 块之间 `BlockSpacing` | 0.75em | 10.5 |
| 紧凑列表项之间 `ItemSpacing` | 0.25em | 3.5 |
| 标题上 / 下 | 1.4em / 0.55em | 19.6 / 7.7 |
| 列表缩进 `ListIndent` | 1.6em | 22.4 |
| 代码块内边距 `CodeBlockPadding` | 0.85em | 11.9 |

这些值由框架换算，**不进 §2.2 的 space 标尺，也不允许逐处手写成 px**：写 `markdown.Theme` 时留零即取默认。

### 2.5 例外规则

**居中余量不进网格**。固定高度的容器（如 U1 定的 33px 队列条）里让文字垂直居中，上下余量 = (容器高 − 行盒高) ÷ 2，允许半像素；网格约束的是元素之间的间距与内边距，不是"剩余空间均分"。

### 2.6 判定

相邻两块的行盒外边界之差必须等于 §2.3 的值（不含阴影与焦点环）；多行文本的段距按"下一段首行行盒上沿 − 上一段末行行盒下沿"量，且必须等于 §2.4 的框架值。走查 §2 区块（C）。

## 3 颜色语义

### 3.1 规则

1. 颜色只经语义 token 使用；元素里不得出现字面色值。
2. **明/暗两套同名同角色**；主题跟随系统（U1 参数）。
3. **强调色只用于"可操作 / 当前 / 进行中"**：主按钮、焦点、框架的选中态、待决与运行中的标记。不作装饰（分隔线、普通图标、标题不用强调色）。
4. **成功 / 警告 / 危险只用于状态**，不作大面积填充：只出现在文字、图标、1px 描边上（单处填充面积 ≤ 该行面积的 15%）。
5. 状态不以颜色单独表达（§4.0 第 4 条）。
6. 每主题 **18 个设计 token**：框架 16 个颜色字段（其中 8 个改值，见 §3.5）+ 2 个框架没有字段的补充（`border-strong`、`accent-ink`）；另有 `InactiveAccent` / `Inverse` / `InverseText` / `Scrollbar` 4 个字段沿用框架，不参与设计。

## 4 状态样式

### 4.0 固定规则

1. **只改已有元素的属性**。每个状态必须能答"用户此刻的眼睛落在哪个既有元素上"，元素归属见 `docs/domains/U1-ia.md` §5；本文不新增容器、不新增状态条、不做一状态一元素（P1、`docs/ui-alignment.md` §5）。
2. **语义态优先于视觉态**：不可用吸收悬停与聚焦，不因悬停把不可用控件点亮（`docs/project-organization.md` §9.5 第二层）。
3. 多状态并列时按固定优先级裁决：**待你决定 > 结果未知 > 失败 > 进行中 > 可用**；高优先级决定可操作性与主视觉，低优先级只作次要提示。
4. **语义态至少两项差异**（颜色 + 形态/文字/位置），色觉障碍下不得只靠颜色区分。悬停与按下是指针反馈、不承载信息，可以只有颜色一项差异。
5. 状态文字只补事实（对象、原因、数值），不承担"状态是什么"（P1）。
6. 本文不写状态文案措辞（归 U1 术语表与 U3）。
7. 框架 `Success` / `Warning` / `Danger` / `Accent` / `Focus` 只提供颜色，不提供状态语义；状态到颜色与形态的映射是本文必须补的一层。

### 4.3 状态与颜色语义的边界

- `accent-ink` 同时承担"运行中 / 待决"，因为这两者都是"当前正在发生或正在等待"，语义一致；它们靠**形态**区分（圆点 / 时钟图标）。它在两个主题下都 ≥3:1（明 4.95 最差、暗 4.31 最差，落在按下面上），满足非文本图形门槛。
- **选中不归本文**：`Sidebar` 的行选中（聚焦时 `Accent` 填充 + `AccentText`，未聚焦 `SurfacePressed`）与 `Tabs` 的选中页都由框架画；本文不新增选中色、不画竖条（UI-13）。`Selection` 只用于文本选区（§3.6）。
- `success` / `warning` / `danger` 只出现在失败、未知、成功这三种结果上，不用于悬停、选中、按钮边框。
- 失败不把正文染红：错误颜色只标"这一项失败了"，正文保持可读。

**判定**：走查 §4 区块（C），每行状态的三个属性（前景 / 背景 / 形态）可量；颜色值对 §3（A），对比度对 §7（B）。

## 5 动效

### 5.1 一律取框架默认

**不定义自有档位。** 时长与曲线全部来自框架（§0.3），代码里不得出现裸时长：

| 场景 | 值 | 来源 |
|---|---|---|
| 状态 / 颜色 / 背景 / 描边 / 不透明度 | 200ms，`EaseOut`（框架转场默认） | `ui/transition.go` |
| 出现 / 消失、折展、队列条进出、附件块增删 | 同上 200ms | 同上 |
| 列表跟随滚动、行增删 | 框架 `Smooth` 弹簧 500ms | `ui/motion.go` |
| 数值与图标的内容变化 | 框架内容动画 350ms 弹簧 | `ui/content.go` |
| 光标闪烁 | 半周期 530ms（周期 1060ms） | `ui/editor_layout.go` |
| 提示（tooltip） | 出现 600ms、热态 400ms | `ui/tooltip.go` |
| 逐字出现 | 渲染库默认（markstream-go 接入时把实际默认值登记在 §8.4，本文不预设） | 接入时实测 |

现役客户端的折叠是 300ms（`docs/domains/U0-design-archaeology.md` §12.8），本文不跟随：框架默认 200ms 已满足"动效明显、可感知"（`docs/ui-alignment.md` §2 动效 = 明显），没有需求要求 300ms。首片也不排除弹簧——框架的 `Smooth` 用于跟随滚动是上游用法，不自造"状态转场不用弹簧"的规则。

### 5.2 逐字出现

| 项 | 值 | 说明 |
|---|---|---|
| 单位 | 词（拉丁）/ 字素簇（中文） | 中文按字出，不按空格切 |
| 节奏 | 到达即出，落后时加速追平 | 不设固定速率打字机；追平参数取渲染库默认 |
| 淡入 | 取渲染库默认 | 只改不透明度/颜色，不重排、不改行高、不位移（UI-4） |
| 顺序 | 严格按事实顺序逐条追加 | 折叠只改可见性，不改顺序（UI-4） |
| 完成判定 | 队列排空（markstream 的 `Revealed`） | 排空后才挂时间与操作条 |

不与"整段淡入"混用：一条消息要么逐字出现，要么整体出现（历史回看时整体出现）。

### 5.3 光标

助手正在写的行尾光标：2×14 `accent-ink`，周期 1060ms（亮 530 / 灭 530，与框架编辑器光标同周期），随本轮完成消失。不用方块光标，不用渐变。

### 5.4 减少动效（UI-5）

这是本文唯一改框架动效行为的地方。框架在 `ReduceMotion` 下仍让颜色与不透明度继续动（`NonMotion`），而 UI-5 要求"所有转场、逐字出现、弹簧效果退化为瞬时呈现"。

| 项 | 正常 | 减少动效时 |
|---|---|---|
| 所有转场 | 框架默认（200 / 500 / 350ms） | 全部 0ms（瞬时） |
| 逐字出现 | 逐单位 + 渲染库默认淡入 | CatchUp 0、Fade 0：随事实到达整段出现 |
| 光标 | 1060ms 闪烁 | 常亮 |
| 跟随滚动 | 框架 `Smooth` | 直接跳到底 |
| 布局与状态 | — | **不变**（UI-5：开关只影响呈现，不增减元素与状态） |

实现注意：不能只依赖框架的 `ReduceMotion` 自动摊平，必须在开关为真时把时长显式设为 0（颜色与透明度默认属于 `NonMotion`，框架会继续动）。

**判定**：C（系统"减少动效" + 预览页开关各走一遍，对比布局与状态不变）+ A（所有时长等于 §5.1 的值）。

## 6 密度与图标

### 6.1 密度

**中**（U1 参数）。只提供一档，不做 compact/roomy 切换。定义的**只是自绘行**的高度与命中区，不是框架控件的尺寸——框架控件的尺寸由框架的内边距与字号算出，本文不改（UI-13）：

| 档 | 值 | 依据 |
|---|---:|---|
| `row-regular` | 28 | 自绘行的行高：现役侧栏行 28（`docs/domains/U0-design-archaeology.md` §12.4），7 × 4；框架侧栏行的高度由框架的行内边距算出，不按此值对齐 |
| `row-compact` | 24 | 现役工具行 24.5，取到 4 的整数倍（−0.5），6 × 4 |
| `control-mini` | 20 | 现役微型按钮 21，取到 4 的整数倍（−1），5 × 4；只用于自绘的微型外壳，框架按钮不取此值 |

框架没有"行高"字段（行高由文字行盒 + 内边距算出），以上三档是本文的补充值，只用于**自绘行**、虚拟列表的行高估算与命中区判定；**不用于给框架按钮/输入框设高**（UI-13）。输入卡高度 60–300、标题行 48 属区域尺寸，见 U1，不在本文重复定义。

### 6.2 行高与图标的关系

**规则：图标盒 ≤ 行高 − 2×`space-1`（8）**。

| 行高 | 图标盒 | 上下余量 |
|---:|---:|---:|
| 28 | 16 | 6 / 6 |
| 24 | 16 | 4 / 4 |
| 20 | 12（仅文字级标记，不用 SVG） | 4 / 4 |

### 6.3 图标风格与来源

| 项 | 规格 |

- Heroicons 24/outline 的文件为 `viewBox="0 0 24 24"`、`stroke-width="1.5"`、`stroke="#0F172A"`（原始文件取自 `tailwindlabs/heroicons` 仓库 `src/24/outline/`）；
- `tailwindlabs/heroicons` 的 GitHub 许可字段为 MIT；
- Lucide 的 `LICENSE` 是 ISC + 一组派生自 Feather 的 MIT 图标（GitHub 许可字段因双许可显示为 Other），因此不选它做统一图标集，避免双声明。

## 7 可访问性

### 7.1 对比度目标与实测

阈值取 WCAG 2.1 AA（正文 4.5、非文本图形与状态 3.0）；可访问性是对齐检验的固定维度（`docs/project-organization.md` §9.7），对比度按 §0.4-B 重算。

| 类别 | 目标 | 实测最小值（明 / 暗） | 位置 |
|---|---:|---|---|
| 正文与标题（全部字号） | ≥4.5 | 16.12 / 13.55（对 surface） | §3.2、§3.3 |
| 次要文本 | ≥4.5 | 5.22（悬停面）/ 4.98（悬停面） | §3.2、§3.3 |
| 成功 / 警告 / 危险作文字 | ≥4.5 | 4.56（success 对 surface）/ 5.38（danger 对 surface） | §3.2、§3.3 |
| 强调色作文字（链接、状态词） | ≥4.5 | 6.10 / 5.86（`accent-ink` 对 surface） | §3.2、§3.3 |
| 填充上的文字 | ≥4.5 | 5.17（`accent-on` 对 `accent`，两主题同值） | §3.2、§3.3 |
| 焦点环 | ≥3 | 3.82（明，落按下面）/ 4.31（暗，落按下面） | §7.2 |
| 非文本图形（状态图标、圆点） | ≥3 | 4.95（明 `accent-ink` 落按下面）/ 4.31（暗） | §4.1、§4.3 |
| 边界单独承担识别的控件 | ≥3 | 3.34（明 `border-strong` 对 surface）/ 4.41（暗） | §3.2、§3.3 |

**三处有意保留的例外**（写明理由，避免被当成疏漏）：

1. `accent` 填充在暗色面/暗色悬停面上的边界 2.88 / 2.22。该按钮有文字标签，识别由标签承担（5.17），边界不承担识别；无文字标签的图标按钮用框架 `Button`（`surface` + `border`）并给 `Label`，本文不自绘按钮外观（UI-13）。
2. 禁用态由框架给：整棵子树 0.5 不透明度、保留原面（明等效 3.31 / 暗 4.55）：WCAG 明确豁免禁用控件。本文不再对禁用控件换面（原 §4.1/§4.2 的"中性化"已删，见 §9.4）。
3. 次要文本落在暗色按下面上 4.28：按下态是 ≤200ms 的指针瞬时反馈，且这条来自框架自己的默认配色（`#a1a1aa` 落 `#3c3c41`），框架内建控件同此。要全态达标只能改框架默认色，不属本领域；本文不为此新增颜色（§4.3 同一取舍）。

系统强调色（`Preferences.Accent` 非空）时，框架按亮度自动选 `AccentText`（§0.3），本文的比值按默认强调色计算，不重算系统色。

### 7.2 焦点环

- 2px 环 + 1px 外偏移（框架 `FocusRingWidth` / `FocusRingOffset`），颜色 `focus`，**不参与布局**（画在元素外侧，出现时不引起任何位移）；由框架画，本文不逐控件设（UI-13）。
- 只在键盘导航时出现（`FocusVisible`）；鼠标点击不出现。
- 与相邻两侧的对比度：明 4.70（对 surface）/ 4.27（对悬停面）；暗 5.86 / 5.02，均 ≥3。
- 环与元素边框之间留 1px 间隙，使"环"与"边框"不混为一个更粗的边。

### 7.3 目标尺寸

交互目标最小 24×24（WCAG 2.2 AA 2.5.8）：自绘行与自绘微型外壳按下表取值（行 28、微型 20 的外壳外扩到 24）；框架控件的目标尺寸就是它自己的尺寸（按钮约 30、输入约 28，根字号 14 时），本文不放宽也不缩小（UI-13）。相邻目标之间的间距 ≥8（`space-2`），避免误触（尤其 24 工具行上的行内元素）。

### 7.4 文本缩放

系统文本缩放 100–200%（框架 `Preferences.TextScale` 乘 `Theme.FontSize`）下：

- 行高全部是倍数（正文与代码 1.5 / 1.4）或框架字体度量，没有"文字区高度 = 行数 × 固定值"的写法；
- 200% 时状态文字不得截断（走查项）；
- 图标盒随行高一起放大（按行高比例），不按字号单独换算。

### 7.5 高对比度

**沿用框架**：`Preferences.HighContrast` 为真时框架自己把 `Border` 与 `Text` 混 45%、`TextMuted` 与 `Text` 混 40%、`Focus` 转不透明、`Scrollbar` 加深（§0.3）。本文不另写覆盖规则（v1 的"border 取 border-strong、text-secondary 取 text、环加宽到 3px"是重复实现，已删）。`border-strong` 与 `accent-ink` 在框架没有字段，高对比度下保持 §3 的值。

### 7.6 色觉

每个语义态至少两项差异：运行中（圆点 + 文字"正在运行"）、失败（叉 + 状态词）、未知（叹号 + 说明行）、待决（时钟图标 + 卡片存在）、成功（勾）、选中（框架的填充 + 文字色）。红绿不并在同一元素上区分两个状态。

**判定**：B（逐格重算）+ C（Tab 走查焦点、200% 缩放走查、系统"增强对比度"走查）。
