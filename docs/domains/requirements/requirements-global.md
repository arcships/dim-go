## 0. 口径

### 0.1 一条需求一行

| 字段 | 写法 |
|---|---|
| 需求 ID | `R-AP-<序号>`；审批域内连续，三位起，不复用（其余类复核后接 `R-GS` / `R-GM` / `R-GQ` / `R-GC` / `R-GR` / `R-GF` / `R-GI`） |
| 元素 ID | 只取 [`inventory-global-rt.md`](inventory-global-rt.md) 各表第一列（`G-C1-01` 形式）；一条需求挂一个元素 |
| 维度 | 状态 / 内容 / 交互 / 动画 / 样式 / 关联 / 异常 / 记忆，再加参考产品里实际出现的其它表现（键盘、窄窗、高 DPI、暗色、无障碍、性能、多语言）；**示例，包括但不限于** |
| 场景 | 用户此刻在做什么、处在哪个采集态；未出现过的元素行首标「未观察（条件）」，其后写触发条件（数据 / 交互） |
| 期望 | 屏上可观察的结果：文案逐字、包围盒、数量、顺序、形变、去向；坐标一律 CSS px（png 像素 ÷ 2） |
| 异常 | 失败、超时、无权限、断线、资源缺失、并发时的表现；不适用写「—」 |
| 验收 | 三形态之一：①具体值；②`判据TBD；量 <屏上物件>；比对项为设计基线`；③「与期望列一致」 |

三份都是 `exec` 的普通权限请求。**没有一份态命中沙箱越权卡（C2）、子代理模型卡（C3）、成员审批区块（C1-04–C1-12）与 C4 的另外九类渲染器**——这些按清单的「需数据 / 需交互」逐条写条件，验收走形态②。

### 0.3 「未观察（条件）」的比例与写法

本版 63 个元素中，A/C38/C39 直接验证到 11 项：C1 的容器、标题、输入区块位、动作按钮组与三枚按钮（C1-01、C1-02、C1-13、C1-17、C1-18、C1-19、C1-20），以及 C4 的容器、「输入」标签、命令行、参数行（C4-01–C4-04）；其余 52 项（82.5%）在本批采集态里没有出现，逐条在场景列写触发条件（变体字段、工具名、加载结果），验收一律形态②或「与期望列一致」。

文案占位：请求里的真实工作目录写作 `{工作区路径}`，真实命令保留形态但换 `{命令}`（A 态 `ls -la` 在这批证据里可核，写作原文）。

## 1. 审批（63 元素）

审批卡贴在输入区上沿、不遮时间线；三张卡（工具权限 / 沙箱越权 / 子代理模型）共用一个外层骨架（边框 + 16px 内边距 + 与页面同底色），差异在标题、说明与按钮语义。A 态卡片 ≈370,503 647×173；标题 386,519 615×21；输入区 387,552 613×27；按钮行 y=632，按钮高 28。

### 2.5 本版仍未解决的三处

1. **C2 / C3 全组与 C4 九类渲染器没有一份采集态**：条件是特定 `variant` 与特定工具，本机三份审批都是 `exec`。这些条目只能按模板条件写，验收走形态②；要转成「具体值」验收，需要各造一次沙箱拦截、子代理换模型、`read`/`write`/`edit`/`grep`/`web_search`/`web_fetch`/`skill`/`agent`/`wait`/未登记 MCP 工具的权限请求。
2. **成员审批区块（C1-04–C1-12）需要团队分支的请求**：本机没有成员发起的审批，四段标题（就绪/加载中/失败/不可审查）无一命中。
3. **C4 的「通用渲染器」与旧版纯文本入参**：清单记旧版入参一律走通用块，但本机没有旧版请求样本，`{input: 文本}` 的实际排版只能按模板描述写，验收走形态②。
