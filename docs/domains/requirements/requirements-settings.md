## 0. 口径

### 0.1 一条需求一行

| 字段 | 写法 |
|---|---|
| 需求 ID | `R-<节缩写>-<三位序号>`，节内连续，不复用 |
| 元素 ID | 取自清单；一条需求只挂一个元素 |
| 维度 | 状态 / 内容 / 交互 / 动画 / 样式 / 关联 / 异常 / 记忆，以及参考产品里出现的其它表现（无障碍、键盘、输入法、高 DPI、窄窗、暗色、性能、外部浏览器）；**示例，包括但不限于** |
| 场景 | 用户做什么，或此刻处在什么状态与条件；带条件未出现的元素在这一列写清「什么条件下出现」 |
| 期望 | 屏上可观察的结果：文案、位置、数量、颜色、形变、去向 |
| 异常 | 失败、超时、无权限、断线、资源缺失时的表现；不适用写「—」 |
| 验收 | 三种形态之一：①具体值；②`判据TBD；量 <什么>；比对项为设计基线`；③与期望列一致 |

### 0.2 元素范围

- 四节合计 **379 个元素**（账户 112 / 用量 74 / 个性化 99 / 外观 94），全部出条目，包含「带条件未出现」的元素：这类元素的场景列固定写明触发条件，期望列写条件成立后屏上的样子。
- 元素名称、文案、坐标一律取清单原文与运行时包围盒（文档坐标 = CSS 坐标，`png 像素 ÷ 2`）；不另起名字。
- 图标行与容器行同样出条目：图标挂宿主包围盒，容器按 png 边框实测。

### 0.3 条目量口径

- 每个元素 ≥8 条；核心元素（列表、下拉、多态开关、账号、供应商、规则编辑）≥30 条。
- 维度覆盖每元素 ≥5；不足 5 的元素在该节末尾「覆盖不足说明」里逐条给理由。
- 文案类断言给逐字值；样式类断言给 `判据TBD；量 …；比对项为设计基线`，量一律落在屏上物件（字号、字重、行高、内边距、色值、圆角、边框宽、间距、对齐线）。
