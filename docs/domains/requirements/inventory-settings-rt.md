### 0.1 数据源

| 材料 | 说明 |

每条 JSON 记录是一行可见节点：`chain`（祖先链，末段是节点自身，最多 6 段）、`tag`、`role`、`text`、`label`、`x`/`y`/`w`/`h`。

坐标口径：JSON 坐标为 1× CSS px，视口宽 1030；同名 `.png` 为 2× 位图（2060×1450），即 **png 像素 = JSON 坐标 × 2**。png 只覆盖首屏（1× CSS y ≤ 725），首屏以下内容只在 JSON 里（本文三节分别为 y ≤ 807 / 143 / 1362）。

JSON 不含 `<svg>`，所以图标只在 png 可见、无法定位；本文不单列图标，仅在名称或备注里注明「图标仅在 png 可见」。

容器（R3）的位置 JSON 里没有行，本文用 png 像素扫描（找 1px 灰线，坐标 ÷2）反推，误差 ±1。实测内容列边框：外壳左右边 x=257 / 997（宽 740），侧栏分隔线 x=228。

### 0.2 元素判定（规则化，可复核）

| 规则 | 内容 |
|---|---|
| R1 控件 | `tag ∈ {button, input, textarea, select, a}` 或 `role ∈ {switch, combobox, slider, tab, tablist, tabpanel, checkbox, progressbar, group, status}` → 一个元素 |
| R2 文本块 | 有 `text` 的叶子节点（`span/p/h1–h4/dt/dd/code/label/time/th` 等）→ 一个元素 |
| R3 容器边界 | 有边框/背景的**区块级**卡片 → 一个元素（字段级外框不算：输入框、下拉、`code` 代码框的外框，其值已作元素）。JSON 未单列该行时，从 `chain` 里 `*.rounded*.border*` 之类的签名推断，标「推断」，并在统计里单列，不计入 JSON 行数 |
| R4 状态指示 | 非控件、且 `w ≤ 16` 且 `h ≤ 16` 的图标点（例如滑块拇指 14×14）→ 一个元素 |
| R5 折叠 | 文本节点的 `chain` 里若有祖先控件行，该文本并入控件（名称取该文本），不单列；相邻 `dt`+`dd` 折叠为一项「标签 + 值」 |
| R6 跳过 | 无 `text`、无 `label`、无 `role`，且 class 无 `border`/`bg-`/`rounded` 的纯布局 `div`/`span` → 结构节点，不计元素，按节报数 |

名称取法：`label` > `text` > `tag + class`，三者皆空标「无文案」。类型词表固定：`控件·按钮`、`控件·开关`、`控件·下拉`、`控件·输入`、`控件·滑块`、`控件·标签页`、`文本·页面标题`、`文本·分组标题`、`文本·标签`、`文本·辅助`、`文本·值`、`文本·链接`、`文本·指标`、`容器·卡片`、`容器·头像`、`状态·徽标`、`状态·进度条`、`指示·滑块拇指`。

计数恒等式（每节都成立，汇总表用同一式子核对）：

```
JSON 条数 = 元素数 − 推断容器数 + 折叠行数 + 跳过结构行数
```
