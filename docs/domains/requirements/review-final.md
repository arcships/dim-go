## 0. 方法与口径

- 抽样：每份 20 条，等距定种 `floor((k+0.61)·N/20)+1`（k=0..19，1-based）。四份共 80 条。
- 元素清单：按各文件 §0.1 声明的 Input 取 `inventory-settings-rt.md` / `inventory-main-rt.md` / `inventory-panels-rt.md` / `inventory-global-rt.md` 各自表的第一列作 ID 全集（992 / 401 / 260 / 276）。
- 三项判据：
  - **① 元素 ID 可追溯**：该行的元素 ID 能在对应清单里找到。
  - **② 验收合规**：三形态之一（①具体值 / ②`判据TBD；量 <屏上物件>；比对项为设计基线` / ③与期望列一致且期望给了可复核值），且量的是屏上物件（不是"该处""印证""如实""正确"这类无对象词）。
  - **③ 场景/期望具体**：场景是用户动作或可指认的条件（不是元素名、不是「与 X 同排」这类关系片段、不是内部状态表达式）；期望给出文案、坐标、数量、顺序等可观察结果（不是"清晰""同构""需固定"）。

分项：**① 元素可追溯 80/80**（全量复核依旧 0 条悬空：8,325 / 3,520 / 2,152 / 2,348）；**② 验收有值或明确基线 80/80**；**③ 场景是动作或条件 80/80**；**④ 判据主语 = 期望主语 67/80**。

三处要点：

1. 前三项这轮**全部满分**——上一轮遗留的「期望只写『保持』」「判据张冠李戴到文案/间距」在场景与验收形态层面已经清完。
2. 剩下 13 条**全部集中在第四项**，形态统一：判据挂了 `判据TBD；量 <某个真实屏上物件>；比对项为设计基线`，形式完全合规，但那个物件不是期望说的那个（期望说勾选状态、判据量高度与边框；期望说选中范围、判据量包围盒）。
3. 四份的 `判据TBD` 占比分别为 settings 57.7%、main 82.1%、global 74.8%、panels 29.2%。形式合规，但可判性实际挂在设计基线上——基线文档不落地，这些条目仍只能"按设计值判"。

**结论：panels 18/20、global 18/20 过线；main 17/20、settings 14/20 未达 18/20。** 这不是"再改一轮验收形态"能解决的，剩下的是逐条核对"期望在说什么、判据在量什么"的主语一致性——13/80 的比例外推到全量约 2,600 条，settings 最重（本组 30%）。
