### 1.3 侧栏内部结构

自上而下五段，顺序固定，只有中段滚动（`components/sidebar/AppSidebar.vue`）：

1. 头部（`SidebarHeader.vue`）：macOS 红绿灯留白 / Win-Linux 品牌；右侧“更新徽章”（下载中/已下载/错误三态）+ 收起按钮。
2. 全局入口（`GlobalEntries.vue`）：新会话、搜索（`⌘G` 提示悬浮出现）、定时任务、技能。固定在滚动区之上，不随列表滚走。
3. 滚动区：置顶区（可拖拽排序；超出可视范围时虚拟化）→ 会话列表（分组视图：内置工作区 🏠 置顶 + 可排序项目 + 固定项目；或平铺视图：今日/昨日/按日/更早，最多 3 个按日分组）。分组每项目默认显示 5 条（阈值可配），超出走“显示更多”；平铺每批 20 条。
4. 列表头（`ThreadListHeader.vue`）：左“会话”标签，右“添加项目” + 视图菜单（排序：最近活跃/最近创建；视图：按项目/平铺；折叠全部项目）。
5. 账号入口（`AccountEntry.vue`）：贴底，不参与滚动。

会话行（`ThreadItem.vue`）是侧栏里信息密度最高的单元，状态优先级写死在模板顺序里：

| 位 | 平时 | 悬停 |
|---|---|---|
| 左 6px 位 | 错误 > 运行中（转圈）> 未读点 > 置顶星 | 变成“置顶/取消置顶”按钮（错误与运行中不被替换） |
| 标题 | 单行滚动字幕式截断 + 悬停完整卡（会话名、所属项目、git 分支、分支不一致警告） | 同 |
| 尾随标记 | “待你处理”琥珀徽标 > 改动统计（+n/-n）> 快捷键编号 > 定时来源图标 > 相对时间 | 变成“归档”按钮 |

### 1.4 会话页面内部结构

`ChatWorkspace.vue` 的会话卡片底部是一条固定“底栈”（贴内容区下沿），自上而下顺序不可换：

```text
[活动条] → [待发队列] → [审批 | 提问 | 输入区] → [状态条]
```

- 活动条（`composer/activity/ComposerActivityStrip.vue`）：只显示“存在即显示”的胶囊——目标、待办、子代理、分支、唤醒、后台进程、本回合文件改动。无内容时整条不占位。
- 审批/提问（`interactions/InlinePermissionPrompt.vue`、`InlineElicitationPrompt.vue`）：占据输入区的位置，而不是叠在其上（`v-if / v-else-if / v-else` 三选一）。
- 状态条（`StatusBar.vue`）：左“工具权限 + 代理档案”，右“git 分支 + 上下文用量/套餐用量”。不放运行状态、不放会话名。
- 标题栏（`ChatHeaderFrame.vue`）：`工作区 / 会话名 ⋯` + 打开方式分体按钮 + 右栏开关；搜索展开时搜索条浮在右侧、其余右动作隐藏。

### 1.5 右栏：12 种内容页与生命周期

右栏不是“一个文件面板”，而是**按会话持久化的多标签容器**（`stores/panel-registry.ts`）。

| tab 类型 | 内容 | 关闭 | 持久化 | 来源 |
|---|---|---|---|---|
| `files` | 工作区文件树 | 不可关（默认页） | 是 | 固定 |
| `diff` | 改动列表 + 范围（未提交/分支/本回合）+ 提交/推送 | 可关 | 是 | 入口 |
| `file-preview` | 单文件预览（含 Office/PPTX/XLSX 只读） | 可关 | 是 | 点文件 |
| `browser` | 内嵌浏览器 | 可关 | 是 | 入口 |
| `terminal` | 本地 shell 多标签 | 可关 | 是 | 入口/`⌘T` |
| `workflow` | 一次 workflow 运行 | 可关 | 是 | workflow 面板 |
| `session-branch` | 侧聊（分支） | 可关 | 仅已绑定分支的 | 消息分支动作 |
| `subagent-chat` | 子代理对话 | 可关 | 否 | 点代理胶囊 |
| `session-wakeup` | 定时唤醒清单 | 可关 | 否 | 活动条 |
| `background-processes` | 后台进程清单 | 可关 | 否 | 活动条 |
| `mcp-app` | 外部应用视图（隔离） | 可关 | 否 | 工具调用 |
| `ui-extension` | 插件提供的界面 | 可关 | 否 | 插件 |

右栏三种布局（同一组件按宽度与用户操作切换，`ChatWorkspace.vue`）：

| 形态 | 触发 | 主区行为 | 右栏行为 |
|---|---|---|---|
| 并排 | 宽/常规档且未展开 | 让出宽度（margin 过渡 250ms） | 固定右侧，边缘 4px 拖宽 |
| 替换 | compact 档，或用户点“展开” | 隐藏并置 `inert` | 全宽覆盖，标题栏给返回箭头 |
| 替换 + 全宽对话 | 上述且内容页允许（非侧聊/非子代理/非任务） | — | 输入区与活动条浮在右栏底部，形成“在面板里继续聊” |

依据：`rightPanelUsesReplacement`、`showFullWidthPanelChat`、`right-panel-chat-overlay`、注释中“遮挡式 wipe：panel 恒不透明不淡出”。

### 1.6 三档宽度

`stores/layout.ts`：`compact < 720 ≤ regular < 960 ≤ wide`（内容宽度，非窗口宽度）。

| 档 | 侧栏 | 右栏 | 设置 |
|---|---|---|---|
| compact | 抽屉 + 遮罩 + Esc 关闭，导航后自动关 | 替换式 | 列表/详情两步 |
| regular | 常驻，可收起（收起留 12px 边缘预览） | 并排 | 双栏 |
| wide | 同上 | 并排，可再展开 | 双栏 |

## 2 每屏信息层级

读法：一眼 = 进入 200ms 内必须能判断的；第二眼 = 一次扫视（标题、分组、状态）；边缘 = 常驻但弱化（时间、用量、编号）；按需 = 悬停、展开、下钻。

### 2.1 新会话（P1）

| 层 | 内容 |
|---|---|
| 一眼 | 品牌标记 + 一句标题；居中的输入框（唯一可操作焦点） |
| 第二眼 | 输入框正下方的控制行：项目选择、分支、工具权限；底部模型/思考档 |
| 边缘 | 项目搜索框（展开后）、无历史 |
| 按需 | 项目下拉（可搜、内置工作区置顶、路径行）、`@` 文件提及、斜杠命令、附件 |

### 2.2 会话（P2）

| 层 | 内容 |
|---|---|
| 一眼 | 最后一条助手文本的结尾 + 是否还在跑（活动条/流式/底部跟随） |
| 第二眼 | 当前轮次结构：用户消息（右侧灰泡）、工作组一行摘要（“读 3 个文件 · 跑了 2 条命令”）、结果文本；错误行 |
| 边缘 | 完成时间、耗时、diff 统计、消息操作（复制/重试/分支，悬停才出现）、用户消息轨（≥3 轮才出现） |
| 按需 | 工具调用详情、思考块、文件改动清单、工具行里的审批结果、上下文用量明细、搜索命中导航 |

### 2.3 侧栏

| 层 | 内容 |
|---|---|
| 一眼 | 全局入口 4 项 + 当前会话高亮 |
| 第二眼 | 项目名与折叠箭头；会话标题；错误/运行中/未读/待你处理 |
| 边缘 | 相对时间、快捷键编号、改动 +n/-n、定时来源图标 |
| 按需 | 悬停完整标题卡（项目、分支、分支不一致警告）、置顶/归档按钮、项目菜单、拖拽排序 |

### 2.4 右栏（以 `diff` 与 `files` 为例）

| 层 | 内容 |
|---|---|
| 一眼 | 标签栏（当前页 + 12 类图标）与内容首屏 |
| 第二眼 | `diff`：范围选择器（未提交/分支/本回合）、提交/推送按钮、文件列表与统计；`files`：树结构 |
| 边缘 | 刷新按钮、筛选框、拒权警告条、行数与状态 |
| 按需 | 单文件 diff 展开、暂存/取消暂存/还原、文件预览、右键菜单（新标签在右侧、重载、关闭、关闭其他、关闭右侧） |

### 2.5 设置（P3）

| 层 | 内容 |
|---|---|
| 一眼 | 左导航 19 节（账号、用量、个性化、外观、通用、快捷键、模型、模态、运行时、MCP、通知、宠物、权限、git、hooks、插件设置、外部代理、归档会话、关于） |
| 第二眼 | 当前节标题 + 分组卡片（每行：标签 + 开关/输入） |
| 边缘 | 默认落点为“个性化”；顺序按“账号 → 个性 → 外观 → 模型/工具 → …”排 |
| 按需 | compact 下先列表后详情；自滚动节不走外层滚动容器 |

### 2.6 技能/插件（P4–P7）

| 层 | 内容 |
|---|---|
| 一眼 | 顶部分段（技能 / 插件）或详情面包屑；右上主操作“创建” |
| 第二眼 | 列表项：名称、描述、状态/更新徽标、来源 |
| 边缘 | “更多操作”菜单（管理、打开目录）、市场入口 |
| 按需 | 详情页、批量管理页（选中后批量启停/更新）、安装与更新对话框 |

### 2.7 定时任务（P8–P9）

| 层 | 内容 |
|---|---|
| 一眼 | 过滤段（全部/…）+ 新建按钮；列表或详情 |
| 第二眼 | 列表行：名称、计划表达式、下次运行、状态（暂停徽标）、技能缺失警告；详情：表单 + 历史执行 |
| 边缘 | 搜索框、建议模板 |
| 按需 | 创建对话框、运行历史条目跳回对应会话、删除确认 |

### 2.8 侧聊（P14）

| 层 | 内容 |
|---|---|
| 一眼 | 分支对话内容（只读历史 + 进行中的流） |
| 第二眼 | 底部单行输入 + 发送/停止/结束分支三按钮 |
| 边缘 | “分支已结束”条、错误条与重试 |
| 按需 | 分支内审批/提问（内联，一次只显示一个）、从切点继承的上下文提示 |

### 2.9 常驻 vs 按需汇总

| 常驻（任何时刻都在） | 按需（有条件才出现） |
|---|---|
| 侧栏全局入口、账号、窗口控制 | 侧栏边缘预览、悬停标题卡、项目菜单 |
| 会话标题栏、输入区、状态条 | 活动条、待发队列、用户消息轨、搜索条 |
| 右栏标签栏（打开时） | 右栏内容页、替换式返回按钮、展开按钮 |
| 一眼可辨的运行/等待状态（活动条、流式、侧栏转圈） | 审批/提问占位、错误 toast、更新徽章 |

## 3 交互模式清单

### 3.1 五种形态的定义（本文口径）

| 代号 | 形态 | 判定特征 | 焦点与遮挡 |
|---|---|---|---|
| I | 内联（inline） | 在原位置替换或插入，不新建层 | 焦点留在主区，可继续看上下文 |
| F | 浮层（float） | 下拉/浮卡/右键菜单/提示，点外部即消失 | 焦点可回到原处，不锁 |
| M | 模态（modal） | Dialog/AlertDialog，锁焦点、遮罩 | 必须显式关闭 |
| S | 静默（silent） | toast、徽标、点、转圈、相对时间 | 不夺焦点、不拦截 |
| K | 打断（interrupt） | 必须立刻回答才能继续，且占据输入位置 | 焦点让位，但不遮历史 |

关键结论：**本项目几乎没有用 M 处理“流程中必须回答”的事**。审批与提问是 K（占位内联）；M 只用于“用户主动发起的破坏性操作确认”“最危险策略变更”“全局检索”“需要输入或预览的表单”。反推：M 会盖住时间线，而审批的合理性依赖“看到是什么请求”，所以把打断做在输入位。

### 3.3 列表 ↔ 详情的切换方式（三种并存，不是一种）

| 方式 | 用在哪 | 机制 | 后果 |

## 4 设计意图反推

每条：事实（E1/E2）→ 解决的问题 → 意图（E4，必要时附 E3 注释）→ 代价。

**4.1 审批占输入位而不是弹窗。** 事实：审批面板与输入区在同一 `v-if` 链上互斥；面板按服务端给出的选项渲染（允许一次 / 始终允许 / 拒绝）。问题：审批需要“工具名 + 参数 + 影响范围”三段上下文，弹窗会遮住刚刚发生的调用。意图：把“看”与“答”放在同一视线高度；答完立刻能继续输入。代价：审批期间输入区被整体取代，待发队列与活动条一起让位，用户不能边审批边准备下一条。这是明确的产品取舍，不是缺陷。

**4.2 分支放右栏 tab，不放新窗口。** 事实：`session-branch` 是右栏 kind，绑定到某条用户消息的切点；全宽对话模式下输入区会浮到右栏底部。问题：分支的价值是“拿主线上下文问别的问题”，窗口一换就丢上下文。意图：分支必须与主线**同屏**可见，且能一边看主线一边问。代价：右栏宽度有限；分支内不再有独立的模型选择（继承切点模型/档位）。

**4.3 右栏是“标签容器”而不是“一个面板”。** 事实：12 种 kind、每会话持久化、中间键关闭、右键批量关闭。问题：读代码/看 diff/开终端/看子代理是并发的，且不同会话需要不同组合。意图：把“辅助工作面”做成可留存的会话级布局状态。代价：标签一多就需要编号提示与“关闭右侧”；compact 下只能退化为替换式单页。

**4.4 左栏是树，右栏是标签。** 事实：左栏三级（全局入口 → 项目 → 会话），右栏扁平。问题：会话是“持续存在并可归档的对象”，辅助面是“临时打开的对象”。意图：持久对象用层级，临时对象用标签；两者的关闭语义因此不同（归档 vs 关标签）。代价：左栏不能并列两个项目视图。

**4.5 侧栏全局入口固定、列表滚动。** 事实：`GlobalEntries` 在 `ScrollArea` 之外。问题：新会话/搜索/定时/技能是“从任何位置都想去”的入口。意图：入口不随列表滚走，保证第一屏永远有四个落点。代价：垂直空间固定占用约 4 行。

**4.6 状态条只放会话级事实，运行状态不进去。** 事实：状态条是权限/代理/分支/用量；运行状态在活动条、输入按钮、侧栏与流式文本里。问题：运行状态变化快、需要贴近“正在发生的内容”。意图：慢变量（策略、分支、用量）放边缘，快变量（运行、等待、错误）贴近输入与内容。代价：运行状态分散在四处，需要一致性维护。

**4.7 工具调用折叠成一行摘要，组再折叠成一行。** 事实：单工具行是“动词 + 目标 + 状态”；工作组是“读 n · 搜 n · 改 n”，运行中 shimmer，结束后可展开；只有运行的组自动展开。问题：一次任务几十个调用会淹没答案。意图：默认展示“做了什么”而不是“怎么做的”，过程可展开但不主动展开。代价：错误必须能穿透折叠（状态色、`✗`、结果卡），否则会被藏起来。

**4.8 用户消息靠右气泡，助手文本铺满宽度。** 事实：用户消息 `max-w-[85%] ml-auto` + 灰底；助手为正文流。问题：阅读的主体是助手输出（代码、表格、长文）。意图：给正文最大行宽，同时保留“谁说的”这一层。代价：用户消息里的长文本需要折叠按钮。

**4.9 用户消息轨（左侧短标记）只在 ≥3 轮出现。** 事实：阈值常量 3；轨在独立层、`pointer-events` 只在标记上开。问题：长会话里“回到某个提问”是高频动作，但早期会话不需要。意图：出现即有用，不出现不占位。代价：多一层绝对定位与滚动同步。

**4.10 通知按“是否当前会话”过滤。** 事实：`shouldShowNotificationToast` 只在“当前会话”或“系统通知不可用”时弹应用内 toast。问题：后台会话完成时弹 toast 会打断正在读的内容。意图：应用内提示只服务“你已经在该会话里”的场景；跨会话靠系统通知与侧栏徽标。代价：系统通知被关闭时，后台完成只剩侧栏徽标（可被忽略）。

**4.11 错误分三级：行内、短 toast、常驻 toast。** 事实：`recoverableError` 用 `duration: Infinity` + 恢复动作。问题：会消失的错误提示等于没提示。意图：能自愈的用行内/短 toast；不能自愈的必须留一个“可点的补救”。代价：常驻 toast 需要手动关，可能堆积（用固定 id 去重）。

**4.12 停止要按两次 Esc。** 事实：3s 窗口内第二次才执行，超时复位；鼠标点按钮一次生效。问题：Esc 也用于关搜索/退编辑/关抽屉，单次即停会误杀回合。意图：给键盘一条“无成本的反悔”，给鼠标一条“确定的动作”。代价：键盘路径上没有提示语，只有鼠标路径是自明的。

**4.13 新建会话把项目/分支/权限放在输入框正下方。** 事实：输入框与一条连体控制行共用圆角底。问题：这三项决定“这条消息会被送到哪、能做什么”，必须在提交前可见。意图：把“上下文配置”降级为输入的附属物，而不是先走一遍向导。代价：控制行只有一行高，分支与权限都被折叠成下拉。

**4.14 侧栏收起留 12px 边缘预览，而不是纯隐藏。** 事实：collapsed 时悬停浮层预览，点击边缘或 `⌘B` 才持久展开；开合动画期间边缘条不挂载。问题：纯隐藏会让“刚收起就想看一眼”变成两次操作。意图：把“看一眼”与“改布局”分开。代价：多一套 hover 生命周期与菜单打开时的例外。

**4.15 右栏开合用遮挡式 wipe，不用淡入。** 事实：panel 恒不透明，chat 卡片靠 margin 过渡让位；替换式下 chat 直接 `invisible`。问题：渐隐会露出底色缝隙与半透明内容。意图：任何一帧看到的都是完整卡片。代价：动画期间面板不可交互（`hit-test-disabled`）。

**4.16 简单/专业双模式（office / pro）。** 事实：`ui-mode` 集中一张可见性表，隐藏终端、分支控件、git 面、打开 IDE、调试菜单等，并把侧栏锁成按项目分组。问题：结果导向的用户会被过程信息劝退。意图：同一份界面按人群做渐进披露，而不是做两个产品。代价：每个新功能都要回答“哪个模式可见”。

**4.17 弹出会话窗口。** 事实：`openSessionInWindow` + 独立 `PopoutApp`（只剩会话卡片）。问题：双屏/对照阅读；也用于把某个会话从主窗口“拿出去”。意图：窗口是一等布局手段，而不是模态的替代。代价：状态需与主窗口共享（同一 App Server 事实），且弹出窗口里侧栏相关动作（置顶/新窗口）被隐藏。

**4.18 事件驱动的事实 + 界面只保留可丢状态。** 事实：App Server 是唯一真相，renderer 只存草稿、面板布局、已读等。问题：多客户端/多窗口/重启后不能出现“两套历史”。意图：界面可以随时重建。代价：所有界面状态都必须能被“重新拉一次”覆盖，动画与恢复要按“可能为空”设计。

**4.19 先做能力探测，再决定入口可见/禁用。** 事实：WIP 入口保留但禁用并写原因（`upstream-readiness.md`）。问题：入口忽隐忽现会让用户以为坏了。意图：**能力缺口用禁用 + 说明表达，不用消失表达**。代价：界面上长期存在禁用态。

**4.20 标题栏承载三层信息（工作区 / 会话 / 动作）。** 事实：`工作区名 / 会话名 ⋯`，右侧打开方式与右栏开关。问题：多项目并行时“我在哪”必须先于“我在读什么”。意图：面包屑化的归属感；动作靠右符合平台惯例。代价：窄窗口下工作区名被截断成 8rem。

## 5 继承与不继承清单

判定口径：**继承** = 结构性选择在新界面仍然成立（不涉及像素与控件）；**不继承** = 明确推翻或明确不搬，每条给理由。理由只允许三类来源：结构约束（native/单进程/无 WebView）、产品范围（`docs/project-organization.md` §3.3 与 R 的裁剪）、旧设计被自身证据否定。

### 5.1 继承（12 条）

| # | 继承项 | 具体内容 | 理由 |
|---|---|---|---|
| H1 | 三区一栏的骨架 | 侧栏（持久对象）/ 主区（会话）/ 右栏（辅助工作面），加底部输入与状态 | 三者的“关闭语义不同”是旧界面最稳的结论（§4.4）；换技术栈不改变对象性质 |
| H2 | 会话是唯一的“当前位置” | 一次只打开一个会话为前台，切换靠侧栏与搜索 | 事实归属在 App Server 的单会话流；同时读多个会话是右栏/弹出窗的职责，不是主区的 |
| H3 | 审批/提问占据输入位 | 打断以“替换输入区”实现，不用模态 | §4.1 的上下文要求（看到请求再回答）与 §4.15 的遮挡问题都指向同一结论 |
| H4 | 过程折叠、结果铺开 | 工具组一行摘要、可展开；助手文本满宽 | §4.7/§4.8：阅读主体是结果，过程按需 |
| H5 | 运行状态三处冗余 | 侧栏行、活动条/输入按钮、流式内容 | §4.6：快变量分散是刻意的冗余，切走/切回都能判断 |
| H6 | 侧栏全局入口固定 | 新会话、搜索、定时、技能四项在滚动区之上 | §4.5：入口的可用性不依赖列表状态 |
| H7 | 待发队列可见可改 | 队列在输入区上方，可编辑/删除/重排，可“插入” | 运行中提交是高频路径；黑盒队列会让用户重复发送 |
| H8 | 右栏按会话保留布局 | 打开哪些辅助页、当前页、宽度，按会话记住 | 同一会话的“工作面”在多次打开间稳定；这是旧界面被反复使用的路径 |
| H9 | 状态条只放慢变量 | 权限/代理/分支/用量；运行状态不进状态条 | §4.6：边缘承载策略，内容区承载进行时 |
| H10 | 错误的分级与“常驻可恢复” | 行内 / 短 toast / 常驻带动作 | §4.11：会消失的错误提示等于没提示 |
| H11 | 能力缺口用“可见但禁用 + 原因” | 不用消失表达缺失 | §4.19：消失会让用户以为功能坏了，也无法自查版本 |
| H12 | 渐进披露的双档（结果导向 / 过程导向） | 一张集中可见性表，不是散落的 if | §4.16：同人群差异是产品事实，与渲染技术无关 |

### 5.2 不继承（10 条）

| # | 不继承项 | 旧做法 | 理由（必须） |
|---|---|---|---|
| N1 | Web 技术栈的卡片/玻璃/皮肤视觉体系 | 三层浮起卡片、半透明 skin、ring/shadow 微调、`backdrop` 系效果 | 结构约束：CSS 合成层、皮肤热重载、逐元素 ring/shadow 与 backdrop 是 Web 实现手段；native 的层次与半透明能力需按框架实测（属 A2），不能把旧视觉当需求。新界面用什么层次手段属 C2，本文不预设 |
| N2 | 12 种右栏 tab 全量搬运 | 文件/diff/预览/浏览器/终端/workflow/侧聊/子代理/唤醒/进程/MCP App/UI 扩展 | 范围：浏览器预览、MCP Apps、UI 扩展已列范围外（§3.3）。其余 8 种是否全进首批，由 C1 定；但“一次全量”不是必须继承的结构 |
| N3 | 内嵌 WebView/`webview` 承载主界面内容 | 主区与右栏大量使用 webview 容器与 41/42/50 层叠 | 结构约束：`AGENTS.md` §3 要求主界面由 native view 组成、外部内容进独立隔离容器；旧的 41/42/50 层叠与命中测试方案不能照搬 |
| N4 | 依赖 DOM 的“悬停揭示”密度 | 悬停才出现的置顶/归档/关闭/消息操作/编号提示 | 结构约束：native 无 DOM 事件模型，悬停揭示的成本与精度不同。**可保留功能，但不保留“全是悬停”的实现假设**（哪些动作要常驻，见 §6 Q-13） |
| N5 | 依赖浏览器能力的富文本编辑器 | Tiptap/ProseMirror 的 `@` 提及、斜杠命令、粘贴转附件、IME 组合保护 | 结构约束：这些能力在 Web 编辑器里是免费的，native 需自建；不继承意味着它们的**交互合同**要重新定义为需求，而不是假定等价 |
| N6 | 用 DOM 查询做全局按键协调 | `document.querySelector('[role="dialog"]')`、`[data-testid=...]` 决定谁抢键 | 结构约束：native 没有选择器世界。按键让位必须变成显式的焦点/模态状态机（旧实现是“用选择器模拟状态机”，其结果不可移植） |
| N7 | 19 节设置一次铺开 | 单页 19 节左导航 | 产品/结构：设置节数由扩展生态撑起；范围裁剪后一次性铺开 19 节会把“设置”做成第二产品。**这不否定设置本身**，只否定“节数照搬” |
| N8 | 皮肤/宠物/市场/插件 UI 表面 | skin 主题、桌面宠物、插件市场、插件详情 | 范围：§3.3 明确范围外（宠物、插件市场）；皮肤属“外观”另行判断 |
| N9 | 以 Vue 组件 API 为设计合同 | 组件 props/emit/插槽即行为合同 | 结构约束：`mygo-native-plan.md` §A3 已写明不再以组件 API 作为新 UI 的设计合同；考古只取行为，不取接口 |
| N10 | 多窗口靠 Electron 窗口系统随意开 | popout、浏览器外壳窗口、宠物窗、MCP widget 窗 | 结构约束 + 范围：窗口管理在 mygo 下重新实现；浏览器外壳窗随浏览器预览出范围；popout 是否保留是产品问题（§6 Q-14），不能默认继承 |

## 6 新界面必须重新决定的问题

每条：旧界面如何回避 → 为什么现在没有答案 → 决定的后果面。**本节只列问题，不给方案。**

| # | 问题 | 旧界面如何回避 | 为什么新界面必须自己定 | 影响面 |
|---|---|---|---|---|
| Q-1 | 多会话并存时的注意力模型 | 只有 1 个前台会话；其余靠侧栏徽标 + 系统通知；要看两个就开 popout 窗口 | native 单窗口下“第二个会话”没有现成容器；而“同时跑多个”是真实用法 | 主区布局、通知策略、侧栏状态语义、快捷键分配 |
| Q-2 | “任务”与“对话”的层级关系 | 唤醒/后台进程/子代理都是**会话内的右栏 tab 或活动条胶囊**，没有跨会话任务总览 | 任务的生命周期长于一次阅读；是否要有“任务中心”这一层，旧界面没回答 | 页面清单（是否新增一级 surface）、状态常驻位置 |
| Q-3 | 右栏的 native 等价物 | 多标签 + 并排/替换/展开三形态 + 4px 手柄 | 标签是 Web 惯用法；native 是否同构、是否改成“分屏/抽屉/堆叠”，旧界面无证据 | 布局系统、快捷键、会话级布局持久化 |
| Q-4 | 审批的键盘通路与可发现性 | 桌面端有隐藏键位（`y`/`Enter` 允许一次、`n`/`Esc` 拒绝），但不覆盖“始终允许”，面板上也不写提示；终端把 `y/a/n` 与方向键写在面板底行 | 旧界面靠“知道的人自然知道”；native 的焦点与语义层要自建，键位覆盖面与是否常显提示必须一次定清 | 审批面板信息结构、焦点模型、教学成本、验收（键盘走查） |
| Q-5 | 长文本/富文本输入的下限 | Web 编辑器免费提供撤销、选区、拖放、IME、粘贴转附件、`@` 补全 | native 需逐项重建，且“重建到哪一层算够”没有旧答案 | 输入区规格、附件与引用模型、验收场景 |
| Q-6 | 列表虚拟化与“可选可复制”的边界 | DOM 虚拟列表 + 浏览器选择/复制/查找 | native 的文本选择、跨块复制、页面内查找都要自建；虚拟化与选择天然冲突 | 时间线规格、性能预算、验收（长会话） |
| Q-7 | 运行中再提交的默认语义 | 默认排队，另有“插入（steer）”；界面上两个动作 | 旧界面把选择留给用户每次决定；新界面要不要默认、要不要记住 | 输入区、队列、写登记意图 |
| Q-8 | 侧聊/分支的空间关系 | 右栏 tab；全宽对话时输入浮到面板底 | 空间关系取决于 Q-3；分支又是“同屏对照”的核心用例 | 布局、分支入口位置、模型继承规则展示 |
| Q-9 | 状态条承载什么 | 权限/代理/分支/上下文用量四项；明细靠浮层 | 浮层在 native 的成本与操作习惯不同；“常驻到什么程度”要重定 | 状态条信息集、用量与套餐的呈现层级 |
| Q-10 | 设置的组织模型 | 19 节左导航 + 页内下钻 + compact 两步 | 节数、分组、是否需要搜索设置、是否允许“未接能力”的禁用页，都是产品决定 | 页面清单、搜索、可见性规则 |
| Q-11 | 外观体系的边界 | 主题 + 皮肤 + 半透明窗口 + 品牌色 | native 的绘制与合成能力不同；“沿用视觉”与“沿用结构”要分开决定 | 视觉规范 C2 的输入、验收截图基线 |
| Q-12 | 键盘全通路与无障碍 | 大量依赖 DOM 语义（role、aria、focus 顺序、选择器判定模态） | native 需要显式建立焦点图与语义层；旧实现没有可搬运的等价物 | 交互规格 C3、验收（可访问性） |
| Q-13 | 悬停揭示的替代 | 置顶/归档/关闭/消息操作/编号提示全靠 hover | 触控板/键盘用户与 precision pointer 的成本不同；native 的 hover 精度与延迟也不同 | 行内动作的可见性、密度、右键菜单负担 |
| Q-14 | 多窗口 | popout 会话窗、浏览器外壳窗、宠物窗 | “窗口是不是布局手段”属产品形态决定；单进程 native 下开窗成本与收益都变了 | 窗口模型、状态共享、平台差异（D10） |
| Q-15 | 断线与重连的界面表达 | 启动遮罩、行内提示、常驻 toast、侧栏错误图标、草稿保留 | 旧界面把“连接”散在四处；新界面要不要一个统一的连接指示，是新的结构问题 | 状态可见性矩阵（C1）、错误文案 |
| Q-16 | 提醒通道的分工 | 系统通知 + 应用内可点 toast + 侧栏徽标 + 未读点 | 三通道的过滤规则是旧实现的经验（§4.10），但“谁是主通道”没写下来 | 通知规格、D10 通知实现、验收 |
| Q-17 | 首批范围与“可见但禁用”的库存 | 一次性带着一批 WIP 入口上线 | 新客户端首批不可能等价；禁用清单要不要暴露、暴露多少，影响“看起来坏了”的判断 | 首批批次划分（§9.3）、验收口径 |
| Q-18 | 事实之外允许保留什么 | 草稿、面板布局、已读、窗口状态、快捷键绑定、UI 模式 | 每加一项本地状态就多一份“重启后不一致”的风险；旧界面的清单是历史堆积，不是设计结论 | 本地状态登记（A/D 域）、恢复语义 |

小计 18 条。

## 7 补充输入：终端客户端作为对照

来源：终端客户端（`dim`，CLI，ratatui 实现）的 `crates/dim-cli/src/ui/*`。它不是桌面端的降级版，而是同一 App Server 的另一套呈现选择，因此适合校验“哪些状态必须常驻”。

### 7.1 终端界面的区域

```text
┌──────────────────────────────────────────────┐
│ 已提交转录（虚拟列表，块级）                  │
│  › 用户消息     （选中后有 e 编辑 · b 分支 · f 分叉）│
│  助手输出行                                   │
│  ▸ 工具组摘要行（运行时展开尾部）             │
├──────────────────────────────────────────────┤
│ dock（永不滚走）：                            │
│   命令输出 tail（shell 运行中）               │
│   队列条（有排队时）                          │
│   侧面板（分支/子代理，按需，最多 1/3 高度）  │
│ ┌──────────────────────────────────────────┐ │
│ │ 输入框：上边框 = 运行状态/模式，下边框 = 模型 · 位置(cwd/branch) │ │
│ └──────────────────────────────────────────┘ │
│ 审批/提问出现时整体替换输入框                  │
└──────────────────────────────────────────────┘
浮层：命令面板/选择器居中，转录变暗
```

同一程序有两种呈现：**滚回模式**（转录直接进终端历史，输入框跟随其后；侧面板开在输入框下方，像菜单）与**全屏模式**（转录是独立视口，dock 固定；侧面板开在转录与输入之间）。两者共用同一份内容与键位，差别只是“谁拥有滚动”。

依据：`ui/render/fullscreen.rs` 顶部注释与 `ui/tui.rs` 的 dock 组装（`queue_strip`、`side_panel`、`composer_box` 的 `title`/`last` 行）。

### 7.2 终端里必须常驻的状态

| 状态 | 位置 | 为什么必须常驻 |
|---|---|---|
| 是否在运行 + 已运行多久 | 输入框上边框（`working… 12s`，含脉冲帧） | 终端没有别的地方能显示“还在动”；用户可能在等 |
| 队列 | 输入框上方条（高度会“记住”，队列排空也不跳） | 队列不可见时用户会重复发送 |
| 审批待答 | 替换输入框 | 与桌面同结论：回答是唯一前进路径 |
| 位置（cwd / git 分支） | 输入框下边框 | 命令与改动的后果取决于位置 |
| 模型 | 输入框上边框右端 | 输出质量差异的唯一提示 |
| 工具组运行态 | 摘要行（`Running ▸` / `Explored` / `· N kept`） | 转录是唯一的历史视图，必须自解释 |

### 7.3 终端与桌面的对照（只列不同，不判断优劣）

| 维度 | 终端 | 桌面 |
|---|---|---|
| 打断形态 | 审批/提问替换输入框；`y` 允许一次、`a` 始终允许、`n` 拒绝，面板底行常显键位 | 审批/提问替换输入区；隐藏键位 `y`/`Enter` 允许一次、`n`/`Esc` 拒绝，面板不显示提示；其余靠按钮 |
| 通知 | 系统级：iTerm2 `OSC 9`、kitty `OSC 99`、Ghostty/WezTerm/foot `OSC 777`、其余 `BEL`；多路复用器一律 `BEL` | 系统通知 + 应用内可点 toast（按会话过滤） |
| 停止 | `Esc` 一次中断，队列消息退回 | `Esc` 两次（3s）或按钮 |
| 中断/队列 | `Ctrl+S` 把草稿或最早队列项改为插入（有专用键） | 提交默认排队，插入是队列项上的动作（无专用键） |
| 会话切换 | 进程级：退出再 `--resume`；转录靠终端滚动缓冲 | 侧栏切换，`KeepAlive` 保位置 |
| 过程折叠 | 工具组折叠，摘要短语（`Explored`、`Read 3 files`） | 工具组折叠，计数摘要 |
| 搜索历史 | 交给终端自己的搜索（不同终端不同键） | `⌘F` 应用内搜索 + 命中导航 |
| 富文本 | 无；`@` 提及与粘贴标记是纯文本协议 | 富文本编辑器 + 附件胶囊 |
| 多任务并存 | 多开进程 | 多会话 + 右栏 + popout |

### 7.4 从终端得到的硬结论

1. **“运行中”和“等待你回答”是必须常驻的两态**；两套客户端都把它们放在输入位置及其上方，未放在设置或日志里。新界面若把这两态做成需要点开才知道，等于退步。
2. **队列必须可见**，且高度要稳定（终端甚至刻意保留已排空的行高）。
3. **过程的默认形态是“一行摘要”，不是“完整日志”**；两套客户端独立收敛到同一选择。
4. **停止动作在键盘上需要一层缓冲**（终端是 `Esc` 可恢复队列，桌面是 `Esc`×2）；两套都在防误触。
5. **位置（工作区/分支）与模型属于“输入框的边框信息”**：它们不进入正文，但也不能藏进菜单。
