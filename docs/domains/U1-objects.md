# U1 界面对象模型

Status: draft（先于线框；随线框版本一起评审）
Owner: U1 界面需求与信息架构
依据: `docs/project-organization.md` §9.9–§9.11（U1/U2/U3 裁决与颗粒度标准）、`docs/domains/U1-brief.md`、`docs/ui-alignment.md`、`docs/domains/D2-projection.md`、`docs/domains/D5-interaction.md`
用语规则: 界面一律用普通人能懂的说法；内部术语（投影、事实、写登记、行身份、证据行）不得出现在界面文案里。

## 1 可展现对象（13 个）

| # | 对象 | 一句人话 | 来源 |
|---|---|---|---|
| O1 | 会话 | 一条对话，有自己的工作目录、分支、标题和状态 | R 块 5；`session.catalog`、`session.summaries` |
| O2 | 分支 | 会话里的一条线，默认一条主线；可以从某一轮分出另一条 | R 块 4；`session.branches`、`session.branch_create`、`session.fork` |
| O3 | 轮次 | 从你发出一句话，到它把这件事做完，算一轮 | R 块 2；`session.history`、`turn/end` |
| O4 | 消息 | 轮次里的一句话：你说的一句，或它回的一段 | R 块 2；`step/text`、`input/message` |
| O5 | 操作 | 它在轮次里做的一件事：读文件、改文件、跑命令 | R 块 2；`step/tool-use`、`tool-completed` |
| O6 | 审批 | 某个操作需要你先同意，它才能继续 | R 块 6；`approval.request`、`approval.respond` |
| O7 | 提问 | 它反过来问你一个问题，等你回答 | R 块 7；`session.question.pending`、`session.question.respond` |
| O8 | 排队项 | 你提交了、但还没轮到发送的一条输入 | R 块 3；`session.input.pending`、`session.input.withdraw` |
| O9 | 目标 | 这条会话要达成的结果，可以设、可以暂停 | R 块 2；`session.goal.set/pause/resume` |
| O10 | 附件 | 跟消息一起发出去的文件或图片 | R 块 12；`attachment.put` |
| O11 | 账号 | 登录状态、套餐与用量 | R 块 10；`account.status`、`account.usage` |
| O12 | 变更 | 这一轮或这条分支改过的文件与差异 | R 块 11；变更读取、git 只读 |
| O13 | 任务 | 轮次结束后还在后台继续跑的一次执行，可以停 | R 块 2、块 9；`session.exec.pending`、`session.exec.stop` |

## 2 层级：谁属于谁

```text
会话 O1
├─ 分支 O2（默认一条主线）
│   └─ 轮次 O3
│       ├─ 消息 O4（你说的 / 它说的）
│       │   └─ 附件 O10
│       └─ 操作 O5
│           ├─ 审批 O6（针对某一次操作）
│           ├─ 提问 O7（操作里问你）
│           └─ 变更 O12（这次操作改了哪些文件）
├─ 排队项 O8（还没开始，不属于任何一轮）
├─ 目标 O9（跨轮）
└─ 任务 O13（由某轮的操作发起，但活过那一轮）

账号 O11 在应用级，不属于任何会话
```

要点：
- 附件跟着消息走；一条消息可以有多个附件。
- 审批与提问是"某一次操作卡住了"，因此属于该操作、也就是属于那一轮。
- 一个轮次可以没有操作（纯对话），也可以有几十个操作。

## 3 附属：谁挂在哪一层

| 问题 | 答案 | 依据 |
|---|---|---|
| 右栏内容属于谁 | **当前会话**：文件、变更、任务、目标都是这条会话的附属内容；不放另一条会话 | §9.9 U2 |
| 审批属于哪一轮 | 属于触发它的那次操作所在的那一轮；一个会话同一时刻最多一条待答审批 | R 块 6、D5 |
| 提问属于哪一轮 | 同上，属于发起提问的那次操作所在那一轮；一次只答一个 | R 块 7 |
| 队列项属于哪一层 | 属于**会话**，不属于任何一轮（它是还没开始的那条输入） | R 块 3 |
| 目标属于哪一层 | 属于**会话**，跨轮存在；可以指向设它的那一轮 | R 块 2 |
| 任务属于哪一层 | 由某一轮的操作发起，但生命周期长于那一轮；在右栏按会话汇总 | R 块 9、Q-2 |
| 账号属于哪一层 | 应用级，不属于会话 | R 块 10 |

## 4 跨对象引用

| 引用 | 谁引用谁 | 界面上怎么表现 |
|---|---|---|
| 操作 → 文件 | 操作引用它读写的文件路径 | 操作行里写文件名；展开看路径与结果 |
| 审批 → 命令 | 审批引用它要执行的那条命令 | 审批卡里原样显示命令与影响范围 |
| 目标 → 轮次 | 目标记录设它的那一轮 | 目标展开时写"在第 N 轮设定" |
| 变更 → 文件 | 变更引用被改的文件 | 轮末计数；右栏"变更"列出文件 |
| 任务 → 操作 | 任务由某次操作发起 | 任务行写发起它的操作名 |
| 提问 → 选项 | 提问带可选项，可多选 | 卡片内直接列选项 |

## 5 界面用词表

| 对象 | 界面里叫什么 | 不这么叫 |
|---|---|---|
| 会话 O1 | 会话 | thread、session、上下文 |
| 分支 O2 | 分支 | branch、line |
| 轮次 O3 | 这一轮 / 第 N 轮 | turn、round、iteration |
| 消息 O4 | 消息 | message、block |
| 操作 O5 | 操作 | 工具调用、tool call、步骤、evidence、证据 |
| 审批 O6 | 待你同意 | approval、permission gate、确认框 |
| 提问 O7 | 它的问题 | question、ask_user、elicitation |
| 排队项 O8 | 排队中 | 待发、pending、queue item |
| 目标 O9 | 目标 | goal、objective |
| 附件 O10 | 附件 | attachment、upload、file staging |
| 账号 O11 | 账号 | account、profile、OAuth |
| 变更 O12 | 改动 | diff、changeset、delta |
| 任务 O13 | 后台运行 | task、background job、exec |
| 一轮的过程（多次操作） | 它做了什么 | 过程、trace、证据行、投影 |
| 提交结果不确定 | 结果不确定 | 未知状态、indeterminate、写登记 |

禁用词（界面不得出现）：投影、事实、写登记、行身份、证据行、trace、fold、folded state、sequence、token（作为"凭证"讲时）。

## 6 展示位置与理由

| 对象 | 出现在哪一层 | 为什么在这一层 |
|---|---|---|
| 会话 O1 | 左栏导航 | 持久对象，要能在任意位置跳到；层级式导航适合"存在并被归档"的东西 |
| 分支 O2 | 标题行 | 它改变"这条消息发到哪条线上"，属于当前会话的属性，随会话切换而变 |
| 轮次 O3 | 主区时间线 | 阅读与回看的单位是一轮，不是单条消息 |
| 消息 O4 | 主区行内 | 正文主体；用户消息右对齐、助手铺开 |
| 操作 O5 | 主区行内，收成一行 | 默认看结果，需要时展开看它做了什么 |
| 审批 O6 | 输入位（替换输入区） | 不回答就无法继续，且必须与刚发生的事同视线；§9.9 U1 |
| 提问 O7 | 输入位（同位置） | 同上；一次只答一个，不与审批叠层 |
| 排队项 O8 | 输入区上方 | 不看见就会重复发送；它是"还没轮到的输入"，紧贴输入区 |
| 目标 O9 | 标题行（展开看详情） | 跨轮的会话属性，不该在每一轮里重复出现 |
| 附件 O10 | 输入区（待发时）/ 消息内（已发） | 发之前是可移除的条目，发之后是消息的一部分 |
| 账号 O11 | 左栏底部 | 应用级入口，不属于任何会话，但要在主界面一步可达 |
| 变更 O12 | 右栏 + 轮末一行计数 | 明细属于会话附属内容；主区只留"改了几个文件" |
| 任务 O13 | 右栏 + 发起它的操作行 | 生命周期长于一轮，需要在会话层面汇总；主区只在发起处留标记 |

## 7 与线框的对应

线框（`docs/domains/wireframes/`）每张画布旁有一列说明，逐段标出"这一段是哪个对象的哪一部分"。两处硬约束直接来自本文件：

- 审批卡出现时，输入区不存在（同一块区域换内容）——U1。
- 右栏标签只有本会话的附属内容（文件 / 改动 / 后台 / 目标）——U2。
