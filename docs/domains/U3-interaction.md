- 提问通知（协议没有；只由清单与时间线事实驱动）。

## 1 任务五段

### 1.0 通用约定

1. **事实优先**：界面只呈现事实与已登记的本地状态；本端占位（发送中、撤回中、正在停止）必须带明确形态，且不得被误读为已发生的事实。
2. **同屏唯一**：同一内容在任一时刻只出现在一个位置；占位消失与事实出现必须同时发生（同一帧），不得先删后补或先补后删。
3. **失败与未知分界**：`明确失败`/`未发生` 允许重发（新幂等键，D3 许可）；`未知` 与 `需人工确认` 不自动重发，也不给假重试。
4. **多态并存**按 `docs/project-organization.md` §9.5 的优先级裁决：待你决定 > 结果未知 > 失败 > 进行中 > 可用。该优先级只裁决同一元素上的形态，不改变事实。
5. **一个位置一件事**：输入位只有一个动作槽（发送/停止），一个决定只有一组互斥选项；不并排放置语义不同的控件。检查结果见 §4.5。
6. **不抢焦点**：除 §3.2 明列的 F4/F5/F6/F8/F9 五种情形，任何状态变化都不移动焦点。

### T1 打开会话

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 左栏会话行上按 Enter 或点击；`Cmd+1..9`；命令面板选中会话。空态发出首条不属本任务（新建在后续批次） | 被选行成为当前会话；标题行出现会话名 |
| 前置 | 控制连接已连接；会话在目录中且已载入；会话未处于版本不兼容；`session.attach` 在能力内 | 不满足时按"失败"段处理，不进入半载入状态 |
| 完成 | attach → 首屏历史（最近一轮）折叠 → 待决清单与审批快照装载 → 权限档位读取 → 滚动位置恢复（本会话上次离开位置；没有或锚点行已不存在的，到最新） → 输入区按档位与连接状态决定可用性 | 最近一轮可见；顶部"读更早"存在当且仅当 `hasOlder`；有排队时队列条出现；档位未读到则输入区不可编辑并给一行原因；同一轮次不重复 |
| 失败 | attach、历史、清单任一失败：主区给一行"这条会话暂时打不开"+包装后的原因+"重试打开"；已显示内容不清空；输入区禁用并给原因。档位读取失败：内容可读、输入区禁用（有"重试读取"） | 不出现空壳会话页；不把失败当空历史；重试只重读，不重发任何写 |
| 断线 | 已显示的行保留可读；未落库尾部消失；底部一行"连接断开，正在重连"；输入区禁用；重连后按序号重读、行按身份去重、档位与清单重读；焦点按 F9 | 断线期间不追加任何本端推测的行；重连后同一行不出现两次；"正在重新载入"只在重读进行时出现 |

**断言**：打开完成后，"输入区可用" ⇔ "连接在线 且 档位有值"；顶部翻页行的存在 ⇔ `hasOlder` 为真。

### T2 发送（未运行时）

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 输入区非空（首片只认文本），按 Enter 或点槽位"发送" | 输入区内容离开输入区，出现"发送中"占位（位置见 §4.2）；槽位变为禁用 |
| 前置 | 在线；会话已打开且未运行；档位有值；文本非空；输入位没有被审批/提问卡占用（UI-1）；同一会话没有同一条在途提交 | 任一不满足时槽位"发送"禁用并给一行原因（S24），不进入发送 |
| 完成 | 写登记受理 → `session.submit` 回执 → 清除"发送中"占位 → 用户消息行由 `input/message` 事实出现 → 运行态由会话状态事实出现 | 同一内容只出现一次；占位与事实同一帧交接；槽位随运行事实变为"停止"；输入区立即可继续输入 |
| 失败 | 明确失败：占位按 §4.2 回填，一行包装后的原因；内容不丢失；仅当错误分类允许（请求未发出，或参数问题已修正）时用槽位"发送"重发（新幂等键，D3 允许） | 不显示"已发送"；不自动重试；不出现第二个发送入口 |
| 未知 | 超时或断线：占位保持并显示"结果不确定 · 正在核对"（内部核对参数不上屏）；结论"未发生"时原文回填、可再次发送；结论"需人工确认"时不提供重发 | 核对期间槽位"发送"禁用；结论只来自核对与事实，不由本地推断 |
| 断线 | 在途提交转未知；输入区禁用但内容与草稿保留；重连后核对继续；不自动重发 | 重连后占位仍在原位置，状态为"结果不确定"或收敛到成功/未发生 |

**断言**：提交受理后输入区为空且"发送中"占位存在；成功后占位消失且恰好一条用户消息行；全程槽位只有一个控件。

### T3 运行中再提交：排队与插话

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 运行中按 `Cmd+Enter`（排队）或 `Cmd+Shift+Enter`（插话）；鼠标路径：右键槽位 →"排队发送"/"插话发送"（有草稿时可用） | 占位进入队列位（R4 上沿，UI-10）；槽位仍是"停止"，不因提交改变 |
| 前置 | 会话正在运行（事实）；在线；档位有值；输入位未被卡占用；有草稿；`session.submit` 在能力内；鼠标菜单在运行中且有草稿时展开 | 不满足时组合键无动作并播报原因；运行态判断以会话状态事实为准，不以本端计时为准 |
| 完成 | 受理 → `input/pending` 事实 → 队列行稳定；默认投递方式（排队）不标注，插话标注"插话"；被消费时队列行消失与时间线出现同一内容同一帧 | 队列顺序与清单顺序一致；行内容、`mode`、`applied` 与清单逐条一致；槽位未出现第二个按钮或第二位停靠点 |
| 失败 | 明确失败：不进入队列，按 §4.2 回填；`未发生`（核对）：可重发；`未知`：不给重发 | 队列条不出现该内容；不产生"幽灵排队项" |
| 断线 | 队列行保留显示，撤回按钮禁用；重连后以清单为准整体重建；本端不预删任何行 | 已不存在的行必须伴随 `consumed`/`deleted`/`withdraw` 事实；没有事实就不删 |
| 插话特例 | 插话行在 `input/applied` 后标"已应用"并禁用撤回（`applied=true` 即不可撤回，D2）；随后进入本轮消息行 | 不把"出现在清单里"当成"等下一轮"；`mode=steer` + `applied` 区分 |

**断言**：队列条每行都有稳定身份（`inputId`），刷新与重连后同一行不重复、不换序（除事实变化）。

### T4 停止（运行中）

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 点槽位"停止"；或焦点在输入区时按 Enter；或命令面板"停止这次运行" | 槽位文案仍为"停止"，进入禁用；上沿一行"正在停止" |
| 前置 | 会话正在运行；输入位未被审批/提问卡占用（UI-1 的直接后果）；未收到 `session.stop` 的能力缺失；槽位可见 | 不满足时无停止入口；不以"可能没在跑"为由发停止 |
| 完成 | 受理 → 等事实：本轮以 `cancelled` 结束 → 摘要行显示"已停止" → 槽位按最新运行事实恢复（无新轮则"发送"；队列被消费开新轮则"停止"） | "已停止"只在 cancelled 事实之后出现；时间线该轮不再新增生成内容；槽位没有消失或换位 |
| 失败 | 明确失败：槽位恢复"停止"可用，一行原因；能力缺失：槽位在运行中不显示，原位置一行"这个版本不能停止"，不改运行态；未知：上沿"停止结果不确定"，槽位禁用，不重发、不给"再停止一次"，以轮次结束事实收尾 | 不出现"已停止"而无事实；不出现自动重试；能力缺失不被写成"已停止" |
| 断线 | 槽位"停止"禁用，上沿给原因；重连后按事实恢复（仍在运行则可停止，已结束则槽位变"发送"） | 断线期间不做本地状态迁移 |

**断言**：运行中槽位文案恒为"停止"且只有一个控件；停止控件存在 ⇔ 会话运行中 且 未收到能力缺失 且 输入位无卡。

### T5 应答一次审批

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | `approval.request` 到达且为会话待决队列的队首，或 attach 重放快照带来队首 | 输入区被审批卡替换（UI-1）；槽位不显示；草稿保存；焦点按 F4 进入卡容器；若窗口在前台且是当前会话，播报到达 |
| 前置 | 在线；会话当前；卡是队首（非队首不渲染）；能收到审批请求即视为可应答（不额外探测方法表）；卡内动作可用性按 §5.2/§5.3 计算 | 同一会话只显示一条；审批与提问同时存在时按到达顺序取队首，不按类型提权 |
| 完成 | 一个决定被写登记受理 → 卡转为只读"已允许/已拒绝，等待结算" → 服务端结算 → 卡消失、槽位按运行事实恢复 → 焦点回输入区（F5） → 工具行显示该操作的允许/拒绝结果 | 受理后卡内没有任何可再点的决定；结算前卡不消失（断线与服务端取消除外） |
| 失败 | 应答明确失败：卡回可答，一行包装后的原因；结果未知/需人工确认：按已答处理、不重发，卡显示"已发出，结果不确定"；始终允许的规则写入失败：不发生同意，卡回可答并说明"规则没有写成功，这次操作还没有被同意" | 不存在"规则失败但已同意"的状态；不存在同一审批被答两次 |
| 断线 | 待决集合被清空（D5）：卡消失、槽位按断线状态显示、焦点按 F5 兜底到时间线；重连后快照重放，卡重建但不抢焦点，只播报（F6） | 断线期间不保留一个无法应答的卡；重建后草稿与队列不变 |

**断言**：卡在"已答未结算"时，决定按钮全部不可用且状态文字可读；结算后卡消失、槽位恢复，且工具行可看出"曾发起过审批"。

### T6 应答一次提问

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 会话待决队列队首是提问（清单装载或截止点后的 `ask_user` 事实） | 输入区被提问卡替换；槽位不显示；焦点进卡容器；播报到达 |
| 前置 | 在线；会话当前；问题解析成功（至少一个问题）；`session.question.respond` 在会话能力表内 | 解析失败不渲染空卡：显示一行"这个问题读不出来"+原因，且不提供作答；能力缺失时显示卡与一行原因，不提供提交（问题本身是事实，不能隐藏） |
| 完成 | 回答或跳过被受理 → 卡只读"已回答/已跳过，等待结算" → 工具结果结算 → 卡消失、槽位按运行事实恢复 → 焦点回输入区 → 回答内容出现在该操作的展开层 | 一次只显示一条；批次内多个问题共用一次提交；结算前不移除 |
| 失败 | 明确失败：卡回可答、已填内容保留（D5 把"已答"定义在受理之后）；未知：按已答、不重发 | 不出现"已跳过"但实际未发出 |
| 断线 | 卡消失；重连后按清单重建，清单失败退回历史推导时卡内标注"按历史推得，可能不全"（D5 §7 第 4 条） | 不伪造截止时间；不显示倒计时 |

**断言**：卡上不存在倒计时元素；"跳过"等价于取消（`cancel`），不是拒绝；回答提交后不可改答。

### T7 展开与收起过程摘要

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 焦点在过程摘要行上按 Enter 或 Space；点击该行 | 该轮在原地展开/收起 |
| 前置 | 该行处于折叠态或展开态；该轮已载入 | 未载入的轮次不提供展开 |
| 完成 | 展开后按事实顺序列出条目（动作 · 对象 · 结果 · 耗时；失败带原因）；摘要行保留；展开状态按会话记住（UI-8） | 行高只在本轮内变化；焦点仍在摘要行；新内容只追加在尾部（UI-4） |
| 失败 | 不适用（纯本地状态）；没有条目时摘要行只保留状态，不生成空展开区 | 不出现"加载中"这类假状态 |
| 断线 | 展开状态保留；断线期间无新条目；重连后按重读结果追加，不重排 | 展开的轮次不因重连自动收起 |

**断言**：展开前后，摘要行文本不变（只变 Expanded 状态）；展开内容的顺序与事实序号一致。

### T8 翻页读更早

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 时间线顶部"读更早"行按 Enter/点击；或焦点在时间线时按 PageUp：未到顶先上翻一屏，已到顶再按才请求更早（↑/↓ 只移动焦点，不触发翻页） | 顶部出现"正在读更早"（行内状态）；不阻塞输入区 |
| 前置 | `hasOlder` 为真；在线；没有在途翻页；当前分支固定 | 不满足时该行不出现 |
| 完成 | 以 `before=cursor` 读一页 → 合并到顶部 → 原首行仍在原屏幕位置 → `hasOlder` 更新 → 用户主动翻页到达最早时，顶部一行"已到最早"；首屏即无更早时不显示任何顶部行 | 不出现重复轮次；滚动锚点不动；焦点留在原行（内容下移但焦点跟随同一行） |
| 失败 | 一行包装后的原因 + "重试读更早"（读重试允许）；已显示内容不动；不切走焦点 | 不把读失败当成"已到最早" |
| 断线 | 翻页请求中断：行内"这次没有读完，连接断开"；重连会重置分页（D2），旧页需重新请求；滚动位置按锚点恢复，无法恢复则回到最新并一行"已重新载入" | 断线后不出现半页内容；不重复已加载轮次 |

**断言**：每次翻页只新增一页；`hasOlder` 与顶部形态一致；任意时刻不出现同一轮次两次。

### T9 切换会话

| 段 | 行为 | 可观察结果 |
|---|---|---|
| 触发 | 左栏选中；`Cmd+1..9`；`Cmd+Shift+[` 或 `Cmd+Shift+]`；命令面板选中 | 当前会话切换；标题行更新 |
| 前置 | 目标会话在已载入目录中；未处于版本不兼容；切换不需要断开旧会话 | 目标不在目录时不切换，给一行原因 |
| 完成 | 切换前若正在组词，先提交组词内容到旧会话草稿；旧会话保存草稿、展开状态、滚动位置；新会话按 UI-8 恢复；待决卡属于各自会话，旧卡留在旧会话；焦点按 F7 | 切回旧会话时草稿、展开与位置原样；不串会话 |
| 失败 | 目标打开失败：留在旧会话，一行原因 + "重试打开"；不显示空壳新页 | 旧会话内容不被清空；输入区不被新会话的失败连带禁用 |
| 断线 | 切到已载入会话：显示其已载入内容，输入区禁用并给原因；重连后按当前会话重读 | 断线切换不清空任何已载入内容 |

**断言**：切换前后发送的内容只出现在发起时的会话；旧会话草稿修订号不被新会话复用。

## 2 键位模型

修饰键写法：`Cmd` = macOS 的 Command，其他平台 Ctrl（框架的 `ui.Cmd`）；`Ctrl` 指字面 Control。首片不提供键位重绑；设置里的键位提示归后续批次。

### 2.1 默认键位表（23 项）

| # | 动作 | 键 | 生效条件 | 行为 |
|---|---|---|---|---|
| K1 | 发送 / 停止 | Enter | 焦点在输入区；非输入法组词；无覆盖层；未运行时需内容非空，运行中不看草稿 | 未运行→发送；运行中→停止（与槽位动作一致） |
| K2 | 排队发送 | `Cmd+Enter` | 运行中；有草稿；非组词；无覆盖层 | 以 `queue` 提交，槽位不变 |
| K3 | 插话发送 | `Cmd+Shift+Enter` | 同 K2 | 以 `steer` 提交，槽位不变 |
| K4 | 换行 | `Shift+Enter` | 焦点在输入区；非组词 | 插入换行，不提交 |
| K5 | 换行 | `Ctrl+J` | 同 K4 | 插入换行（终端习惯） `[沿用]` |
| K6 | 允许一次 | Y | 审批卡为队首；无覆盖层；焦点不在文本输入；非组词 | 同"允许一次" |

| K10 | 展开 / 收起摘要 | Enter 或 Space | 焦点在过程摘要行 | 切换展开状态 |
| K11 | 打开所选会话 | Enter | 焦点在左栏会话行 | 打开该会话 |
| K12 | 区内移动焦点 | ↑ / ↓ | 焦点在左栏列表；或时间线（只移动焦点，不翻页） | 上一行/下一行 |
| K13 | 上翻 / 读更早 | PageUp | 焦点在时间线 | 未到顶：上翻一屏；已在顶部且 `hasOlder`：读更早 |
| K14 | 跳到顶部 | `Cmd+↑` | 焦点在时间线 | 滚到已加载最早处（不自动读取） |
| K15 | 跳到最新 | `Cmd+↓` | 焦点在时间线 | 滚到最新并恢复"跟随底部" |
| K16 | 首行 / 末行 | Home / End | 焦点在时间线 | 焦点移到已加载首/末行 |
| K17 | 聚焦输入 | `Cmd+L` | 无覆盖层 | 焦点到输入区文本末尾；卡占位时到卡容器 |
| K18 | 打开第 n 个会话 | `Cmd+1..9` | 无覆盖层 | 打开左栏第 n 个可见会话 |
| K19 | 上一条 / 下一条会话 | `Cmd+Shift+[` / `Cmd+Shift+]` | 无覆盖层 | 按左栏顺序切换 |

| K23 | 关闭覆盖层 | Esc | 覆盖层打开 | 关闭面板/菜单并回焦到打开它的元素（F8） |

### 2.2 冲突消解

按键归属按下列顺序裁决，先命中者取得该键，后续不再处理：

| # | 层级 | 规则 |
|---|---|---|
| C1 | 输入法组词 | 组词期间未修饰键全部归输入法；客户端快捷键整组让路（含 Esc、Enter、Y/A/N、Tab、方向键、`Cmd` 组合）；组词结束后恢复，被让路的按键不补发 |
| C2 | 覆盖层 | 命令面板或槽位菜单打开时，除 Esc（面板下另有 `Cmd+K`）外不响应客户端快捷键；Tab 在面板内循环，菜单用方向键 |
| C3 | 待决卡 | 卡为队首时：Y/A/N 只在焦点不在文本输入且非组词时生效；Enter 不答复（焦点在卡容器时无动作）；Esc 不答复、不跳过 |
| C4 | 队列行 | 焦点在队列行时 Backspace/Delete 为撤回；不进文本输入语义；撤回中再按无效 |
| C5 | 文本输入 | 焦点在输入区时 Enter 按 K1（发送或停止）、Shift+Enter/Ctrl+J 按 K4/K5；`Cmd+L` 仍可用；方向键归光标 |
| C6 | 时间线 | ↑/↓、PageUp、Home/End、Enter/Space 按 K10–K16；↑/↓ 不触发翻页；`Cmd+↓` 不切换会话 |
| C7 | 全局 | `Cmd+K`/`Cmd+1..9`/`Cmd+Shift+[`/`]`/`Cmd+L` 在无覆盖层时生效；卡占位不屏蔽 `Cmd+1..9`（切走会话合法） |
| C8 | Esc 专表 | Esc 只关闭覆盖层或交给输入法/文本选区；不停止、不答复、不跳过、不切换会话 |

**Esc 语义顺序**（从高到低，命中即止）：

1. 输入法组词中 → 交给输入法（取消组词）。
2. 覆盖层打开 → 关闭覆盖层（K23）。
3. 输入区有文本选区 → 清除选区（框架文本行为）。
4. 其余 → 无动作。

`[改变]` 现役客户端把 Esc 同时用于"关闭浮层/退编辑/停止预备"和"拒绝审批"；本规格把停止移到 Enter/槽位（与槽位一致），并把决定类动作移出 Esc（K8）。停止不再有"按两次"的预备态，代价与缓解见 Q11。

### 2.3 输入法组词

| 情形 | 规则 |
|---|---|
| 组词中按 Enter | 提交候选，不发送、不停止消息（C1） |
| 组词中按 Shift+Enter | 交给输入法（候选翻页/保留），不换行 |
| 组词中按 Esc | 取消组词，不关闭覆盖层、不停止、不拒绝 |
| 组词中按 Y/A/N | 作为候选字母，不触发决定 |
| 组词中 `Cmd+K`/`Cmd+L`/`Cmd+1..9` | 不触发，也不排队；组词结束后用户需重新按键 |
| 组词提交后的同一次按键 | 只用于提交候选，不冒泡为 K1；停止/发送需要新的一次按键 |
| 组词中鼠标点击别处 | 由平台提交或取消组词；提交后按普通按键处理，不重放组词期间被吞的快捷键 |
| 判定依据 | 只用框架的 `Composing()`；不按"最近按了哪个键"推断 |

### 2.4 平台与可发现性

- 所有快捷键在 macOS 用 `Cmd`，其他平台用 Ctrl；字面 `Ctrl+J` 例外（两端都是 Control）。
- 槽位是唯一动作控件：空闲写"发送"，运行中写"停止"；悬停提示写"回车：发送/停止 · ⌘回车：排队 · ⇧⌘回车：插话"（提示是文本，不是第二个控件）。
- 停止不再单独出现在输入区右侧；审批卡内显示一行按键提示（Y 允许一次 · A 始终允许 · N 拒绝），`[改变]` 现役界面用隐藏键位；提问卡不设单键决定。
- 运行中排队/插话的鼠标路径是槽位右键菜单（"排队发送 / 插话发送"），菜单属于覆盖层，不占位置。
- 命令面板的清单只包含本片已有的动作：切换会话、聚焦输入、停止这次运行（条件同 T4）、读更早（条件同 T8）。不放入未接能力（UI-6），也不放"展开摘要"这类在时间线内有直接键位的动作。

## 3 焦点模型

### 3.1 焦点区与 Tab 顺序

首片五个焦点区（右栏不在本片）：

| # | 焦点区 | 内容 | Tab 停靠点 |
|---|---|---|---|
| Z1 | 左栏 | 会话列表 | 列表整体一个停靠点，↑/↓ 选行，Enter 打开 |
| Z2 | 标题行 | 会话名与可操作项 | 按可见项顺序，每项一个停靠点 |
| Z3 | 时间线 | 顶部"读更早"行、轮次与摘要行 | 整体一个停靠点（焦点组）；区内 ↑/↓/Home/End/PageUp |
| Z4 | 输入位 | 队列行（有则）→ 输入区文本 → 槽位（发送或停止，同一停靠点） | 队列表一个停靠点（↑/↓ 选行），其余每项一个停靠点 |
| Z5 | 覆盖层 | 命令面板、槽位右键菜单 | 面板内部自成顺序，Tab 循环；菜单用方向键 |

Tab 顺序：Z1 → Z2 → Z3 → Z4 → Z1；`Shift+Tab` 反向。卡占位时，Z4 的内容换成"队列行 → 卡容器 → 卡内动作"，顺序不变。

时间线的"跟随底部"是本端布尔状态：位于最新时为真；用户上滚或按 K12/K16 离开末尾时为假；按 K15、按 K16 的 End，或滚回末尾恢复为真。

### 3.2 焦点规则（15 条）

| # | 规则 |
|---|---|
| F1 | Tab 顺序固定为 Z1→Z2→Z3→Z4→Z1；任何区域内容变化不改顺序 |
| F2 | 时间线是一个焦点组：Tab 进入时落在"当前阅读行"（上次焦点行；没有则最后可见行）；↑/↓ 移动并把目标行滚入视野 |
| F3 | 输入位内顺序：队列行 → 输入文本 → 槽位；卡占位时为：队列行 → 卡容器 → 卡内动作（视觉顺序）。槽位无论显示"发送"还是"停止"都占同一个停靠点 |
| F4 | 待决卡首次出现：焦点移动到卡容器（角色为组，名称=卡标题），**不预选任何决定**；Tab 才到第一个动作。理由：预选"允许"会让 Enter 变成误批准 |
| F5 | 卡结束时（已结算、服务端取消、断线）：若焦点在卡内或当前无焦点，焦点回输入区，光标恢复到进入卡前的偏移（超出文本长度时夹到末尾）；若焦点在其他区域，不移动；输入区不可用（断线）时焦点到时间线并播报原因 |
| F6 | 卡在重连后重建：不移动焦点，只播报；若原焦点元素已不存在，按 F5 兜底 |
| F7 | 切换会话：焦点留在当前区域；该区域在新会话不存在（例如原摘要在未载入页）时，焦点到输入区；输入区不可用时到时间线 |
| F8 | 命令面板/槽位菜单：打开时焦点进搜索框或菜单首项；关闭（Esc/选中/`Cmd+K`）后回打开它的元素；元素已消失则到输入区 |
| F9 | 断线恢复：记住焦点令牌（区域 + 稳定标识：会话 id / 轮次 key / 队列 inputId / "输入区"）；重连数据稳定后恢复；目标不存在时按 F5 兜底；恢复不改变滚动位置规则 |
| F10 | 焦点移入时间线不自动滚动；键盘移动焦点时目标行滚入视野；鼠标滚动不改变焦点 |
| F11 | 新内容到达不抢焦点、不自动滚动；只有"跟随底部"为真且焦点不在时间线时才自动滚到最新；否则保持位置，用户用 K15 回到底部 |
| F12 | 除 F4/F5/F6/F8/F9 列明的情形，任何状态变化（运行、失败、未知、队列增减、连接变化）都不移动焦点 |
| F13 | 卡占位期间输入区不存在，但保留一个"意图焦点"=输入区，用于 F5/F9 回位；草稿与光标偏移一并保存，回位时按 F5 恢复 |
| F14 | 焦点环只由键盘移动触发（框架行为 `[沿用]`）；鼠标点击不显示焦点环，但焦点位置照常更新 |
| F15 | 焦点不进入不可见或不可用元素：禁用控件不可聚焦；被卡替换的输入区不在 Tab 顺序里 |

### 3.3 焦点与读屏的交接

U0 §10.3.4 记录的现役问题是：审批出现时没有显式聚焦，焦点落回页面基底（body），键盘用户失去位置。本规格用 F4/F5 取代它：卡出现即聚焦卡容器，卡结束回输入区；不存在"无主焦点"，也不把焦点交给不存在的输入区。

- 焦点进入卡容器时，读屏读到卡标题与第一段（动作/问题），不自动读长参数。
- 卡结束时焦点回输入区，读屏读"输入消息"标签，不读整段草稿。
- 重连恢复焦点后播报一次"已重新连接"（不播报焦点细节）。

## 4 提交与排队

### 4.1 发送槽：一个位置一件事

输入位右侧只有**一个**动作槽（`[改变]` 本次修正：此前"发送 + 停止 + 插话发送"三控件并排，违反 UI-1 与"一个位置一件事"）。

| 会话状态 | 槽位 | 可用 | 触发 |
|---|---|---|---|
| 未运行 | 发送 | 有草稿、在线、档位有值 | 点击/Enter 提交 |
| 未运行、空 | 发送 | 否（上沿一行原因） | — |
| 未运行、提交在途 | 发送 | 否（上沿"发送中"） | — |
| 未运行、结果不确定 / 需人工确认 | 发送 | 否（上沿对应说明） | — |
| 运行中 | 停止 | 是 | 点击/Enter 停止 |
| 运行中、停止在途 | 停止 | 否（上沿"正在停止"） | — |
| 运行中、停止未知 | 停止 | 否（上沿"停止结果不确定"） | — |
| 运行中、停止能力缺失 | 不显示 | — | 原位置一行"这个版本不能停止" |
| 断线 | 按运行事实取"发送"或"停止" | 否（上沿断线原因） | — |
| 卡占位（审批/提问） | 不显示 | — | 输入位被卡替换 |

约束：

- **同一位置、同一尺寸**：只有"发送"与"停止"两种文案，不因状态变长、换位或改变尺寸；状态说明写在输入位上沿既有的一行（U1 H1/H2/H3/S24），不塞进槽位。具体尺寸归 U2。
- **不并列**：不出现第二个停止/发送控件，也不出现"插话发送"这类并排次要按钮。
- **排队与插话走键位**：`Cmd+Enter` / `Cmd+Shift+Enter`；鼠标路径是槽位右键菜单（运行中且有草稿时提供"排队发送 / 插话发送"），菜单是覆盖层，不占位置。
- **槽位只表达动作**：可用性由状态与能力决定；运行中永远显示"停止"，不因草稿有无而变成发送。
- **停止不可绕过**：运行中按 Enter 与点槽位等价；不做二次确认（Q11 记录该取舍）。

### 4.2 提交到受理之间的锁定与反馈

| 阶段 | 界面位置 | 内容 | 槽位 | 解锁 |
|---|---|---|---|---|
| 已登记 / 在途（未运行） | 时间线尾部的"发送中"行 | 原文可读、可选中复制；不参与事实排序 | "发送"禁用 | 回执 / 错误 / 超时 |
| 已登记 / 在途（运行中，排队/插话） | 队列位的"发送中"行 | 同上 | "停止"可用（提交在队列，不影响停止） | 回执 / 错误 / 超时 |
| 成功 | 占位被事实替换 | 用户消息行（未运行）或队列行（运行中） | 按运行事实 | — |
| 明确失败 | 见下方回填规则 | 原文保留 | 恢复可发送 | 用户重发 |
| 未知 | 原占位保持 | 原文 + "结果不确定 · 正在核对" | "发送"禁用 | 核对结论 |
| 需人工确认 | 原占位保持 | 原文 + "需要人工确认" + 说明（不发重试） | "发送"禁用 | 人工核对，不自动 |
| 未发生 | 原占位消失 | 原文回填输入区 | 恢复可发送 | 用户重发 |

**失败回填规则**（与 U1 W1 的接口，见 Q7）：

1. 输入区为空：原文自动回填输入区，光标在末尾，"发送中"占位消失；原因显示在输入区上沿一行。
2. 输入区已有新草稿（用户已开始写下一句）：不覆盖新草稿；"发送中"占位转为失败行留在原位（可选中复制），行内给原因与"放回输入框"；点"放回输入框"把原文追加到当前草稿末尾（另起一行），并把焦点移到接缝处。
3. 两种情况都不产生第二条用户消息行。

## 5 审批与提问

### 5.1 出现与消失

| 事件 | 输入位 | 焦点 | 队列 | 草稿 | 播报 |
|---|---|---|---|---|---|
| 卡首次出现（队首） | 被卡替换，槽位不显示 | F4：卡容器 | 保留、可撤回 | 保存 | 前景且当前会话时播报标题 |
| 卡变成只读（已答未结算） | 不变 | 留在原元素；若原动作已禁用则到卡容器 | 保留 | 保存 | 不播报 |
| 卡结算 | 回输入区，槽位按运行事实恢复 | F5 | 保留 | 恢复 | 不播报 |
| 服务端取消 | 回输入区，槽位恢复 | F5 | 保留 | 恢复 | 播报"这条不需要你了"（前台） |
| 断线 | 回输入区（禁用），槽位按断线状态 | F5 兜底到时间线 | 保留、禁用撤回 | 保存 | 播报断线 |
| 重连重建 | 再次被卡替换，槽位不显示 | F6：不抢焦点 | 保留 | 保存 | 播报"有一条需要你处理" |

卡出现时若输入区正在组词：先按平台提交当前组词（内容进草稿），再替换输入位；不得丢弃已输入内容。

### 5.2 三个决定的差异

| 决定 | 出现条件 | 写入序列 | 卡上状态 | 失败处理 |
|---|---|---|---|---|
| 允许一次 | 总是 | `approval.respond {decision:"allow"}` 一条意图 | "已允许，等待结算" | 明确失败→卡回可答；未知/需人工确认→按已答、不重发 |
| 始终允许 | 仅当 `LongTermAvailable`（服务端声明的可长期允许 + 可写规则参数；本片只覆盖 `exec`/`execute` 的简单命令） | 先读规则集 `permission.rules`，带 revision 整集写回一条 `{command, match:"exact", decision:"allow"}`，成功后再 `approval.respond {decision:"allow"}` | 规则写入中："正在写入规则…"；成功后"已允许，等待结算" | 规则失败→**不发同意**，卡回可答，说明"规则没有写成功，这次操作还没有被同意"；同意失败但规则已写→只重试同意，不重写规则、不改口 |
| 拒绝 | 总是 | `approval.respond {decision:"deny"}` | "已拒绝，等待结算" | 同"允许一次" |

补充：

- 三个决定是同一件事的互斥选项，不是三个并存动作；同一时刻只有一个决定被选中/提交（U2 用既有视觉态表达）。
- 服务端没有 `approval.allow_always`；"始终允许"是客户端把两条真实能力串起来的结果（D5 §4.6），卡上不得暗示它是一次请求。
- 三个决定都只对队首有效；非队首不渲染，也不提前应答。
- 允许/拒绝语义以服务端 `approval.respond` 的 `allow`/`deny` 为准（D5 §4.5）。

### 5.3 始终允许的作用域提示

卡上必须写清三件事，且与将要写入的内容一致：

1. **写的是什么**：`<命令原文>`（规则内容）；拿不到命令原文时不提供"始终允许"（UI-6 隐藏，不给看不清作用域的按钮）。
2. **匹配方式**：精确匹配（`exact`）为默认；前缀匹配只能在设置 · 命令规则里由用户显式选择，客户端不因一次审批自动升级（D5 §4.13）。
3. **作用范围**：这是用户级命令规则，对你所有会话生效；修改或撤销在 设置 · 命令规则。

措辞要求：不用"永远允许"这类无范围的话；说明这是客户端按规则 API 语义给出的解释，服务端审批请求本身不带作用域字段（D5 §7 第 27 条）。

`[依赖]` 当前交互裁决的条目视图只给"工具名 + 原因"，不含命令原文与规则预览（`docs/domains/D5-interaction.md` §3 的 `Item`）。在补齐之前按第 1 条降级：不显示"始终允许"。见 Q1。

### 5.4 应答后的焦点与滚动

- 应答受理后：焦点留在卡内原位置（动作变为只读状态），不立即跳走；卡消失时才按 F5 回输入区。
- 卡消失后滚动：不滚动。时间线保持在应答前的位置；若该操作行不在视野内，不自动跳转（避免失去上下文）。
- 用户想看这次决定的结果：时间线中该操作行由事实更新（允许/拒绝），展开可见原因；不做 toast。
- 断线导致的卡消失：不滚动；焦点按 F5。

### 5.5 提问卡

| # | 规则 |
|---|---|
| QA1 | 一个批次一条卡；批次内多个问题按清单顺序全部展示，卡体在自身范围内滚动；不做"下一步"分步向导 `[改变]` |
| QA2 | 每个问题展示正文；有候选项时按单选/多选语义列出（多选由事实 `multiSelect` 决定） |
| QA3 | 选择候选项把其文本填入该问题的回答框，用户可改；不隐藏格式、不自行拼接未展示的内容 |
| QA4 | 整个批次只提交一次：回答内容按用户看到的文本提交（D5 要求合法 JSON，按字符串提交）；多问题时用单个回答框，提示"请按顺序回答以上问题" |
| QA5 | "跳过"=取消（`cancel`），不代表拒绝；本片不提供提问的"拒绝"动作（Q5） |
| QA6 | 不显示倒计时、不显示截止时间、不因"等太久"自动跳过（无事实） |
| QA7 | 回答被受理后不可改答；卡显示"已回答，等待结算"；结算前不消失 |
| QA8 | 清单来源为历史推导时，卡内标注"按历史推得，可能不全" |
| QA9 | 解析不出问题时显示一行原因，不提供作答；不伪造空选项 |

`[依赖]` 提问应答的 JSON 形状（字符串 vs 结构化）没有在真实 `ask_user` 上验证（D5 §6.6 标 blocked）；本片按自由文本提交，真实消费方按工具结果为准（Q2）。

### 5.6 一次一条与到达顺序

- 每会话一条待决队列，按到达顺序（审批与提问共队），界面只渲染队首；不按类型提权 `[改变]`（现役界面审批优先于提问）。这回答了 U1 `docs/domains/U1-ia.md` §9 第 5 项。
- 已答未结算的项仍占队首：卡保持只读，直到结算才让位下一条；下一条出现时焦点按 F4 只在新卡是"首次出现"时移动。
- 跨会话：非当前会话的待决只在左栏行标记（U1 A4）；切过去才显示卡。

## 6 错误与未知

### 6.1 分类、呈现与可行动作

| 情形 | 判定来源 | 呈现（输入位/时间线/行内） | 可行动作 | 不给的动作 |
|---|---|---|---|---|
| 明确失败（未发出） | `connection_missing` | 输入区上沿一行："没有发出去 · <包装原因>"，可展开细节 | 服务恢复后用槽位"发送"重发（内容已回填，新幂等键） | 自动重试、第二个"重新发送"按钮 |
| 明确失败（参数/能力） | `non_retryable`（`unknown_method`、参数错误） | 一行"这个版本不支持/参数不对" + 细节 | 复制细节 | 重发、禁用项冒充可用 |
| 未发生 | 核对 `unknown` | 原文回输入区，一行"没有发出去，可以再发一次" | 槽位"发送"重发 | 显示"已发送" |
| 结果不确定 | `timeout`、`retryable`、断线 | 原占位 + "结果不确定 · 正在核对" | 等待核对；人工核对时提供"复制内容/详情" | 重发、改口为成功 |
| 需人工确认 | 核对上限 | 原占位 + "需要人工确认" + 一句"在时间线里核对是否已经发出" | 复制；明确告知不自动重发 | 重发按钮 |
| 断线 | `OnResync`/连接状态 | 左栏底部一行 + 输入区上沿一行原因；时间线底部一行 | 等待自动重连（无需按钮） | 本地"离线继续发送" |
| 版本不兼容 | `version_incompatible` | 启动态整屏（P3），不进主界面 | 按启动态说明 | 主界面内重试 |
| 服务缺失 | `connection_missing`（启动时） | 启动态整屏 | 启动态说明 | 主界面骨架 |
| 权限拒绝：用户拒绝审批 | 审批结果 | 该操作行"已拒绝"，展开可看原因 | 无（协议无重新发起审批的方法） | "重新批准" |
| 权限拒绝：规则拒绝 | 工具结果错误，`reason` 可能带规则命令与 match | 操作行"被规则拒绝"+展开原因 | 无（改规则在设置，后续批次） | "一键放行" |
| 权限拒绝：档位不足 | 工具结果错误 | 操作行"权限不够"+原因 | 无（档位切换入口不在本片，Q8） | "提高权限"顺手按钮 |
| 档位未读到 | `ErrPermissionUnset` | 输入区禁用 + 一行"还没读到这次会话的权限档位" | "重试读取"（读重试） | 猜一个默认档位 |
| 能力缺失 | `session.methods` 缺项 | 入口不出现（UI-6），设置里另列（后续批次） | 无 | 禁用按钮 + "即将支持" |

### 6.2 呈现规则

- 包装（P5）：结论 + 影响 + 可展开细节；不把裸错误码丢给用户；不出现内部术语（UI-3）。
- 位置（U1）：提交类在输入区上沿一行；操作类在该操作行；断线在左栏底部与时间线底部；启动类在启动态。
- 同一错误只出现在一个位置（U1 §2.5"错误"主表达为操作行/该轮），不做 toast 通道。
- 未知与失败必须可区分：未知不能写成"失败"，失败不能写成"没发"。

### 6.3 不虚构清单

不提供：重新生成回答、重试工具调用、撤销/编辑已发消息、重新发起同一条审批、客户端取消审批、队列重排、提问倒计时、审批的"提高权限"捷径、离线发送、自动重连按钮、"再停止一次"（停止未知时，Q4）。

### 7.2 读屏语义（按现有框架能力）

| 对象 | 角色与名称 | 状态 | 说明 |
|---|---|---|---|
| 左栏列表 | 列表（list/listbox），行=选项，名称=会话名 | 选中 | 框架报"第 n 项，共 m 项" |
| 时间线 | 列表；每轮为组，名称"第 N 轮" | — | 行位置由框架报 |
| 过程摘要行 | 可展开按钮，名称=摘要文本（操作数/文件数/耗时） | Expanded | 展开后子项为列表 |
| 输入区 | 多行文本框，名称"输入消息" | 值=草稿 | 组词由框架处理 |
| 槽位 | 按钮，名称"发送"或"停止" | Disabled、描述=原因或快捷键 | 同一控件随运行态改名；不另设停止按钮 |
| 队列表 | 列表，名称"等待发送"；行=选项，名称=内容首行 | 位置；已应用 | 行内动作"撤回"为按钮 |
| 审批卡 | 组，名称"待你同意：<动作>" | — | 动作=按钮；提交中 Busy；错误=Invalid+描述 |
| 提问卡 | 组，名称"它的问题"；每问=文本；选项=单选/复选组 | Checked；组名=问题 | 回答框=文本框 |
| 排队中/已应用/已停止 | 作为对应元素的状态与描述，不做独立播报元素 | — | P1：状态不新开容器 |

**播报（`c.Announce`，仅当前会话且窗口前台）**：审批到达、提问到达、提交失败、结果不确定、需人工确认、断线、重连完成、停止生效、翻页失败、规则写入失败。流式文本不播报（避免刷屏）。

### 7.3 现有能力的边界

- 虚拟列表的屏读需要滚动触发行构建（U0 §8.4），与平台有关；本片不承诺"未滚动也能读到全部行"。
- 自绘元素（摘要行、状态位）默认对辅助技术不存在，必须显式给名称与状态；实现归 U5，验收归 E。
- 未在真实屏读器上验证：相关验收标 blocked，直到 E 阶段实机走查（不虚构通过）。
