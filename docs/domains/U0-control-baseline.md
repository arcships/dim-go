# U0 控件基线（与官方控件并排对照）

Status: 现行（v2 取值层，2026-11-13）
Owner: U4 技术设计（界面领域）／U2 视觉
依据: `docs/project-organization.md` §9.0（A4 只管窗口装饰与系统集成）、§9.14 第 3 层「视觉校准与排版基线」、UI-24（视觉以并排对照为准）；mygo v0.8.3 的 `ui/*.go` 与 `ui/markdown/*`；`docs/domains/U2-visual.md`
范围: 官方控件的实测几何、我们与它的逐项对照、风格板、迁移清单。
不做: 定形式（在 U2 形式库）、定交互（在 U3）、改公理与判定。

**先记一句话**：官方示例是**功能型示例**——它证明"这些控件能这么组合"，不证明"这就是好看"。
界面之所以还薄，不是控件尺寸的错，是**组合层**（标题层级、分组方式、面层、留白节奏、
输入区体量）没做。控件再对齐也换不来"精致"：精致只能来自组合层的自觉取舍。
以后不得再用"控件尺寸已对齐"冒充设计完成（UI-24）。

**取证方式**：`internal/ui/baseline_test.go` 渲染官方控件对照表（`controls-1x/2x.png`）；
`scripts/compare-screens.py` 把**官方示例的真实切片**（`docs/domains/calibration/examples/`）
与我们同尺寸的切片并排。每张并排图的左上角写着两边的来源文件与裁剪坐标。

```bash
go test ./internal/ui -run 'TestBaseline' -v      # 出对照图 + 打印几何
python3 scripts/compare-screens.py                # 三屏并排（左官方 / 右我们）
```

## 2 逐项并排对照（基线值 vs 我们的值）

**我们的旧值 → 新值**：`v1` 把字号固定成 14（比平台默认大 1 档），所有控件
因此比官方高 1.2–2 px。v2 的取值层第一件事就是**不覆盖 `Theme.FontSize`**，
让字阶按 `t.FontSize / 14` 跟随平台默认（macOS 13、其它 14）。

| 项 | 基线值（官方） | 我们的值（v2） | 差异 | 处置 |
|---|---|---|---|---|
| 正文字号 / 行盒 | 13 / 15.31 | 13 / 15.31（`typeControl`，不设行高） | 0 | **沿用**：控件里的文字不设行高，交给框架字形度量 |
| 正文（阅读段落）行高 | 1.5 倍（`markdown.Theme.LineHeight`） | 1.5 倍（`typeBody` line 21/14） | 0 | **沿用**：与官方 markdown 同一倍率 |
| 次要字级 | —（官方只有一档 13） | 11.4（12.25 × 13/14） | −1.6 | **偏离**：层级需要三档；侧栏与说明文字用它，行高随之更密（见「侧栏行高」） |
| 按钮内边距 | 6 / 14 | 6 / 14（`controlPadV/H`） | 0 | **沿旧正**：v1 的 4/12 改为框架值 |
| 文字按钮高度 | 29.31（Button） / 27.31（Primary） | 30.00 / 28.00 | +0.7 | **沿用**：差 0.7 来自我们自绘按钮的 1px 描边与文字度量；不再追这 0.7 |
| Select / 输入框高度 | 29.31 | 29.31 | 0 | **沿旧正**（此前 30.49，因为覆盖了 FontSize） |
| Switch | 36×20 | 36×20 | 0 | **沿用** |
| 侧栏行高 | 23.31 | 22.13 | −1.2 | **偏离**：行内标签用次要字级；侧栏要更密的列表，选中靠面差 + 字重（U1 A1–A4） |
| 侧栏行内边距 | 6 / 8 | 6 / 8 | 0 | **沿用** |
| 列表行结构与选中态 | 行高 = 内容 + 12；选中 `SurfacePressed` | 同 | 0 | **沿用**（框架 Sidebar/SidebarItem 直接用） |
| 输入卡内边距 | 8（`Space(2)`） | 8 | 0 | **沿用**（卡内边距 `space2`，与官方输入框的横向内边距同档） |
| 输入卡圆角 | 6（`Theme.Radius`） | 6 | 0 | **沿用** |
| 弹层内边距 | `Space(1.5)` / `Space(2)`（菜单项） | 同（框架弹层，不自绘） | 0 | **沿用** |
| 图标与文字间距 | `Space(1.5)=6`（Button 的 Gap） | 4（`space1`）/ 8（`space2`） | −2 / +2 | **偏离**：图标 + 文字的行用 4（更紧），行内分段用 8；理由见 `U2-visual §4.7` |
| 面层数 | `Background` / `Surface` / `SurfaceHover` / `SurfacePressed` 四层 | 同四层（不自造第五层） | 0 | **沿用**（UI-18：边界只用面差与主题 Border） |
| 面层色值 | 亮 `#ffffff` / `#f4f4f5` / `#e9e9ec` / `#e3e3e6`；暗 `#18181b` / `#27272a` / `#323236` / `#3a3a3f` | 同 | 0 | **沿用**（`U2-visual §8` 的 token 表本来就是这套值） |
| 圆角档 | 6（控件）/ 6（卡片） | 6 / 6；代码块 8 | 0 / +2 | **沿用 + 偏离一处**：代码块用 8（等宽字与 6 圆角视觉上偏硬，`radiusCode`） |
| 图标尺寸 | 16（框架 `Space(4)` 的图标盒） | 16（`iconInline`）/ 20（`iconBlock`） | 0 | **沿用** |
| 控件高度档 | 无（各控件按内容算） | 24（`rowCompact`）/ 28（`rowRegular`） | — | **偏离**：命中区下限 24 是 UI-22 的契约，不是视觉风格；保留 |

对照结论（细节在 §3.1）：字号、按钮高度、面层与示例一致；**组合层的三处差距**
是标题层级偏弱、分组靠留白没有"卡片/行"的边界、输入区体量与位置与示例不同——
后两项是首片有意的取舍（见 §3.1 的处置列）。

### 3.1 组合层对照（官方示例 vs 我们）

`[改变]` = 本轮改了；`[沿用]` = 与示例做法一致；`[偏离]` = 有意不跟，附理由。

| # | 组合手法 | 示例做法（指到区域） | 我们的做法 | 差异 | 处置 |
|---|---|---|---|---|---|
| C1 | 页面标题层级 | `gallery-overview.png (234,50)–(420,130)`：页面标题 24/700 + 一句 13 muted 说明；`notes.png (258,88)–(430,116)`：文档标题 24/700；`permissionflow.png (12,18)–(510,80)`：标题 20/700 + 两行 13 说明 | 标题行会话名 15/600（48 高的窗口标题行）；设置屏分节标题 16.1/600 | 示例的页面标题比我们大 4–9 px，且都配一句辅助说明 | `[改变]` 标题行会话名 14→**15/600**（标题行只有 48 高，24 放不下）；设置分节标题保持不变（16.1）。**`[偏离]` 不配"辅助说明"**：标题行是窗口标题栏，说明会挤掉可拖区（UI-19） |
| C2 | 分组靠什么分开 | `permissionflow.png (8,80)–(512,300)`：每条权限一张**卡片行**（白底 + 1px border + 圆角 8 + 间距 12）；`gallery-overview.png (230,140)–(730,500)`：每个主题一张**卡片**（border + 圆角 8 + 内边距 16） | 轮次之间只有留白 24；审批卡与输入卡是唯一有边界的块 | 示例用"卡片边界"分组，我们用"留白"分组 | `[偏离]`：对话流是连续阅读，卡片化会把每一轮切成"独立文档"、打断滚动阅读；边界留给"需要硬分开"的两处（审批卡、附件 chip，L11 白名单）。**这条是本轮最需要用户确认的取舍** |
| C3 | 标题/正文/辅助四级 | `notes.png`：列表标题 15/600、文档标题 24/700、正文 14、状态行 12 muted；`markdown-chat.png (14,230)–(800,260)`：H2 18/700 | 标题 15、正文 13、次要 11.4、微 10.5（四级齐全） | 示例正文 14、我们 13（跟框架平台默认）；层级比例接近 | `[沿用]` 四级结构；字号跟平台默认（§2 第 1 行），不再自行放大 |
| C4 | 面层与边界 | `gallery-overview.png`：页面 `background` → 导航 `surface` → 卡片 `background` + `border`；`markdown-chat.png (14,236)–(800,320)`：代码块 `surface` 无边界 | 页面 `background` → 左栏 `surface` → 输入卡 `surface` 无边界；审批卡 `surface` + `border` | 示例"卡片 = 浅底 + 边界"，我们"卡片 = 浅底无边界" | `[偏离]`：UI-18 定了"边界只有一套、能靠面差就不画线"，输入卡与代码块都用面差；示例里卡片是白底（比页面亮），我们反过来用浅底（比页面暗），这是深浅主题下更稳的一层 |
| C5 | 输入区体量与位置 | `markdown-chat.png (14,676)–(800,714)`：一行输入框（border + 圆角 6）+ 右侧 Send 主按钮，同高 | 输入卡 124 高：附件 chip + 多行输入 + 右下附件/发送 + 右上用量；上方还有目标行与队列条 | 示例 1 行 38 高；我们 124 + 上沿两行 | `[偏离]`：多行 + 用量 + 附件是 U1 R4 的契约（F10/F17/E2）。**但可以借示例一处**：`[改变]` 输入卡内边距保持 8（与内容列一致，L8），不再加大——加大会破坏 272.5 的左缘 |
| C6 | 行内元素的呼吸 | `permissionflow.png (30,90)–(390,130)`：标题 14/600 与状态词 13 间距 2；按钮组间距 8；`gallery-overview.png (10,80)–(200,110)`：导航行高约 26–28，图标 16 与文字间距 8 | 侧栏行高 22.1（偏密）；组头内图标与文字间距 4；记录行间距 8 | 示例行高 26–28，我们 22 | `[改变]` 侧栏会话行最小高度 → **28**（`rowRegular`，对齐 gallery 导航行）；组头间距保持 4（它比导航更密，是"行内提示"不是"导航项"） |

## 5 迁移清单

**改了哪些值（v2 取值层）**

| 变更 | 旧 | 新 | 依据 |
|---|---|---|---|
| `Theme.FontSize` | 固定 14 | 不覆盖，跟平台默认（macOS 13 / 其它 14） | `ui/theme.go:159`；`compare-*` 图 |
| 字级缩放基准 | `t.FontSize / 14`（同上，语义改为"相对平台默认"） | 同公式，含义改为"平台默认 × 比例" | 同上 |
| 控件文字字级 | `typeBody`（line 21） | 新增 `typeControl`（不设行高） | `Button/Select` 的 15.31 行盒 |
| 文字按钮内边距 | `space1 / space3`（4 / 12） | `controlPadV / controlPadH`（6 / 14） | `ui/widgets.go` `styleButton` |
| 设置项标签 / 导航字级 | `typeBody` / `typeBodyStrong` | `typeControl` / `typeControlStrong` | 同上 |
| 标题行会话名字号 | 14 / 600 | **15 / 600** | 组合层 C1（`gallery-overview`/`notes`/`permissionflow` 的标题档） |
| 侧栏会话行最小高度 | 22.1（框架按字号算） | **28**（`rowRegular`） | 组合层 C6（`gallery-overview` 导航行 26–28） |

**影响哪些屏**：主界面五态（侧栏行变高、标题行会话名变大）、分支/目标/后台任务、设置三节——文字小 1 档
（约 7%），控件高度 −1.2 px 左右。列宽、区域尺寸、左缘基线不变。

**影响哪些检查项**：L8（三档左缘）阈值不变（仍是 ±1.5，实测仍 272.5）；
L14（五态取色）阈值不变；L15（200% 不越界）复跑通过；L13（命中区 ≥24）不变。
截图全部重出（`state-*`、`variant-*`、`window-*`）。
