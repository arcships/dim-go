## 1 方案 A：过程收成一行

**解 T2。** 线框：[wireframes/a.html](wireframes/a.html)

### 1.1 结构描述

基线不变；一轮里的全部操作与中途说明收成一行**过程摘要行**，只有最终回复铺开；这一行自己承担运行中、等待同意、失败三种形态，并且**必须可展开**：展开后按发生顺序逐条列出每一次操作。

摘要行不是标题，是一句具体的事实：`做了什么：运行了 4 个操作 · 改了 2 个文件 · 12s`。展开后每条形如 `3 · 执行 · go test ./... · 失败 · 2.1s`，失败条目下面加一行原因。展开状态按会话记住。

### 1.2 偏离台账（2 处）

| # | 常规做法 | 改成什么 | 代价 |
|---|---|---|---|
| A-1 | 每个操作一行摘要（读一行、改一行、跑一行），基线如此 | 一轮的全部操作收成一行过程摘要：「做了什么：运行了 4 个操作 · 改了 2 个文件 · 12s」；点「展开 ⌄」按顺序逐条列出（序号、动作、对象、结果、耗时，失败带原因） | 折叠时看不到每一步；一行能放的数字有限，超过 5 个操作要合并计数 |
| A-2 | 运行中 / 出错由各自的操作行或提示承载 | 同一行换形态：`●` 进行中并写"正在运行 1 个操作"、`◷` 等待同意、`✕` 失败并写"1 个失败"；不新增提示区 | 一行要同时说清"做了什么"和"卡在哪"，文字要短 |

### 1.3 三行说明（按状态）

| 状态 | 主次排序 | 重复单元 | 面积分配理由 |
|---|---|---|---|
| 默认态（摘要折叠） | ① 最近一轮 ② 输入区 ③ 摘要行 | 一轮 = 用户消息 + 助手消息 + 过程摘要行 | 时间线 728 / 输入 124 / 标题 48；内容 784 居中，左栏 20% |
| 摘要展开 | ① 展开后的条目列表 ② 那一轮的回复 ③ 输入区 | 一条操作一行：序号 · 动作 · 对象 · 结果 · 耗时；失败下加 18px 原因行 | 展开占 4 行（约 91px）从时间线借，不改变宽度 |
| 动效关闭 | 与折叠态一致 | 与折叠态一致 | 与折叠态一致；只去掉逐字出现与转场 |
| 运行中 | ① 正在写的那段回复 ② 摘要行的 `▍` 与"正在运行 1 个操作" ③ 队列条 | 同上；运行态不加行，只给摘要行换标记与文字 | 队列条 33 从时间线借 |
| 等待你同意 | ① 审批卡 ② 摘要行的 `◷` 与"等待你同意" ③ 其余历史 | 审批卡三段：要做什么 / 影响 / 决定 | 输入区整块换成审批卡（110→150），时间线 728→702 |
| 出错/不确定 | ① 摘要行的 `✕` 与"1 个失败" ② 消息下的结果说明 ③ 其余历史 | 同一套标记：✕、次要灰度、一行说明；展开后失败条目给原因 | 不加新区域 |
| 长历史 | ① 当前轮 ② 上一页 ③ 输入区 | 一行一轮 | 上一页 28px，按需 |

### 1.4 信息层级

一眼：最近一轮的回复与过程摘要行；等待同意时是审批卡。第二眼：轮次结构、队列条。按需：摘要行展开后的每次操作、右栏（文件/改动/后台/目标）。

### 1.5 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 发送 | 按发送 → 输入区清空、轮尾出现用户消息与回复流式 → 回执后行固定（`session.submit`） |
| 打断 | 审批到达 → 输入区整块换成审批卡，同时那一行写"等待你同意" → 决定后卡消失、输入区回来（`approval.respond`；一直允许先写规则 `permission.set_rules`） |
| 会话切换 | 点左栏会话 → 主区整块重建，不闪空 |
| 展开/收起 | 点「展开 ⌄」或按 → → 摘要行下方按发生顺序列出条目（1、2、3……），同一行变「收起 ⌃」；展开状态按会话记住 → 再点收起 |
| 出错与不确定 | 操作失败 → 摘要行 ✕ + "1 个失败"，展开后失败条目下写"原因：权限不足，命令没有执行"；提交超时 → 消息下加一行"结果不确定…正在核对"，不出现重试按钮 |

### 1.6 附属对象落点（对应对象模型 §3）

| 对象 | 落点 |
|---|---|
| 目标 O9 | 标题行「目标」按钮，展开看全文与设定轮次 |
| 改动 O12 | 那一行末尾计数，明细在右栏「改动」 |
| 后台运行 O13 | 那一行标记，明细在右栏「后台」 |
| 文件 | 展开后的操作行写文件名；完整内容在右栏「文件」 |
| 账号 O11 | 左栏底部 |

### 1.7 状态如何附着

| 状态 | 元素 | 属性 | 不做什么 |
|---|---|---|---|
| 运行中 | 助手消息 + 摘要行 + 发送键 | 末尾光标；摘要行 `●` + "正在运行 1 个操作"；键文字变「停止」 | 不加运行胶囊 |
| 排队中 | 队列条 | 出现 / 消失，33px | 不加徽标 |
| 等待同意 | 输入区整块 | 内容换成审批卡（110→150） | 不与输入并存；不用模态 |
| 工具失败 | 摘要行 | 行首 `✕`、"1 个失败"、文字转 #999；展开后失败条目给原因 | 不弹窗、不加提示条、不造重试 |
| 结果不确定 | 消息下说明行 | 多一行 22.75 | 不标记成功 |
| 断线 | 输入区 + 时间线底部 | 输入区不可用；底部一行断点 | 不另立连接指示 |
| 长历史 | 顶部「上一页」 | 出现 / 消失 | 不改滚动位置 |
| 摘要展开 | 摘要行本身 | 变「收起 ⌃」；下方追加条目列表 | 不改变条目顺序（UI-4） |
| 动效关闭 | 全部转场与逐字 | 变为瞬时；无光标闪烁、无弹簧 | 布局与状态不变（UI-5） |

### 1.8 可见性取舍

首屏：时间线、输入区、标题行；等待同意时审批卡。按需：那一行展开、右栏、队列条、上一页。不出现：状态条、活动条、任务中心、重试入口。

### 1.9 放弃什么

- 放弃"过程顺次可见"：要看每一步必须展开。
- 放弃中途说明的默认呈现：它被并进那一行，只能展开看。
- 放弃一行的表达力上限之外的信息：一行只放"动词 + 数量"。

## 2 方案 B：轮次索引

**解 T6。** 线框：[wireframes/b.html](wireframes/b.html)

### 2.1 结构描述

基线不变；时间线左缘加一条轮次索引，每一针是一轮，悬停显示该轮第一句，点击跳过去；只在超过 5 轮时出现，占 22px。

### 2.3 三行说明（按状态）

| 状态 | 主次排序 | 重复单元 | 面积分配理由 |
|---|---|---|---|
| 默认态 | ① 最近一轮 ② 输入区 ③ 索引条 | 一轮 = 用户消息 + 助手消息 + 每个操作一行 | 索引 22 / 内容 784 / 输入 124；索引只在长会话出现 |
| 运行中 | ① 正在跑的操作行 ② 正在写的回复 ③ 队列 | 操作行：动词 + 目标 + 结果词 | 索引条不随运行变化 |

### 2.4 信息层级

一眼：最近一轮。第二眼：操作行结果词、索引针位置。按需：右栏、展开细节。

|---|---|
| P1 | 状态落在操作行、消息、输入区；索引针不承载状态 |
| P2 | 审批在输入位内联 |
| P3 | 主=时间线；附属=标题行；子=索引、展开、右栏 |
| P4 | 索引可用键盘上下跳；鼠标点击同样可达 |
| P5 | 失败给结论，细节展开 |
| P6 | 索引只表示位置，不暗示状态 |
| P7 | 索引只在长会话出现 |
| P8 | 索引来自已有轮次，不生成任何新信息 |

### 2.12 元素来源

同 A 的表，另加：轮次索引 ← R 块 2（`session.history` 已加载轮次序列，本地计算位置）。

**缺口：0。**

### 2.13 可实现性

mygo 已有：`List`+`ListState`（行身份与位置）、`Scroll`、`Attach`。需自建：针与轮次的映射（虚拟列表下按已加载轮次算比例）、点击跳转的锚定。

## 3 横向比较

### 3.1 一句话区别

| 方案 | 解哪个张力 | 一句话 | 偏离 |
|---|---|---|---|
| A 过程摘要行 | T2 | 一轮只看一行具体摘要，点开才逐条 | 2 |
| B 轮次索引 | T6 | 长会话左缘一排针，直接跳到某一轮 | 1 |

### 3.2 同场景差异

| 场景 | A | B |
|---|---|---|
| 默认态 | 一轮三行（你 / 它 / 过程摘要行） | 一轮多行（你 / 它 / 每个操作一行）+ 索引 |
| 运行中 | 摘要行 `●` + "正在运行 1 个操作" | 操作行写"进行中" |
| 等待同意 | 同一张审批卡 | 同一张审批卡 |
| 出错 | 摘要行带 ✕ 与"1 个失败" | 失败的操作行带 ✕ |
| 长历史 | 上一页 | 上一页 + 索引针 |

### 3.3 比例处理

| 方案 | 比例上做了什么 | 代价 |
|---|---|---|
| A | 不改横向，只改时间线内的行数（折叠时一轮 3 行；展开时 +4 行/条） | 折叠时过程不可见 |
| B | 时间线左缘 22px 给索引；内容仍 784 居中 | 内容实际宽度 −22px |

### 3.4 淘汰线自检

| 淘汰线 | A | B |
|---|---|---|
| 虚构动作/状态 | 无 | 无 |
| 新增状态容器 | 无 | 无（索引是导航，不承载状态） |
| 模态承载非阻塞事务 | 无 | 无 |
| 以"常见做法"论证 | 无 | 无 |
| 首屏铺开全部 | 无 | 无 |
| 界面自攒事实/乐观更新 | 无 | 无 |
| 偏离 >2 处 | 2 | 1 |
| 违反 §9.9 | 无 | 无 |

### 3.5 共同未决

见 §0.6。另：A 的"一行里同时表达做了什么与卡在哪"需要在 C1 定出字数上限；B 的索引在虚拟列表下的位置稳定性需在 C4 验证。
