### 0.2 张力清单（都来自 A1，不是设想）

张力 = 两个都想要的好处互相挤压。每条给证据与"选它要付什么"。

| # | 张力 | 相争的两端 | 证据 | 选它做第一张力要付的代价 |
|---|---|---|---|---|
| T1 | 打断的抢占 vs 输入的连续 | 审批/提问必须与历史同视线、答完即继续；但抢占输入位时用户没法准备下一条 | U0 §4.1（审批与输入区在同一绑定上互斥）、§4.1 代价段、§7.2（终端同样替换输入框）、H3 | 打断面要让位/占位，主区可用高度被切走；"边看历史边答"与"边写边答"仍难两全 |

### 0.4 怎么比

同一组四个场景：默认态、运行中、审批待答、长历史。三方案用同一段会话内容，差异只应出现在"结构"上。画法统一：默认态给完整框；运行中、审批待答、长历史只给"变化所在一段"的纵向切片，三方案切片位置相同，便于逐行横向对照。每个方案自报：解决哪个张力、为什么它优先、放弃了什么、指不到来源的元素有哪些（应为 0）。

## 1 方案一：打断即主干

**第一张力：T1（打断的抢占 vs 输入的连续）。**

选它的理由：首批闭环的定义就是"看历史 + 提交 + 处理审批"（`docs/project-organization.md` §9.3），三件事里唯一会互相打断的就是审批/提问；而它是唯一"不处理就完全走不下去"的处境（B1 S2）。T1 的损失最不可逆：被抢占的输入要用户重新组织，而重新组织没有服务端事实可以恢复。

### 1.1 一句话概念

把"必须回答的事"抬成主区里独立的一层主干，输入位不再被它替换——旧界面靠互斥换来的"同一视线"，用上下相邻的两层同样拿到，同时保住正在写的输入。

### 1.2 画面骨架

默认态（空闲，有 3 轮历史）：

```text
┌──────────────────────────────────────────────────────────────┐
│ 索引        │ 项目 A · 修发送路径 · 分支 main · 权限 ▾      │
│ 新会话      ├──────────────────────────────────────────────┤
│ 搜索        │ 轮次 2  用户：看看这次的失败                  │
│ ──────────  │         助手：结论……（工具组 4 项 ▸）         │
│ 项目 A      │ 轮次 3  用户：改成排队                        │
│  · 修发送 ▸ │         助手：已改……                          │
│ 项目 B      │ （时间线底部跟随）                            │
│             ├──────────────────────────────────────────────┤
│ 账号        │ 输入位 ［文件块］ 文本…      模型 ▾  ↹ 提交   │
│             │ 输入位下缘：目标 · 上下文用量                   │
└──────────────────────────────────────────────────────────────┘
主操作区 = 时间线 + 输入位；附属信息区 = 标题行（项目/会话/分支/权限）与输入位下缘（目标/用量）；
子操作区 = 时间线内的行内展开、右栏（默认折叠）
```

运行中（第 4 轮在跑，队列 1 条）：

```text

│         助手：已改……                                          │
│ 轮次 4  用户：再跑一次                                        │
│         助手：流式……▍                                         │
│         工具组 3 项 · 读 2 写 1（运行中）▸                     │
├──────────────────────────────────────────────────────────────┤
│ 排队 1：把日志也开上（▸ 编辑 · ✕ 撤回）                       │
│ 输入位 ［文件块］ 文本…                     ■ 停止  ↹ 提交    │
```

审批待答（第 5 轮 exec 请求审批）：

```text
│ 轮次 5  用户：清一下临时目录                                  │
│         助手：要执行命令，等待你决定                          │
│ ╔═ 打断层 ═════════════════════════════════════════════════╗ │
│ ║ exec：rm -rf ./tmp/*        影响：工作区内写              ║ │
│ ║ 原因：工具需要写权限                                       ║ │
│ ║ [允许一次]  [始终允许此命令]  [拒绝]     ← 键位见下       ║ │
│ ╚══════════════════════════════════════════════════════════╝ │
├──────────────────────────────────────────────────────────────┤
```

长历史（60 轮，已上翻 2 页）：

```text
│ 轮次 1  用户：…                                  ┃ ┃ ┃      │
```

### 1.3 信息层级

| 层 | 放什么 | 依据 |
|---|---|---|
| 一眼 | 最后一轮的内容与是否在跑；有待答时是打断层 | U0 §2.2；§7.4 第 1 条 |
| 第二眼 | 轮次结构：用户消息、工具组摘要、结果文本；队列条 | U0 §2.2 |
| 按需 | 工具调用详情、思考块、文件改动、审批历史（对应工具行内）、右栏各标签 | 同上「按需」层 |

### 1.4 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 在输入位按提交 → 输入位清空、轮次尾部出现用户消息行与流式 → 服务端回执后行身份被替换（`session.submit`；排队时进队列条） |
| 打断 | 服务端来 `approval.request` → 时间线对应工具行标记"待你决定"，输入位上方出现打断层 → 应答（`approval.respond`；长期允许先写 `permission.rules`/`set_rules`）→ 打断层收起、工具行转结果 |
| 会话切换 | 点索引里的会话行 → 主区整体重建为那条会话（滑入，重建不闪空）→ 侧栏行"待你处理/运行中"标记沿用服务端事实 |
| 错误与未知 | 提交超时 → 输入位与本轮行同时呈现"结果未知"，核对（`session.input_lookup`）→ 命中则转成功；确认未写入则允许以新幂等键重提；核对到上限转"需人工确认"，不自动重发 |

### 1.5 状态如何附着

| 状态 | 附着元素 | 变化属性 | 不做什么 |
|---|---|---|---|
| 运行中 | 轮尾行 + 输入位提交键 | 行尾流式光标；提交键形态变"停止" | 不新增运行胶囊/状态条 |
| 排队中 | 队列条（已有对象列表） | 条数与位置；输入位提交键转"排队" | 不新增"排队中"徽标 |
| 审批待答 | 对应工具行 + 打断层 | 工具行标记变"待你决定"；打断层出现 | 不动用模态；不遮历史 |
| 提问待答 | 提问来源行 + 打断层 | 同上，层内是选项 | 不与审批叠成两层（一次只答一个） |
| 工具失败 | 该工具行 | 状态标记变叉，整行转次要灰度，可展开看结果 | 不弹窗、不加提示条、不造重试入口 |
| 结果未知 | 输入位 + 本轮用户行 | 两者同时呈现"结果未知"，带核对进度 | 不乐观标记为成功 |
| 断线 | 输入位 + 时间线底部 | 输入位不可提交（形态转"等待连接"）；底部行出现断点标记 | 不另立连接指示层 |
| 后台完成/未读 | 索引中的会话行 | 行首标记与未读点 | 不在主区加"完成"toast（跨会话走系统通知） |
| 上下文将满 | 输入位下缘的用量 | 数值与阈值形态变化，可展开明细 | 不新增独立用量条 |
| 能力缺失 | 该动作所在的元素 | 元素不可用并写原因（点击展开原因） | 不做沉默消失（见 §5 待裁决） |

### 1.6 可见性取舍

- 首屏默认：时间线、输入位、标题行；有待答时打断层。
- 按需：队列条（有才出现，无则不占位）、右栏、行内展开、消息轨、`@` 搜索。
- 不出现：唤醒与后台任务的常驻胶囊（改走对应行内与右栏）、状态条、任务中心、成本仪表。

### 1.7 放弃什么

- **放弃"打断期间输入位不可用"这一旧保障**：允许边答边写，代价是打断层与输入位同时存在，视线要跨一层。
- **放弃主区的完整高度**：打断层固定占位，长历史在打断时可见行数变少。
- **放弃活动条承担的"一眼看到会话级附属对象"**：目标、分支、唤醒、后台任务不再有一处汇总，各自附着（分支/目标在标题与下缘，唤醒/任务在右栏）。
- 若服务端在审批待答时拒绝提交，输入位在打断期间只能保留为本地草稿（见 §4.4 依赖项）。

### 1.8 概念级 Q 的答案

| Q | 本方案的回答 |
|---|---|
| Q-1 多会话 | 单前台；其余会话只在索引里带状态标记；跨会话完成走系统通知（U0 §4.10 沿用） |
| Q-3 右栏 | 默认折叠，展开是带标签容器；不参与打断 |
| Q-14 多窗口 | 首批不做；保留"把会话拉出"的余地（作为第二个窗口承载同一条会话） |
| Q-15 断线 | 附着在输入位与时间线底部（§1.5），不另立指示层 |
| Q-17 能力缺口 | 未接能力不进主界面，设置内留清单与原因；**该条与 U0 H11 冲突，待裁决**（`docs/ui-alignment.md` §7 C-9） |
| 活动条 | 删除。分支与目标并入标题行/下缘；唤醒、后台任务、子代理走右栏标签或所属行内 |

### 1.9 原则对照

| # | 如何满足 |
|---|---|
| P1 | 全部状态落在工具行、输入位、会话行、下缘用量上；打断层是决策面不是状态面（它承载要回答的事，不承载状态） |
| P2 | 审批与提问内联；唯一模态留给"完全访问"这类破坏性档位切换（U0 模式清单第 7 条） |
| P3 | 主操作区=时间线与输入位；附属=标题行与下缘；子操作=行内展开与右栏 |
| P4 | 提交、停止、应答、切换会话、上翻各给键位；鼠标路径（按钮、行内、展开）不被削弱 |
| P5 | 审批行给"命令 + 影响范围 + 原因"三段；错误行给结论 + 可展开原文，不直出原始错误码 |
| P6 | 断线与结果未知只呈现事实与进度；默认重连过程不用告警语 |
| P7 | 队列/右栏/消息轨/展开均"有才出现"，首屏不铺开 |
| P8 | 每个元素在 §0.3 与 §1.10 有来源；不出现重试、重新生成等无能力入口 |

| 右栏标签（唤醒/任务/子代理） | R 块 9、块 7；`session.wakeup.list`、`session.exec.pending`、`session.collaboration.pending` |
| 能力缺失原因 | R 块 9（能力缺失处理）+ `session.methods` |

**缺口：0。** 其余元素见 §0.3。

### 1.11 可实现性

用 mygo 已有能力：`Column/Row/Split`（布局）、`List`+`ListState{Key,FollowEnd,FollowAnimation}`（时间线与队列）、`Scroll`（上翻）、`Modal`（仅破坏性确认）、`PopoverMenu`（权限档位/模型）、`Button` 状态由 view 里的 `if` 表达、`ui/markdown` 或 markstream（正文与流式）、`c.TrackScroll` 与 `Attach`（跳回锚点）。

需自建：打断层的出现/收起与焦点转移；输入位与打断层的键位让位状态机；工具行折叠渲染与行内标记绘制（`Base`+`Painter`）；断线与结果未知的界面状态机（事实来自 D1/D3）；会话切换的重建与滚动恢复。

待确认依赖：审批待答时服务端是否接受 `session.submit`（若拒绝，改为"输入位保留草稿、提交不可用"）。

## 2 方案二：结果即骨架

**第一张力：T2（结果 vs 过程）。**

选它的理由：B1 的处境 S1 与 S4（等结果、回看历史）占了会话里的大部分停留时间，用户读的是结论；而过程信息在出问题时才变成证据。T2 解决得不好，代价是持续的注意力税（U0 §4.7 的问题陈述），而且它不依赖窗口宽度或平台能力，收益最普遍。

### 2.1 一句话概念

时间线以"结果"为骨架，过程是骨架上可展开的证据层；折叠不是收起来藏住，而是把"必须被看到的状态"抬到摘要行上。

### 2.2 画面骨架

默认态：

```text
┌──────────────────────────────────────────────────────────────┐
│ 索引        │ 项目 A · 修发送路径 · 分支 main · 权限 ▾      │
│ 新会话      ├──────────────────────────────────────────────┤
│ 搜索        │ ▌轮次 2 · 结论：发送丢失在排队判定            │
│ ──────────  │   证据：工具组 4 项 ▸（读 2 写 1 跑 1）       │
│ 项目 A      │ ▌轮次 3 · 结论：已改为默认排队                │
│  · 修发送 ▸ │   证据：工具组 2 项 ▸（改 2）                 │
│ 项目 B      │ ▌当前轮 · 正在改写发送路径                    │
│             │   ▸ 工具组运行中（读 3）                      │
│ 账号        ├──────────────────────────────────────────────┤
│             │ 输入位 ［文件块］ 文本…      模型 ▾  ↹ 提交   │
└──────────────────────────────────────────────────────────────┘
主操作区 = 结论骨架与输入位；附属信息区 = 每组"证据"行与标题行；子操作区 = 展开后的步骤、右栏
```

运行中：

```text

│   ▸ 工具组运行中 · 读 3 · 写 1（最近：send.go）               │

├──────────────────────────────────────────────────────────────┤
│ 排队 1：把日志也开上              输入位 …    ■ 停止         │
```

审批待答：

```text
│ ▌当前轮 · 等待你决定                                          │
│   ▸ 工具组 1 项 · exec 待答 ◂ 展开即定位到该步                │
│   ╔═ 打断层：exec 需要写权限 ═══════════════════════════════╗ │
│   ║ rm -rf ./tmp/*     影响：工作区内写   原因：…           ║ │
│   ║ [允许一次] [始终允许此命令] [拒绝]                      ║ │
│   ╚════════════════════════════════════════════════════════╝ │
├──────────────────────────────────────────────────────────────┤
│ 输入位 …                                            ↹ 提交    │
```

长历史：

```text

│ ▌轮次 18 · 结论：…                            ▸ 证据 3 项     │
│ ▌轮次 19 · 结论：…（失败）✕                   ▸ 证据 2 项     │
│ ▌轮次 20 · 结论：…                            ▸ 证据 5 项     │
│ …                                                             │
│ 顶部：只剩结论与证据计数；失败轮次整行保留标记                │
```

### 2.3 信息层级

| 层 | 放什么 |
|---|---|
| 一眼 | 每轮一行"结论"；当前轮的流式结论与工具组摘要 |
| 第二眼 | 证据计数（读/写/跑）与失败标记；排队条 |
| 按需 | 展开后的逐步工具行与结果、思考块、文件改动、审批历史 |

### 2.4 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 输入位提交 → 当前轮出现"结论（流式）"骨架与证据计数 → 回执后行身份替换 |
| 打断 | `approval.request` → 当前轮骨架行标"等待你决定"，证据行出现待答标记 → 应答后骨架转结论，展开可定位到那一步 |
| 会话切换 | 点会话行 → 该会话以"最近一轮结论 + 较旧结论摘要行"重建，展开任一轮即取该轮证据 |
| 错误与未知 | 失败：该轮结论行带叉标记并保留，展开看失败调用；未知：输入位与本轮结论行同时标"结果未知"，核对后转态 |

### 2.5 状态如何附着

| 状态 | 附着元素 | 变化属性 | 不做什么 |
|---|---|---|---|
| 运行中 | 当前轮骨架行 + 证据行 | 骨架行标记变"流式"；证据行计数变化 | 不新增运行条 |
| 排队中 | 队列条 + 输入位提交键 | 计数值；提交键形态 | 不新增徽标 |
| 审批待答 | 证据行 + 打断层 | 证据行标记"待答"，打断层内联 | 不动用模态 |
| 提问待答 | 证据行 + 打断层 | 同上，选项在层内 | 不同时叠两层 |
| 工具失败 | 该轮结论行 + 证据行 | 结论行整行保留并带叉；证据行标出失败步骤 | **折叠不得隐藏失败**（U0 §4.7 代价） |
| 结果未知 | 输入位 + 本轮结论行 | 两者同时呈现未知与核对进度 | 不乐观更新 |
| 断线 | 输入位 + 当前轮骨架行 | 输入位不可提交；骨架行标断点 | 不另立指示层 |
| 后台完成/未读 | 索引会话行 | 行首标记 | 不在主区弹完成提示 |
| 上下文将满 | 标题行用量 | 数值形态变化 | 不做独立仪表 |
| 子代理进行中 | 该轮证据行 | 计数与标记 | 不常驻胶囊 |

### 2.6 可见性取舍

- 首屏默认：每轮一行结论、当前轮流式、输入位。
- 按需：证据展开、思考块、文件改动、审批历史、右栏。
- 不出现：逐步日志常驻、活动条、状态条、任务中心。

### 2.7 放弃什么

- **放弃默认可见的逐步过程**：用户要看"它做了什么"必须展开；对以过程为阅读目的的用户（调试工具链）这是损失。
- **放弃"平铺时间线"的确定性**：骨架行是折叠结果的投影，折叠规则本身成为需要维护的一致性来源；折叠一旦出错，用户看到的是"被整理过的过去"。
- **放弃部分长历史密度**：一行一轮意味着同屏可容纳的轮次信息少于平铺（但可定位性更好）。

### 2.8 概念级 Q 的答案

| Q | 本方案的回答 |
|---|---|
| Q-1 多会话 | 单前台；索引行承载状态标记（沿用 U0 §4.10） |
| Q-3 右栏 | 默认折叠，带标签；本方案把"证据"默认收在行内，右栏只放跨轮视图（diff/终端） |
| Q-14 多窗口 | 首批不做，留余地 |
| Q-15 断线 | 输入位 + 当前轮骨架行 |
| Q-17 能力缺口 | 隐藏 + 设置清单；待裁决（同 §1.8） |
| 活动条 | 删除；"过程类对象"（子代理/后台任务）并入所属轮的证据行计数；唤醒进右栏标签 |

### 2.9 原则对照

| # | 如何满足 |
|---|---|
| P1 | 状态落在骨架行、证据行、输入位、会话行；折叠摘要行是既有元素 |
| P2 | 打断内联在证据行下方；模态只留破坏性确认 |
| P3 | 主=结论骨架与输入位；附属=证据行与标题；子=展开的步骤与右栏 |
| P4 | 每轮可键盘上/下跳、展开/折叠有键位；鼠标点击行与计数同样可达 |
| P5 | 错误给"哪一步、影响、原因"，原始输出在展开层 |
| P6 | 折叠只做呈现层整理，不改事实；重连过程不明示为失败 |
| P7 | 证据默认收起；活动条等容器不引入 |
| P8 | 只折叠已有行，不生成摘要、不推断结论；"结论"取自助手文本本身（D2 `step/text`） |

### 2.10 元素来源（增量与缺口）

| 本方案特有元素 | 来源 |
|---|---|
| 每轮骨架行（结论 + 证据计数） | R 块 2；D2 行类型（`step/text`、`step/tool-use`） |
| 证据计数（读/写/跑） | R 块 2；`session.event` 工具事实 |
| 证据展开定位到步骤 | R 块 2；工具行 `call_id` |
| 打断层（在证据行下） | R 块 6、块 7；`approval.request`、`session.question.pending` |
| 失败轮整行保留 | R 块 2；`tool-completed` 结果 |
| 未知标记与核对 | R 块 3；`session.input_lookup` |

**缺口：0。** 骨架行与"结论"不是新事实：结论=该轮助手文本，折叠计数=该轮工具行计数，都来自 D2 已有行。

### 2.11 可实现性

用 mygo 已有能力：`List`+`ListState{Key,FollowEnd}`（骨架行列表，行高可变）、`Collapsible`/`Accordion`（证据展开）、`Scroll`、`PopoverMenu`、`ui/markdown`（结论与流式）。

需自建：折叠规则与行高测量（折叠后高度变化）；"证据行 ↔ 步骤"的锚定滚动；状态标记绘制；未知/断线状态机。

风险：折叠投影与 D2 的行身份必须一一对应，不能出现"界面自己的一组摘要行"（违反 J1）；这条要在 C1 写成断言。

## 3 方案三：对照即同屏

**第一张力：T3（多会话的深度 vs 并行感知），并顺带解 T4（同屏对照 vs 主区宽度）。**

选它的理由：多会话并行是真实用法（U0 Q-1 的"同时跑多个"），但旧界面只有两条弱通道——侧栏徽标与系统通知，通知还可能被系统关掉（U0 §4.10 代价段）。把第二条会话搬进同屏，是唯一不依赖系统通知的解法；代价（宽度）是显式且可选的。

### 3.1 一句话概念

主区可以并排两条会话：一条主、一条副（副列可折叠），侧栏从"列表"降为"索引"；右栏仍是带标签容器，副列就是它其中的一个标签。

### 3.2 画面骨架

默认态（wide，副列收起）：

```text

│ 新会话├───────────────────────────────────────┤（默认折叠）  │
│ 搜索  │ 轮次 2  用户：看看这次的失败          │              │
│ ────  │         助手：结论……（工具组 4 ▸）    │              │
│ 项目 A│ 轮次 3  用户：改成排队                │              │

│ ·参考  │                                       │              │

主操作区 = 主列（时间线 + 输入位）；附属信息区 = 标题行与右栏标签；子操作区 = 行内展开与副列
```

长历史（主列 60 轮，副列保持自己的位置）：

### 3.3 信息层级

| 层 | 放什么 |
|---|---|
| 一眼 | 主列当前轮与是否在跑；副列标题与待答标记 |
| 第二眼 | 主列轮次结构；索引里的会话状态标记 |
| 按需 | 右栏其他标签、副列的 diff/终端标签、行内展开 |

### 3.4 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 输入位提交 → 所在列尾部流式；焦点固定在该列 → 回执后行身份替换（不跨列） |
| 打断 | 任一列收到 `approval.request` → 该列内联打断层，另一列不加任何标记（除索引行）→ 应答只作用于该列会话 |
| 会话切换 | 索引点会话 → 载入主列；右键/拖拽 → 载入副列（右栏"会话"标签）→ 主列不重建 |
| 错误与未知 | 出错列内标未知/失败，另一列不受影响；断线时两列都不可提交（同一连接） |

### 3.5 状态如何附着

| 状态 | 附着元素 | 变化属性 | 不做什么 |
|---|---|---|---|
| 运行中 | 该列轮尾 + 提交键 + 索引行 | 流式光标；提交键变停止；索引行标记 | 不新增运行条 |
| 排队中 | 该列队列条 | 条数 | 不新增徽标 |
| 审批待答 | 该列工具行 + 列内打断层 + 索引行 | 三处同一含义 | 不用模态；不影响另一列 |
| 提问待答 | 同上 | 同上 | 不与审批叠层 |
| 工具失败 | 该工具行 | 叉标记 + 灰度 | 不加提示条 |
| 结果未知 | 该列输入位 + 本轮行 | 未知标记与核对进度 | 不乐观更新 |
| 断线 | 两列输入位 + 各自底部 | 不可提交 + 断点 | 不另立指示层 |
| 后台完成/未读 | 索引行 + 副列标题 | 标记 | 主列不弹提示 |
| 焦点列/非焦点列 | 列容器本身 | 非焦点列整体降一级（A2 `InactiveAccent` 同款思路） | 不用遮罩或模糊 |
| 上下文将满 | 该列标题行用量 | 数值形态 | 不做仪表 |

### 3.6 可见性取舍

- 首屏默认（wide）：主列 + 折叠的右栏与副列入口；索引常驻。
- 按需：副列、右栏其他标签、行内展开。
- 不出现：活动条、状态条、任务中心；窄窗口下不提供副列（不降级为"两个都缩"）。

### 3.7 放弃什么

- **放弃窄窗口的对照能力**：compact 下副列不存在，只能切换（与 U0 §9.1.2 的替换式同结论）。
- **放弃"右栏是唯一辅助面"的简单性**：右栏现在也可能是第二条会话，它的标签语义变重，用户要判断"这一栏是资料还是对话"。
- **放弃单列时的时间线宽度**：副列展开必然挤压主列。
- **放弃"切换即完整换页"的心智**：两列各自有滚动、焦点、未读状态，状态恢复面变大。

### 3.8 概念级 Q 的答案

| Q | 本方案的回答 |
|---|---|
| Q-1 多会话 | **改判参数**：主区不是永远一个会话，而是"一主一副"；副列可折叠，折叠后回到单前台。需要用户确认是否接受对 Q-1 的改判 |
| Q-3 右栏 | 保留"默认折叠 + 带标签"，但把"会话"作为其中一个标签，用于副列 |
| Q-14 多窗口 | 本方案用同屏部分替代开窗需求；popout 保留余地并排更后 |
| Q-15 断线 | 附着在受影响列与索引行（断的是连接，影响所有列） |
| Q-17 能力缺口 | 隐藏 + 设置清单；待裁决（同 §1.8） |
| 活动条 | 删除；会话级对象的状态落到索引行与该列标题；后台任务/子代理进右栏标签 |

### 3.9 原则对照

| # | 如何满足 |
|---|---|
| P1 | 状态落在该列的行、输入位、索引行；焦点列用整体降级表达"不在这一列"，不加遮罩 |
| P2 | 打断列内内联；模态只留破坏性确认 |
| P3 | 主=主列；附属=标题与右栏标签；子=副列与行内展开 |
| P4 | 列间切换、列内跳转、提交、应答有键位；鼠标拖拽/右键开副列同样可达 |
| P5 | 打断层与错误行同样给三段信息；跨列不重复播报 |
| P6 | 降级只作用于非焦点列，不改该列事实与状态 |
| P7 | 副列与右栏默认折叠；索引不展开成树的全量 |
| P8 | 副列只承载"已存在的会话"，不凭空造"并行任务"概念；无跨会话合并视图 |

### 3.10 元素来源（增量与缺口）

| 本方案特有元素 | 来源 |
|---|---|
| 副列（第二会话） | R 块 5 + R 块 2；`session.catalog` + `session.history`（同会话订阅） |
| 右栏"会话"标签 | Q-3（带标签容器）+ R 块 5 |
| 列焦点与降级 | 无新事实；本地界面状态（Q-18 待定） |
| 索引行状态标记 | R 块 3、块 5；`session.state`、`session.catalog` |
| 拖拽/右键开副列 | 本地动作；`session.history` 已有能力 |

**缺口：0。** 但有一处**依赖本地状态**：哪一列显示哪个会话、列宽、焦点列——需在 A 域登记（Q-18 未定），否则重启后无法恢复。

### 3.11 可实现性

用 mygo 已有能力：`Split`（两列）、`List`+`ListState`（每列一个）、`Sidebar`/`SidebarItem`（索引）、`Tabs`（右栏标签）、`InactiveAccent` 与 `Opacity`（非焦点列降级）、`WindowOptions`（预留开窗）。

需自建：两列的焦点与键位让位状态机（A2 §2.7 只有原语）；列内滚动与恢复（`TrackScroll` 之上）；跨列通知抑制规则（哪一列的完成提示不打扰另一列）。

## 4 三方案横向比较

### 4.1 一句话区别

| 方案 | 第一张力 | 一句话 |
|---|---|---|
| 一 打断即主干 | T1 打断 vs 连续输入 | 把必须回答的事抬成主区的一层，输入位不再被替换 |
| 二 结果即骨架 | T2 结果 vs 过程 | 每轮一行结论、证据可展开，失败不许被折叠藏住 |
| 三 对照即同屏 | T3/T4 多会话与空间 | 主区可并排两条会话，侧栏降为索引 |

### 4.2 同场景结构差异

| 场景 | 方案一 | 方案二 | 方案三 |
|---|---|---|---|
| 默认态 | 时间线 + 输入位，标题行与下缘挂附属信息 | 每轮一行结论 + 证据计数 | 主列 + 折叠副列 + 索引 |
| 运行中 | 轮尾流式 + 提交键转停止 | 当前轮骨架行 + 证据计数变化 | 该列内变化，另一列不受影响 |
| 审批待答 | 输入位上方打断层，输入位保留 | 证据行下打断层，当前轮标"等待你决定" | 该列内联打断层，索引行同义标记 |
| 长历史 | 上翻分页 + 消息轨跳回 | 结论骨架 + 展开证据 | 两列各自滚动与恢复 |
| 主要代价 | 打断占高度 | 默认看不到步骤 | 窄窗口失去对照、状态恢复面变大 |

### 4.3 淘汰线自检

| 淘汰线 | 方案一 | 方案二 | 方案三 |
|---|---|---|---|
| 虚构动作/状态 | 无（重试/重新生成未出现） | 无 | 无 |
| 新增状态容器 | 无（打断层是决策面；队列是对象列表） | 无 | 无（副列是会话容器） |
| 模态承载非阻塞事务 | 无（唯一模态是破坏性档位切换） | 无 | 无 |
| 以"常见做法"论证 | 无 | 无 | 无 |
| 首屏铺开全部 | 无 | 无 | 无（副列与右栏默认折叠） |
| 界面自攒事实/乐观更新 | 无 | 无（折叠只整理已有行） | 无（列宽与焦点属本地状态，需登记） |

## 5 被删掉的候选元素（避免虚构）

以下曾在讨论中出现，但指不到需求条目或协议方法，三方案均不采用：

| 候选 | 为什么删 |
|---|---|
| 工具调用失败后的"重试"/"重新生成" | 协议没有该能力；写登记不自动重发（D3）。用户原话：「这种东西没有能力重试的啊」 |
| 自动摘要/智能折叠成"要点" | 没有生成摘要的能力；只能折叠已有行并取首末行作预览 |
| 全局会话全文搜索 | 目录只有列表与分页，没有内容检索方法 |
| 会话内全文查找 | 同上；且与虚拟化冲突（Q-6） |
| 任务中心 / 跨会话任务总览 | Q-2 已裁定界面不存在"任务"层 |
| 常驻状态条 / 活动条胶囊 | P1、Q-9 |
