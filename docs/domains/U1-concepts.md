### 0.2 常规构图基线（这类应用的默认形态）

**基线**：左侧导航承载项目与会话（256）；中间一条会话，标题栏 48 写会话名、分支、权限与模型；对话流按内容上限 784 居中，用户消息右对齐、助手文本满宽、工具调用折叠成一行摘要；输入区贴在对话底部（60–300），运行中提交以队列条显示在输入区上方；右栏可选（280–容器−400），默认关闭。

基线里**没有**状态条与活动条——这两项由 P1、Q-9、Q-19 直接排除，不计为偏离。

**偏离上限**：每个方案只允许在基线上偏离 **≤2 处**。超过 2 处即说明它不属于"通用桌面 agent"的可识别形态，直接砍掉。偏离必须写成三行：常规做法是什么 → 我改成什么 → 代价是什么。

三个方案的偏离数：**A = 1，B = 2，C = 2。**

### 0.3 张力与方案取向

方案不是从"想做得不一样"来的，而是从 A1 里真实存在的张力里选一个先解，再在基线上做最少的结构改动。

| # | 张力 | 相争的两端 | 证据 | 选它的代价 |
|---|---|---|---|---|
| T1 | 打断的抢占 vs 输入的连续 | 审批必须与历史同视线；但抢占输入位时用户没法准备下一条 | U0 §4.1 及其代价段、§7.2、H3 | 打断面占位，主区高度被切走 |
| T2 | 结果 vs 过程 | 阅读主体是结果，过程默认折叠；但折叠会藏住失败 | U0 §4.7 及其代价段、§2.2、H4 | 默认看不到步骤；折叠规则要长期维护 |
| T3 | 多会话的深度 vs 并行感知 | 单前台保深度；另一条只能靠侧栏与系统通知 | U0 §4.10 代价段、H2、§7.4 | 侧栏/通知是弱通道，"看一眼另一条"要切换 |
| T4 | 同屏对照 vs 主区宽度 | 并排能对照；但并排挤压主区，窄窗口只能替换 | U0 §4.3、§12.3、§12.9、H8 | 对照只在宽窗口成立 |

三方案各解一个：A 解 T1，B 解 T2，C 解 T3+T4。T6（长历史可定位）、T8（错误留下）、T9（空态控制行）不在本阶段展开，三方案都只按基线处理。

### 0.4 图解约定

- 线框按真实像素布局：侧栏 256、标题栏 48、内容上限 784、输入区 60–300、右栏 280–容器−400；两组宽 1440 与 900。
- 灰度配色（#fff 背景 / #f5f5f5 面板 / #ddd 边线 / #333 文本 / #999 次要），系统字体，无外部资源、无 JS。

## 1 方案 A：输入区常驻 + 审批占底栈一层

**解 T1。** 线框：[wireframes/a.html](wireframes/a.html)

### 1.1 结构描述

左导航 256 / 中间对话 / 输入区贴底；审批不替换输入区，改在输入区上方多占一层，输入区仍可编辑与提交。

### 1.2 偏离台账（1 处）

| # | 常规做法 | 我改成什么 | 代价 |
|---|---|---|---|
| A-1 | 审批出现时占据输入区位置（旧界面同一条互斥绑定：审批与输入区互斥），输入区暂时不可用 | 审批在底栈单独占一层（约 116px），输入区保持可用；提交通道不变，默认排队 | 主区可见高度从 566px 降到约 450px（−21%）；两层同在时视线要跨一层 |

下列各项**不偏离**，只是上面这处的后果：活动条位置空出（Q-19，不计偏离）；状态条不存在（P1，不计偏离）；右栏宽度与三档让位沿用 §12.9。

### 1.3 三行说明（按状态）

| 状态 | 主次排序 | 重复单元 | 面积分配理由 |
|---|---|---|---|
| 默认态 | ① 末两轮 ② 输入区 ③ 标题行 | 一轮 = 右对齐用户消息 + 助手块，工具组以 16.75px 缩进一行摘要 | 时间线 566 / 输入 110 / 标题 48，与现役一致；侧栏 20% 只做导航 |
| 运行中 | ① 流式结论 ② 工具组摘要 ③ 队列条 | 同上；运行态只改形态，不加行 | 队列 32px 从时间线借，阶段性占用 |
| 审批待答 | ① 审批层 ② 触发它的工具行 ③ 输入区 | 审批层内部三段：动作 / 影响与原因 / 决定 | 审批层 116 + 输入 110 同时存在，时间线让出 116 |
| 出错/未知 | ① 未知标记（输入区与本轮用户行）② 失败的工具行 ③ 其余历史 | 同一套标记语言：叉、灰度、未知文案 | 不加新区域，只在既有行上变化 |
| 长历史 | ① 当前轮 ② 上翻锚点 ③ 消息轨 | 一行一轮的锚点；展开仍是标准轮结构 | 上翻条 28px，按需出现 |

### 1.4 信息层级

| 层 | 放什么 |
|---|---|
| 一眼 | 最后一轮的内容与是否在跑；有待答时是审批层 |
| 第二眼 | 轮次结构（用户消息、工具组摘要、结果文本）；队列条 |
| 按需 | 工具详情、思考块、文件改动、审批历史、右栏各标签 |

### 1.5 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 输入区提交 → 输入区清空、轮尾出现用户行与流式 → 回执后行身份被替换（`session.submit`）。运行中或审批待答时同样可提交，默认排队（Q-7），提交不改变待决审批（D5 §4.12） |
| 打断 | `approval.request` → 工具行标"待你决定"，输入区上方出现审批层 → 应答（`approval.respond`；长期允许先写 `permission.set_rules`）→ 层收起、工具行转结果 |
| 会话切换 | 点导航行 → 主区整体重建（滑入，不闪空）→ 导航行状态标记来自服务端事实 |
| 错误与未知 | 提交超时 → 输入区与本轮用户行同时呈现"结果未知"，核对（`session.input_lookup`）→ 命中转成功；确认未写入才允许以新幂等键重提；到上限转人工确认，不自动重发 |

### 1.6 七类事实的附着方向（Q-19，方向归 C1）

| 事实 | 附着元素 | 表现方式 |
|---|---|---|
| 目标 | 标题行 | 会话名右侧事实文案，展开看全文（`session.goal.*`） |
| 待办 | 所属轮的工具组行 | 该行计数，展开看条目 |
| 子代理 | 所属轮的工具组行 | 同上；运行中只改这一行形态 |
| 分支 | 标题行 | 与会话名同列（`session.branches`） |
| 唤醒 | 右栏"唤醒"标签 | 无时间线行，按需查看（`session.wakeup.list`） |
| 后台进程 | 工具组行 + 右栏"任务"标签 | 行内计数；停止在任务页（`session.exec.stop`） |
| 本回合文件改动 | 该轮结果行末尾 | 计数，展开到右栏 diff |

### 1.7 状态如何附着

| 状态 | 附着元素 | 变化属性 | 不做什么 |
|---|---|---|---|
| 运行中 | 轮尾行 + 提交键 | 行尾流式光标；提交键换为停止 | 不新增运行胶囊 |
| 队列中 | 队列条 + 提交键 | 条数；提交键转"排队" | 不新增徽标 |
| 审批待答 | 该工具行 + 审批层 | 工具行标记转"待你决定"；层出现 | 不用模态；不遮历史 |
| 提问待答 | 提问来源行 + 审批层同位置 | 同上，层内是选项 | 不与审批叠两层 |
| 工具失败 | 该工具行 | 标记变叉、整行转次要灰度、可展开 | 不弹窗、不加提示条、不造重试入口 |
| 结果未知 | 输入区 + 本轮用户行 | 两处同义标记 + 核对进度 | 不乐观标记成功 |
| 断线 | 输入区 + 时间线底部 | 输入区不可提交；底部断点标记 | 不另立连接指示层 |
| 后台完成/未读 | 导航会话行 | 行首标记与未读点 | 主区不弹完成提示 |
| 上下文将满 | 输入区下缘用量 | 数值与阈值形态 | 不做独立仪表 |
| 能力缺失 | 该动作所在元素 | 待决 D-1：隐藏，或禁用并写原因 | 不两种一起做 |

### 1.8 可见性取舍

首屏：时间线、输入区、标题行，有待答时审批层。按需：队列条、右栏、行内展开、消息轨、`@` 搜索、唤醒与任务页。不出现：状态条、活动条、任务中心、成本仪表。

### 1.9 放弃什么

- 放弃"打断期间输入区不可用"这个旧保障：眼要跨一层。
- 放弃主区完整高度：打断时时间线 −21%。
- 放弃活动条那处"会话级对象汇总"：七类事实分别去它们的行、标题行或右栏找。

## 2 方案 B：结论行 + 证据行

**解 T2。** 线框：[wireframes/b.html](wireframes/b.html)

### 2.1 结构描述

左导航 256 / 中间对话 / 输入区贴底不变；对话流里每一轮压成"结论行 + 证据行"两行，失败与待答的标记提到结论行上。

### 2.2 偏离台账（2 处）

| # | 常规做法 | 我改成什么 | 代价 |
|---|---|---|---|
| B-1 | 对话流平铺：用户气泡、助手满宽文本、工具组一行摘要，块间 10.5px | 每轮先出一行结论（22.75px），过程收进第二行证据计数（同一行高，缩进 16.75px） | 同面积装约 2 倍轮次，但每轮默认只显示结论；一行位置只能放一句话 |
| B-2 | 失败只在内层工具行可见，折叠后看不到 | 失败与待答标记上提到结论行（叉 + 整行保留），折叠不得隐藏 | 结论行承担状态，行内文字要留位置给标记 |

### 2.3 三行说明（按状态）

| 状态 | 主次排序 | 重复单元 | 面积分配理由 |
|---|---|---|---|
| 默认态 | ① 结论行 ② 证据计数 ③ 输入区 | 一轮 = 结论行 + 证据行，两行同高 22.75px | 时间线与输入区面积不变，轮次密度提高约 2 倍 |
| 运行中 | ① 流式结论 ② 证据计数 ③ 队列条 | 运行态不加行：结论行转流式、证据行更新计数 | 与默认态同高，不因运行长高 |
| 审批待答 | ① 结论行上的"待你决定" ② 审批卡 ③ 那一步证据 | 审批卡仍是对话流内的一张卡（基线做法） | 卡片在内，结论行不变高，滚动位置稳定 |
| 出错/未知 | ① 带叉的结论行 ② 证据行标出失败步 ③ 未知标记 | 同上；折叠不得隐藏 | 不给错误新区域，只给结论行一个标记位 |
| 长历史 | ① 结论序列 ② 失败轮 ③ 输入区 | 一行一轮 | 同屏约 8 轮（平铺约 3 轮） |

### 2.4 信息层级

| 层 | 放什么 |
|---|---|
| 一眼 | 每轮一行结论；当前轮流式结论与证据计数 |
| 第二眼 | 证据计数（读/写/执行）与失败标记；队列条 |
| 按需 | 展开后的逐步工具行与结果、思考块、文件改动、审批历史 |

### 2.5 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 输入区提交 → 当前轮出现结论行与流式 → 回执后行身份替换（`session.submit`；审批待答时同样可提交，D5 §4.12） |
| 打断 | `approval.request` → 结论行标"待你决定"，证据行标该步 → 应答后结论行转文本，展开可定位到那一步 |
| 会话切换 | 点导航行 → 以"最近一轮结论 + 较旧结论行"重建；展开任一轮即取该轮证据 |
| 错误与未知 | 失败：结论行带叉并保留，展开看失败调用；未知：输入区与本轮结论行同时标"结果未知"，核对后转态 |

### 2.6 七类事实的附着方向（Q-19）

| 事实 | 附着元素 | 表现方式 |
|---|---|---|
| 目标 | 标题行 | 会话名右侧事实文案 |
