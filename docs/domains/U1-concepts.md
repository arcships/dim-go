## 1 方案一：打断即主干

**第一张力：T1（打断的抢占 vs 输入的连续）。**

选它的理由：首批闭环的定义就是"看历史 + 提交 + 处理审批"（`docs/project-organization.md` §9.3），三件事里唯一会互相打断的就是审批/提问；而它是唯一"不处理就完全走不下去"的处境（B1 S2）。T1 的损失最不可逆：被抢占的输入要用户重新组织，而重新组织没有服务端事实可以恢复。

### 1.1 一句话概念

把"必须回答的事"抬成主区里独立的一层主干，输入区不再被它替换——旧界面靠互斥换来的"同一视线"，用上下相邻的两层同样拿到，同时保住正在写的输入。

### 1.2 画面骨架

**默认态（wide 1280；侧栏 256 / 主区 1024 / 右栏折叠 / 内容 784）**

```text
┌────────┬────────────────────────────────┐
│ 新会话 │项目 A · 修发送路径 · main      │
│ 搜索   │                                │
├────────┼────────────────────────────────┤
│ 项目 A │轮次 2  用户：看看这次失败      │
│ ·修发送│        助手：结论… ▸工具 4     │
│ 项目 B │轮次 3  用户：改成排队          │
│ ·参考  │        助手：已改…             │
│        │⋮ 时间线 531+35（17 行）        │
│        │────────────────────────────────│
│        │输入区 110（3 行）              │
│        │［块］文本…  模型▾ 提交         │
│ 账号   │下缘：目标 · 用量               │
└────────┴────────────────────────────────┘
```
图注：标题行 48px；主区内 784px 内容带居中，左右各留约 4 格（下文同，方案三双列除外）

- **主次排序**：① 时间线末两轮（要读的判断）② 输入区（下一步动作）③ 标题行（提交前的归属与权限）。三者都在 784 内容带里纵向相邻，视线不横跳。
- **重复单元**：一轮 = 右对齐用户消息（≤85% 内容宽）+ 助手块（块间 10.5px）；工具组在该轮内以 16.75px 缩进的一行摘要（22.75px 行高）出现。
- **面积分配理由**：时间线 566/800 ≈ 71%、输入 110 ≈ 14%、标题 48 ≈ 6%；停留时间与操作频率都集中在前两者，侧栏只做导航，20% 与之相称。

**运行中（第 4 轮在跑，队列 1 条）**

```text
┌────────────────────────────────┐
│  轮次 4 用户：再跑一次         │
│         助手：流式…▍           │
│         ▸ 工具组 3（读2 写1）  │
├────────────────────────────────┤
│排队 1：把日志也开上 ▸编辑 ✕撤回│
│输入区 ［块］文本…    ■停止     │
└────────────────────────────────┘
```
图注：队列有才出现

- **主次排序**：① 流式结论（此刻唯一在变的东西）② 工具组摘要（过程是否需要看）③ 队列条（自己刚提交的那条）。停止键在输入区里，不进主区。
- **重复单元**：轮 = 用户行 + 助手块 + 工具组摘要；运行态只改这三者的形态，不新增行。
- **面积分配理由**：队列条占 1 行（32px），从时间线借；不因为有运行就固定预留，因为它是阶段性的。

**审批待答（第 5 轮 exec 请求审批）**

```text
┌────────────────────────────────┐
│  轮次 5 用户：清一下临时目录   │
│     ▸ 工具组 1 · exec ⚑待你决定│
│ ╔══════════════════════════╗   │
│ ║exec：rm -rf ./tmp/*      ║   │
│ ║影响：工作区内写          ║   │
│ ║原因：需要写权限          ║   │
│ ║[允许一次][始终允许][拒绝]║   │
│ ╚══════════════════════════╝   │
├────────────────────────────────┤
│输入区（保留，可提交）  排队 ▸  │
└────────────────────────────────┘
```
图注：打断层（约 4 行 ≈128px，E4）

- **主次排序**：① 打断层（必须回答，且带影响范围）② 触发它的那一行工具（判断依据）③ 输入区（答完就能继续）。打断层与工具行上下相邻，不遮历史。
- **重复单元**：打断层内部固定三段（动作 → 影响与原因 → 决定），与提问层同构；层高随内容，按 4 行估。
- **面积分配理由**：打断层 128px、输入区 110px 同时存在，时间线从 566 掉到约 438px（−23%）；这是"同时看见要答的事与自己在写什么"必须付的面积。

**长历史（60 轮，已上翻 2 页）**

```text
┌────────────────────────────────┐
│⤒ 上一页（还有 42 轮）          │
│┃ 轮次 1  用户：…               │
│┃ 轮次 2  用户：…（折叠 ▸）     │
│⋮                               │
│┃ 轮次 60 用户：…（当前）       │
│消息轨 22px，悬停跳回同一问     │
└────────────────────────────────┘
```

- **主次排序**：① 当前轮 ② 上翻锚点（知道自己在哪）③ 消息轨（回到某个提问）。三者都不与正文争宽。
- **重复单元**：一行一轮的锚点；展开仍是标准轮结构，节奏不因历史长而改。
- **面积分配理由**：消息轨占 22px（约内容带的 3%），只在 ≥3 轮出现；它省掉的是滚很久找一句话的时间，比例上划算。

### 1.5 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 在输入区按提交 → 输入区清空、轮尾出现用户行与流式 → 回执后行身份被替换（`session.submit`）。运行中或审批待答时同样可提交，默认排队（Q-7），提交不改变待决审批（D5 §4.12） |
| 打断 | `approval.request` → 对应工具行标记"待你决定"，输入区上方出现打断层 → 应答（`approval.respond`；长期允许先写 `permission.rules`/`set_rules`）→ 层收起、工具行转结果 |
| 会话切换 | 点索引行 → 主区整体重建（滑入，不闪空）→ 索引行状态标记来自服务端事实 |
| 错误与未知 | 提交超时 → 输入区与本轮用户行同时呈现"结果未知"，核对（`session.input_lookup`）→ 命中转成功；确认未写入才允许以新幂等键重提；到上限转人工确认，不自动重发 |

## 2 方案二：结果即骨架

**第一张力：T2（结果 vs 过程）。**

选它的理由：B1 的处境 S1 与 S4（等结果、回看历史）占了会话里的大部分停留时间，用户读的是结论；过程信息在出问题时才变成证据。T2 解决不好会持续收"注意力税"（U0 §4.7 的问题陈述），而它不依赖窗口宽度或平台能力，收益最普遍。

### 2.1 一句话概念

时间线以"结果"为骨架，过程是骨架上可展开的证据层；折叠不是把东西藏起来，而是把"必须被看到的状态"抬到骨架行上。

### 2.2 画面骨架

**默认态（wide 1280；侧栏 256 / 主区 1024 / 内容 784）**

```text
┌────────┬────────────────────────────────┐
│ 新会话 │项目 A · 修发送路径 · main      │
│ 搜索   │                                │
├────────┼────────────────────────────────┤
│ 项目 A │▌轮次 2 结论：丢在排队判定      │
│ ·修发送│  ▸ 证据 4（读2 写1 跑1）       │
│ 项目 B │▌轮次 3 结论：已改默认排队      │
│ ·参考  │  ▸ 证据 2（改2）               │
│        │▌当前轮：正在改写发送路径       │
│        │  ▸ 证据 3（读3）·运行中        │
│        │────────────────────────────────│
│        │输入区 110（3 行）              │
│ 账号   │［块］文本…  模型▾ 提交         │
│        │下缘：目标 · 用量               │
└────────┴────────────────────────────────┘
```
图注：标题行 48px；骨架行 22.75px；证据行（缩进 16.75）

- **主次排序**：① 每轮结论行（骨架）② 当前轮的证据计数（是否要看过程）③ 输入区。同宽下比平铺多出 2–3 倍的轮次可见量。
- **重复单元**：一轮 = 一行骨架（22.75px）+ 一行证据计数（22.75px，左缩进 16.75px，沿用 §12.4 的工具组缩进）；展开后回到标准行结构。
- **面积分配理由**：时间线 566px、输入 110px 与方案一相同；差异在时间线内部——同样面积装约 2 倍轮次，代价是每轮默认只显示结论。

**运行中（第 4 轮）**

```text
┌────────────────────────────────┐
│▌轮次 4 结论（流式）：先补排队…▍│
│  ▸ 证据 3 · 读2 写1 · send.go  │
├────────────────────────────────┤
│排队 1：把日志也开上            │
│输入区 ［块］文本…    ■停止     │
└────────────────────────────────┘
```

- **主次排序**：① 流式结论 ② 证据计数与"最近做了什么"③ 队列。过程收在计数里，只给一个"最近"钩子。
- **重复单元**：运行态不新增行：骨架行转流式、证据行更新计数。
- **面积分配理由**：运行态与默认态同高，不因运行而长高——这是本方案相对"运行胶囊/进度条"的关键取舍。

**审批待答（第 5 轮）**

```text
┌────────────────────────────────┐
│▌轮次 5 结论：等待你决定 ⚑      │
│  ▸ 证据 1 · exec 待答          │
│ ╔══════════════════════════╗   │
│ ║exec：rm -rf ./tmp/*      ║   │
│ ║影响：工作区内写          ║   │
│ ║原因：需要写权限          ║   │
│ ║[允许一次][始终允许][拒绝]║   │
│ ╚══════════════════════════╝   │
├────────────────────────────────┤
│输入区（保留，可提交）          │
└────────────────────────────────┘
```

- **主次排序**：① 骨架行上的"等待你决定"② 打断层（内容）③ 那一步证据（判断依据）。状态先出现在骨架行，细节在层里，两者同义。
- **重复单元**：打断层沿用三段结构；骨架行保持 22.75px 不变高。
- **面积分配理由**：打断层约 128px（E4）从时间线借；骨架行不因打断改变行高，滚动位置因此稳定。

**长历史（60 轮）**

```text
┌────────────────────────────────┐
│⤒ 上一页（还有 42 轮）          │
│▌轮次 18 结论：… ▸证据 3        │
│▌轮次 19 结论：… 失败 ✕ ▸证据 2 │
│▌轮次 20 结论：… ▸证据 5        │
│⋮ 同屏约 8 轮（平铺约 3 轮）    │
└────────────────────────────────┘
```

- **主次排序**：① 结论序列（扫读定位）② 失败轮次的叉标记（唯一必须穿透的例外）③ 输入区。左侧 `▌` 承担消息轨角色。
- **重复单元**：一行一轮；失败整行保留标记，折叠不得隐藏（U0 §4.7 代价）。
- **面积分配理由**：同面积装更多轮次是这条张力的直接收益；代价写在 §2.9。

| P3 | 主=骨架与输入区；附属=证据行与标题；子=展开的步骤与右栏 |
| P4 | 每轮可键盘上/下跳、展开/折叠有键位；鼠标点行与计数同样可达 |
| P5 | 错误给"哪一步、影响、原因"，原始输出在展开层 |
| P6 | 折叠只整理呈现，不改事实；重连过程不明示为失败 |
| P7 | 证据默认收起；活动条等容器不引入 |
| P8 | 只折叠已有行，不生成摘要、不推断结论；"结论"取自助手文本本身（D2 `step/text`） |

### 2.12 元素来源（增量与缺口）

| 本方案特有元素 | 来源 |
|---|---|
| 轮骨架行 | R 块 2；D2 行类型（`step/text`、`step/tool-use`） |
| 证据计数（读/写/跑） | R 块 2；`session.event` 工具事实（按工具名归类） |
| 证据展开定位 | R 块 2；工具行 `call_id` |
| 失败上传到骨架行 | R 块 2；`tool-completed` 结果 |
| 未知标记与核对 | R 块 3；`session.input_lookup` |

**缺口：0。** 骨架行与结论不是新事实：结论=该轮助手文本，计数=该轮工具行计数。

### 2.13 可实现性

用 mygo 已有能力：`List`+`ListState{Key,FollowEnd}`（可变行高）、`Collapsible`/`Accordion`、`Scroll`、`PopoverMenu`、`ui/markdown`。

需自建：折叠规则与行高测量；"骨架行 ↔ 证据步"的锚定滚动；状态标记绘制；未知/断线状态机。

风险：折叠投影必须与 D2 行身份一一对应，不能出现"界面自己的一组摘要行"（违反 J1）；C1 要写成断言。

## 3 方案三：对照即同屏

**第一张力：T3（多会话的深度 vs 并行感知），顺带解 T4（同屏对照 vs 主区宽度）。**

选它的理由：多会话并行是真实用法（U0 Q-1 的"同时跑多个"），但旧界面只有两条弱通道——侧栏徽标与系统通知，通知还可能被系统关掉（U0 §4.10 代价段）。把第二条会话搬进同屏，是唯一不依赖系统通知的解法；代价（宽度）显式且可选。

### 3.1 一句话概念

主区可以并排两条会话：一条主、一条副（副列可折叠），侧栏从"列表"降为"索引"；右栏仍是带标签容器，副列就是它其中的"会话"标签。

### 3.2 画面骨架

**运行中（主列在跑，副列待答）**

- **重复单元**：两列共用同一套行形态；只有焦点列满强度，非焦点列整体降一级。
- **面积分配理由**：两列同高各自滚动；不因副列待答就改宽度分配——改宽度会让正在读的位置跳。

- **面积分配理由**：打断层只在主列内长高，副列不缩——两列各自承担自己的打断，互不牵连。

**长历史（主列 60 轮，副列保持自己位置）**


### 3.4 信息层级

| 层 | 放什么 |
|---|---|
| 一眼 | 主列当前轮与是否在跑；副列标题与待答标记 |
| 第二眼 | 主列轮次结构；索引里的会话状态标记 |
| 按需 | 右栏其他标签、副列的 diff/终端标签、行内展开 |

### 3.5 关键交互

| 动作 | 触发 → 看到什么 → 结果 |
|---|---|
| 提交 | 某列输入区提交 → 该列尾部流式（焦点不跨列）→ 回执后行身份替换；审批待答时同样可提交（D5 §4.12） |
| 打断 | 任一列收到 `approval.request` → 该列内联打断层，索引行同义标记 → 应答只作用于该列会话 |
| 会话切换 | 索引点会话 → 载入主列；拖拽/右键 → 载入副列（右栏"会话"标签）→ 主列不重建 |
| 错误与未知 | 出错列内标未知/失败，另一列不受影响；断线时两列都不可提交（同一连接） |

### 3.6 七类事实的附着方向（Q-19）

| 事实 | 附着元素 | 表现方式 |
|---|---|---|
| 目标 | 该列标题行 | 会话名右侧事实文案 |
| 待办 | 该列所属轮的工具组行 | 计数与展开 |
| 子代理 | 该列所属轮的工具组行 | 同上 |
| 分支 | 该列标题行 | 与会话名同列（分支属于会话） |
| 唤醒 | 该列标题行或右栏"唤醒"标签 | 按需 |
| 后台进程 | 该列工具组行 + 右栏"任务"标签 | 行内计数；停止在任务页 |
| 本回合文件改动 | 该列结果行末尾 | 计数，展开到右栏 diff |

### 3.7 状态如何附着（写到元素与属性）

| 状态 | 附着元素 | 变化属性 | 不做什么 |
|---|---|---|---|
| 运行中 | 该列轮尾 + 提交键 + 索引行 | 流式光标；键形态；索引标记 | 不新增运行条 |
| 队列中 | 该列队列条 + 提交键 | 条数；键形态 | 不新增徽标 |
| 审批待答 | 该列工具行 + 列内打断层 + 索引行 | 三处同义 | 不用模态；不影响另一列 |
| 提问待答 | 同上 | 同上 | 不叠层 |
| 工具失败 | 该工具行 | 叉标记 + 灰度 | 不加提示条 |
| 结果未知 | 该列输入区 + 本轮行 | 未知标记 + 核对进度 | 不乐观更新 |
| 断线 | 两列输入区 + 各自底部 | 不可提交 + 断点 | 不另立指示层 |
| 后台完成/未读 | 索引行 + 副列标题 | 标记 | 主列不弹提示 |
| 焦点列 | 列容器本身 | 非焦点列整体降一级 | 不用遮罩或模糊 |
| 能力缺失 | 该动作所在元素 | 待决 D-1：隐藏，或禁用并写原因 | 不替用户选 |

### 3.8 可见性取舍

- 首屏默认（wide）：主列 + 折叠的副列入口与右栏；索引常驻。
- 按需：副列、右栏其他标签、行内展开。
- 不出现：状态条、活动条、任务中心；窄窗口不提供副列（不降级为"两个都缩"）。

### 3.9 放弃什么

- **放弃窄窗口的对照能力**：compact 下副列不存在，只能切换（与 §12.9 的替换式同结论）。
- **放弃"右栏只放资料"的简单性**：右栏现在还可能是第二条会话，用户要判断"这一栏是资料还是对话"。
- **放弃单列阅读的宽度**：副列展开后主列内容从 784 掉到 511（−35%）。
- **放弃"切换即整页换"的心智**：两列各有滚动、焦点、未读，恢复面变大（依赖 Q-18 的本地状态登记）。

### 3.10 概念级 Q 的答案

| Q | 本方案的回答 |
|---|---|
| Q-1 多会话 | **改判参数**：主区不是永远一个会话，而是"一主一副"；副列折叠后回到单前台。需要用户确认是否接受改判 |
| Q-3 右栏 | 保留"默认折叠 + 带标签"，把"会话"作为其中一个标签用于副列 |
| Q-14 多窗口 | 同屏部分替代开窗需求；popout 保留余地并排更后 |
| Q-15 断线 | 附着在受影响列与索引行（断的是连接，影响所有列） |
| Q-17 能力缺口 | **待决 D-1**，两种都记录，不选一边 |
| Q-19 活动条 | 删除；七类事实的附着方向见 §3.6 |

## 4 三方案横向比较

### 4.1 一句话区别

| 方案 | 第一张力 | 一句话 |
|---|---|---|
| 一 打断即主干 | T1 打断 vs 连续输入 | 把必须回答的事抬成主区的一层，输入区不再被替换 |
| 二 结果即骨架 | T2 结果 vs 过程 | 每轮一行结论、证据可展开，失败不许被折叠藏住 |
| 三 对照即同屏 | T3/T4 多会话与空间 | 主区可并排两条会话，侧栏降为索引 |

### 4.2 三档让位（数值引 §12.9；1 格 = 32px，方括号即真实占宽）

```text
compact 640（20 格）  [主区 ████████████████████]                      侧栏浮层不占宽
regular 800（25 格）  [侧 ████████][主区 █████████████████]
wide 1280（40 格）    [侧 ████████][主区 ████████████████████████████████]
wide + 副列（40 格）  [侧 ████████][主列 █████████████████][副列 ███████████████]

共用让位顺序（沿用 §12.9）：
  右栏或副列先失空间（上限 = 容器−400）→ 主区触 784 后收窄 → 侧栏 256 不动
各方案唯一的退化差异：
  一：打断层不因窗口变窄消失；先压缩时间线，输入区可降到紧凑档 240px
  二：骨架行不因变窄改结构，只减少同屏轮次；证据行保持缩进
  三：compact 下副列取消（右栏只能替换），对照能力只在 ≥960 存在
```

### 4.3 同场景结构差异

| 场景 | 方案一 | 方案二 | 方案三 |
|---|---|---|---|
| 默认态 | 时间线 + 输入区，标题行与下缘挂附属信息 | 每轮一行结论 + 证据计数 | 主列 + 折叠副列 + 索引 |
| 运行中 | 轮尾流式 + 提交键转停止 | 当前轮骨架行 + 证据计数变化 | 该列内变化，另一列不受影响 |
| 审批待答 | 输入区上方打断层，输入区保留 | 证据行下打断层，骨架行标"等待你决定" | 该列内联打断层，索引行同义标记 |
| 长历史 | 上翻分页 + 消息轨跳回 | 结论骨架 + 展开证据 | 两列各自滚动与恢复 |

### 4.4 三处比例处理的差异

| 方案 | 比例上做了什么 | 代价落在哪 |
|---|---|---|
| 一 | **不改横向比例**（侧栏 20% / 内容 784 居中 / 右栏 280–480 原样），只改纵向底栈：删状态条 35px、活动条 28px 位改由打断层按需占用 | 打断时时间线 566→≈438px（−23%） |
