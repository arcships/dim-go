# U1 C1：信息架构与区域划分

Status: draft（C1；区域与页面，不含视觉与交互细则）
Owner: U1 界面需求与信息架构
依据: `docs/domains/U1-information.md`（180 项、5 组、37 项常驻预算）、`docs/domains/U1-objects.md`（13 个对象与层级）、`docs/ui-alignment.md`（P1–P8）、`docs/project-organization.md` §9.9（UI-1…UI-5）、`docs/domains/U0-design-archaeology.md` §12（尺寸与让位）
范围: 区域职责、常驻预算落位、区域关系、页面清单与页面地图。不写字阶、颜色、圆角（C2），不写键位与焦点顺序（C3），不写代码与控件结构（C4）。

## 0 前提

- 信息项编号一律引 `docs/domains/U1-information.md`（A1…H8、S…、T1…T29、U1/U2），本文不新造信息项。
- 5 个分组沿用该文 §4：① 当前这一轮、② 输入位、③ 会话身份、④ 别的会话与应用状态、⑤ 会话附属。
- 尺寸一律引 U0 §12：侧栏 256（200–360）、标题行 48、内容上限 784、输入 60–300、右栏 280–（容器−400）；三档 compact <720 / regular 720–959 / wide ≥960。
- 三条硬约束：设置独立成屏且含"命令规则"一节；主界面不出现费用金额；改动只在过程摘要行给文件数。

## 1 区域清单（6 个区域 + 1 个一次性态）

**覆盖率**：180 项中 179 项有区域归属；S40（推荐卡片）属范围外，明确不展示，不落任何区域。

**R4 的特殊性**：它承载 19 个信息项，但同屏上限是 **4**（队列条 + 一张卡 + 一句不可用原因 + 附件条目），因为审批、提问、输入三者互斥（UI-1），队列与原因是一行。这是"项多不等于同屏多"的唯一一处，也是 C1 不把审批另开区域的原因。

**按区域汇总与是否超载**

| 区域 | 常驻项数 | 同屏上限（实际同时可见） | 判断 |
|---|---:|---:|---|
| R1 左栏 | 4 | 4（行状态 / 高亮 / 连接 / 时间） | 平衡：一屏 15–20 行会话，状态位是行内标记，不额外占位 |
| R2 标题行 | 4 | 3（会话名 + 分支/权限/模型 + 用量） | 平衡但**已达上限**：再往标题行加一项就必须进下拉 |
| R3 主区 | 9 | 9（同一轮内顺序出现，不是同时并列） | 平衡：9 项分布在一轮的不同行上 |
| R4 输入位 | 19 | 4（队列 + 卡片 + 原因 + 附件） | 平衡：靠互斥压到 4；**这是本架构最紧的一处** |
| R5 右栏 | 3 | 3 | 平衡（默认关闭） |
| R6 设置 | 1 | 1 | 平衡 |
| R0 启动态 | 0（不进主界面） | 1（整屏说明） | 平衡 |

**结论**：37 项全部有落位（S40 属范围外不展示，不计入），无超载。两处已到上限——R2（再加必须进下拉）与 R4（互斥是唯一缓冲）。若后续新增"一眼且每次"的信息项，按顺序选择：进 R4 的互斥槽 → 降为二层（进摘要行展开）→ 进 R2 下拉。

## 3 区域关系

### 3.1 挤占与让位

| 关系 | 规则 | 与 U0 §12.9 的异同 |
|---|---|---|
| R5 ↔ R3 | R5 打开时从 R3 的宽度里取（280–容器−400）；R3 不缩到 400 以下 | 同 U0 |
| R1 ↔ R3 | R1 收起时 R3 吃掉 256；收起后留 12px 边条 | 同 U0 |
| 让位顺序 | R5 先失空间（上限 = 容器−400）→ R3 触到 784 后开始收窄 → R1 保持 256 不动 | 同 U0 |
| R4 vs R3 | **高度方向 R4 优先**：R4 从 60 长到 300 时先吃 R3 的高度，R3 只保证剩余可读高度 | 补充：U0 只写宽度让位，没写高度优先级 |
| R6 | 整屏替代主界面，不并排、不挤占 | 新增（U0 的设置是路由页，这里明确为独立屏） |
| 窄窗 | compact（<720）：R1 变抽屉浮层、R5 只能整屏替代；regular：R1 常驻、R5 并排但不低于 280 | 同 U0 |

### 3.2 可收起性

| 区域 | 可收起 | 收起后信息去哪 |
|---|---|---|
| R1 | 是（12px 边条，悬停预览不改变布局） | 会话列表暂不可见；标题行保留当前会话名，不丢失"我在哪" |
| R2 | 否 | — |
| R3 | 否 | — |
| R4 | 否（但可压缩到 60） | — |
| R5 | 是（默认关） | 内容留在本地状态，标题行的入口按钮保留；再开回原位 |
| R6 | 否（整屏进出） | 返回主界面时恢复离开前的会话与滚动位置 |

## 4 页面清单（2 页 + 2 个一次性态）

| 页 | 名称 | 入口 | 出口 | 区域构成 |
|---|---|---|---|---|
| P1 | 主界面 | 启动后的默认页；左栏"新会话"回到同一页的空态 | 进入 R6（设置）；退出应用 | R1 + R2 + R3 + R4（+ R5 按需） |
| P2 | 设置 | 左栏底部账号区 / R2 的"去设置改这一项"入口 | 返回主界面（回到离开前的会话） | 左导航 224 + 内容（上限 1008） |
| P3 | 启动态 | 应用启动即进入 | 连接建立后进入 P1；失败停留并给原因 | 全屏遮罩（不是页面，不可导航） |
| P4 | 登录引导 | 未登录时由 P3 转入 | 登录成功回 P1；可跳过 | 模态（后续批次） |

**主界面只有一页**：空态（无会话）与会话态是 P1 的两种页态，不拆成两个页面——两者共用 R1/R2/R4，只有 R3 的内容不同（一个给"还没有消息"，一个给对话流）。这样"从空态发出第一条消息"不会发生页面跳转。

**设置分 9 节**（按能力域，引 C0 §14 的结论：设置是独立一屏）：

| 节 | 内容 | 承载信息项 |
|---|---|---|
| 1 账号与套餐 | 身份、登录、套餐价格与额度、用量重置 | A10–A12、G5、T27、T24 |
| 2 模型与供应商 | 供应商、模型清单与开关、目录单价（每百万 token）、探测 | A9、T3–T5、G6、S23 |
| 3 命令规则 | 规则清单、匹配方式（exact 默认 / prefix 需确认）、对所有会话生效、拒绝优先 | T1、T2、T29、H5 |
| 4 扩展 | 技能、插件、钩子 | S43–S48、T6、T7、E4 |
| 5 MCP | 服务器、认证、导入、连接测试 | T8–T11、T12 |
| 6 定时任务 | 任务、计划、历史 | S49–S54 |
| 7 运行时与模态 | 组件、管理进度、模态能力与任务 | T13–T17 |
| 8 存储与诊断 | 存储读数、服务版本与诊断 | T18、T19、T26 |
| 9 外观与键位 | 主题、动效开关、时区、快捷键提示 | T20–T23、S35 |

## 5 状态可见性（每区域每状态落在哪个元素）

不新增容器；每条状态只落在一个元素上，"同义标记"仅用于跨区域导航（规则见 C0 §2.5）。

| 区域 | 状态 | 落在哪个元素的哪个属性 |
|---|---|---|
| R1 | 会话运行中 / 待你处理 / 有新内容 | 会话行行首标记（一个位，按优先级取一个） |
| R1 | 连接断线 | 左栏底部账号区上方一行文字 |
| R2 | 上下文将满 | 用量数值的形态变化（不是新元素） |
| R2 | 权限/分支/模型被改 | 对应文字本身更新（无提示） |
| R3 | 运行中 | 过程摘要行行首标记 + 助手行尾光标 |
| R3 | 失败 | 该轮摘要行的叉标记 + 文字转次要灰度 |
| R3 | 结果不确定 | 该轮消息下方一行说明（属于本轮，不是容器） |
| R3 | 压缩发生 | 轮次之间的分隔说明 |
| R4 | 等待你回答 | 该位置内容整体换成卡片（UI-1） |
| R4 | 排队中 | 该位置上沿一行（有才出现） |
| R4 | 断线 / 不可用 | 输入内容区不可编辑 + 一行原因（S24） |
| R4 | 附件失败 | 附件条目上的标记 |
| R4 | 提交失败 / 结果不确定 | 位置上沿一行说明（与队列同一行位） |
| R5 | 内容页运行中 | 右栏标签上的标记 |
| R5 | 加载失败 | 该页自身一行说明 |
| R6 | 能力缺失 / 待决（D-1） | 该项自身的禁用态或隐藏（待 D-1 裁决） |
| 全局 | 服务缺失 / 版本不兼容 | P3 启动态整屏说明（不进主界面） |

**约束检查**：没有一条状态新增容器；R1 的行首是"一个位"，同一时刻只显示一个状态（对应 C0 §2.5 的"其余降级"）；R4 的所有状态都落在同一块位置上。

## 6 与 C0 的对应

| C0 分组 | 区域 | 说明 |
|---|---|---|
| ① 当前这一轮 | R3 + R4 | R3 承载内容与过程；R4 承载打断（C0 把打断归在 ②，见下） |
| ② 输入位 | R4 | 与 ① 在 R4 交汇：这是 C1 唯一"两组共用一个区域"的地方，靠互斥成立 |
| ③ 会话身份 | R2 | 含目标与用量 |
| ④ 别的会话与应用状态 | R1 | 含连接与账号入口 |
| ⑤ 会话附属 | R5 | 只放本会话附属（UI-2） |
| C0 的"进设置"批（设置不参与分组） | R6 | 正式定为独立屏，9 节 |

**反向检查**：6 个区域全部能指回 C0；没有"指不回"的区域，也没有分组无处安放。唯一需要留意的是 ① 与 ② 共用 R4——这不是分组错误，而是 UI-1 的互斥本身要求它们抢同一块位置。
